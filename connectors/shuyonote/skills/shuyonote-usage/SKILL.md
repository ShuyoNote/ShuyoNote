# ShuyoNote 使用说明

用户要查、要读、要写自己的笔记时用它。**笔记只在本机**：工具返回的是片段与正文，数据不出这台电脑（除了你把这些内容交给模型本身）。

## 先判断该用哪个工具

| 用户说的话 | 先做什么 |
| :-- | :-- |
| 「有没有关于 X 的笔记」 | `pages_search`（多个关键词用空格分隔，全部出现才算命中） |
| 「我最近改了什么」「笔记里都有什么」 | `pages_list`（按最近更新倒序） |
| 「读一下那一页」 | `pages_get` |
| 「写到笔记里」「帮我记一下」 | `pages_create` / `blocks_append`（先给草稿，见下） |
| 「别的空间里有没有」 | 先 `spaces_list` 拿 id，再 `pages_search` 带 `spaceId` |

## 四条硬规则

1. **`pages_get` 必须看 `chars_total`**：返回的正文可能被 `limit` 截断。`chars_total` 大于你拿到的长度 ⇒ 还没读完，用 `offset` 接着读；**不许**把半页当成整页来总结。
2. **空结果不是"没有"**：`pages_search` 的 `matched: 0` 只说明**这个空间**没命中，且可能因为关键词太整（中文没有分词）。先换 2–4 个短关键词、用空格分开再试；返回里的 `hint` 会直接告诉你该怎么做。搜不到再用 `pages_list` 看一遍最近改过的页面。
3. **跨空间读要授权**：`spaceId` 只在用户把「外部 AI 接入」开到「只读（全部空间）」或更高档时可用；被拒（`permission_denied`）就如实告诉用户去设置里换档，**不要**改用 `spaces_switch` 绕——那会切换用户界面上的空间。
4. **写入不是立刻生效**：写工具返回的是**草稿**，用户确认后才落库（有的档位会自动应用，但 `pages_update` 整页替换**一定**要确认）。返回里没有"已写入"就不要对用户说"已保存"。

## 引用要能追溯

要把结论锚到原文：先 `pages_get` 找到内容，再用 `blocks_list` 拿段落级 `blockId`，引用时给出「页面标题 + blockId」。页面被改/删时块引用会显式失效——这比编一个位置可靠。

## 写之前

- 整页替换（`pages_update`）风险最高：它会把原正文全部换掉。确认框会显示「原文 N 字 → 新正文 M 字」，用户能看到。
- 追加（`blocks_append`）比替换安全，优先用它。
- 新建页面（`pages_create`）记得给标题；写进哪个空间由用户当前所在空间决定，不要假设。

## 出错时怎么说

| 返回 | 意思 | 你该做什么 |
| :-- | :-- | :-- |
| `permission_denied` | 缺权限（读/写/跨空间） | 告诉用户在「设置 → 外部 AI 接入」调档位 |
| `space_locked` | 那个空间加密未解锁 | 请用户先在 App 里解锁 |
| `bad_args` | 参数问题（含空间 id 不存在） | 修正参数；空间 id 先用 `spaces_list` 看 |
| 「通道未开」/ 连不上 | ShuyoNote 没开，或开关没开 | 请用户打开 App 并开启外部接入 |

## 不要做

- 不要编造笔记内容或引用；没读到就说没读到。
- 不要一次拉全库正文（`pages_list` 只给元数据，正文按需读）。
- 不要把用户的笔记内容贴进无关的对话或外部链接里。
