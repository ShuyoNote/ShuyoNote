## 一句话

> 很多「笔记应用」把数据存在别人的服务器上；本地优先的应用反过来：**数据先在
> 你自己的硬盘上，同步服务只是可选项**。这篇拆开讲「数据在硬盘上到底长什么样」，
> 以及为什么这个设计比「花哨的功能列表」更有价值。

## 为什么值得写

这两年「本地优先」成了个热词，但多数介绍停在「离线能用」这种功能层面。真正
值得展开的是**存储模型**——它决定了你能不能搬走数据、会不会被供应商锁死、
介质出问题时能不能救回来。这些恰恰是知识库产品最不该含糊的地方。

## 存储怎么分

一个笔记本应有三个层次的存储，别全塞一个文件里：

1. **应用级**：工作空间清单、同步目标、插件、模板——跨空间共享的元信息。
2. **空间级**：一个空间一个库，页面、块、属性、版本历史都在里面。
3. **附件级**：图片、PDF、文件，单独存放，**按内容指纹（hash）寻址**，同名
   文件只存一份。

```
meta.db                    ← 应用级：空间清单 / 同步目标 / 插件 / 模板
spaces/<空间ID>/main.db    ← 空间级：页面 / 块 / 属性 / 版本历史
attachments/<hash>.<ext>   ← 附件级：内容寻址，跨空间去重
```

## 这样分，换来什么

### 1. 换机 = 拷一个文件夹

空间库是自包含的，连同它引用的附件打包成 zip，带到另一台设备「导入空间包」
即可——**不依赖云端、不需要导出再清洗**。数据格式就在你手边。

### 2. 数据不会被默默拿去

本地优先的另一个侧面是**没有隐性的数据上传**。索引、搜索、OCR、AI 都是本地
跑的（模型接的是你自己配的端点）；只有你明确配置了同步服务器，数据才会离开
本机，而且那一层是可选的。

### 3. 我们能「看懂」单个文件

因为 SQLite 是公开格式，空间库和附件目录都是**可以直接读的**。这不是为了
秀技术，而是意味着：你丢了应用、换了个产品、甚至想自己写个小脚本处理笔记，
都不会被格式锁死。数据格式可移植，是「数据主权」里最实在的一条。

## 反过来，代价是什么

说清楚代价，这篇才可信：

- **跨设备同步不是免费的**：本地优先意味着没有「云端帮你同步」的默认。要多端
  同步就得自建或购买同步服务——这是功能取舍，不是藏着掖着的坑。
- **手动备份是用户的职责**：应用帮你生成备份包，但「多久备一次、存哪里」得
  用户自己决定。这正是「数据在你手上」的另一面。

## 一句话收尾

> 功能决定一个笔记应用好不好用；**存储模型决定它值不值得信赖**。本地优先不是
> 一句口号，它落在 `meta.db + spaces/*.db + attachments/` 这三层里——你随时
> 能把数据带走。

## 附：可以写成对比/演示的展开点

- 拿一个 10MB 的 SQLite 库 + 几个附件，现场做一次「导出空间包 → 新设备导入」，
  全程不带云——比十段文字都直观。
- 对比：把「云端同步」当成卖点的产品，迁移通常要导出专属格式 / 走厂商 API，
  数据主权打折。
- 呼应官网定价页「个人开源版 ¥0 / 个人自建同步 ¥199 / 团队询价」的档位设计
  ——本地优先正是这个档位结构成立的理由。
