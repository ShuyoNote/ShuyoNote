前两年「本地优先」流行起来，但多数介绍停在「离线能用」这种功能层面。真正值得
展开的是**存储模型**：它决定了数据能不能搬走、会不会被供应商锁死、介质出问题时
能不能救回来。这些恰恰是知识库产品最不该含糊的地方。

## 存储分三层，而不是一个文件

一个笔记应用的数据，别全塞进一个文件里：

1. **应用级**：工作空间清单、同步目标、插件、模板——跨空间共享的元信息。
2. **空间级**：一个空间一个库，页面、块、属性、版本历史都在里面。
3. **附件级**：图片、PDF、文件单独存放，**按内容指纹（hash）寻址**，同名文件
   只存一份。

```
meta.db                   ← 应用级：空间清单 / 同步目标 / 插件 / 模板
spaces/<空间ID>/main.db   ← 空间级：页面 / 块 / 属性 / 版本历史
attachments/<hash>.<ext>  ← 附件级：内容寻址，跨空间去重
```

## 这样分，换来三件实在的事

### 一、换机 = 拷一个文件夹

空间库自包含，连同它引用的附件打包成一个 zip，带到另一台设备「导入空间包」
即可——不依赖云端、不需要导出再清洗。数据格式就在手边。

### 二、没有隐性的数据上传

本地优先的另一面是**不会默默把数据送出去**。索引、搜索、OCR、AI 都在本地跑
（模型接的是你自己配置的端点，而不是某个内置云服务）；只有你明确配置了同步
服务器，数据才会离开本机，而那一层是可选的。

### 三、单个文件你能看懂

因为 SQLite 是公开格式，空间库和附件目录都是**可直接读**的。这不是为了秀技术，
而是说你丢了应用、换了产品、甚至想自己写个脚本处理笔记，都不会被格式锁死。
数据格式可移植，是「数据主权」里最实在的一条。

## 反过来，代价是什么

把代价说清楚，这篇才可信：

- **跨设备同步不是免费的**：本地优先意味着没有「云端默认帮你同步」。要多端
  同步，就得自建或购买同步服务——这是功能取舍，不是藏着掖着的坑。
- **手动备份是用户的职责**：应用能生成备份包，但「多久备一次、存哪里」得你
  自己决定。这正是「数据在你手上」的另一面。

## 收尾

> 功能决定一个笔记应用好不好用；**存储模型决定它值不值得信赖**。本地优先不是
> 一句口号，它落在 `meta.db + spaces/*.db + attachments/` 这三层里——你随时
> 能把数据带走。

## 附：可部署的演示点

- 现场做一次「导出空间包 → 新设备导入」，10MB 库加几个附件，全程不带云——
  比十段文字都直观。
- 对比：以「云端同步」为主卖点的产品，迁移通常要走专属格式 / 厂商 API，
  数据主权打折。
- 附录：客户端为 AGPL-3.0 开源的笔记应用，同步服务端为可选的商业授权组件
  （自建或购买，都不强绑定）。
