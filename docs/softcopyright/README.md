# 软件著作权登记材料（ShuyoNote 数友笔记）

> 软件全称：**ShuyoNote 数友笔记**（2026-09-13 定）
> 版本：**V1.90.1**（登记版本号应与提交的源代码版本一致）
> 办理渠道：**中国版权保护中心**（www.ccopyright.com.cn）——**登记制**，材料规范基本都能过。

## 一、要交的东西

| 材料 | 要求 | 现状 |
|---|---|---|
| 软件著作权登记申请表 | 在线填写：软件全称、简称、版本号、开发完成日期 | ⛔ 待填（需你的身份信息） |
| **源代码文档** | **前 30 页 + 后 30 页**（共 60 页）；**每页 ≥50 行**；**页眉标注软件全称 + 版本号**；**连续页码** | ✅ **本仓库可生成**（见下） |
| 软件说明书（用户手册） | 图文说明功能、界面、操作流程，通常 10–30 页 | 🟡 草稿见 [`说明书.md`](说明书.md)（**需你补截图**） |
| 申请人身份证明 | 个人：身份证复印件；企业：营业执照复印件 | ⛔ 需你提供 |

**周期**：普通约 30 个工作日；可加急（20 / 10 / 5 / 3 工作日，费用约 1000–5000 元）。**个人可以申请。**

## 二、源代码文档怎么生成

```bash
node scripts/software-copyright-doc.mjs
# 产出：tmp/softcopyright/源代码-ShuyoNote数友笔记-V1.90.1.html
```

然后 **用浏览器打开 → 打印 → 另存为 PDF**，就是可提交的那份（版式已按 A4 纵向、
每页强制分页、每页 50 行、页眉带全称+版本、页码连续）。

脚本**自己会校验**这些格式要求（页数、每页行数、页眉、页码），任何一条不满足就非零退出——
**不会产出一份"看起来没问题"的文档**。补正一次就是几十个工作日，这个自检值那几行代码。

取码顺序是**确定的**（Rust 内核在前、入口 `lib.rs`/`main.rs` 最前，然后前端；**不含测试文件**），
所以同一版本两次产出同一份文档，便于与提交件核对。

> `tmp/` 在 `.gitignore` 里，所以这份产物**不入库**（它随版本变、且可随时重建）。
> 要交给代理/版权中心时，直接从该目录取。

## 三、两个高频补正的坑（都已规避，但你要知道）

1. **源代码格式**：页眉必须标注软件全称 + 版本号、页码必须连续、每页不少于 50 行。
   随意截取不连续段落会被要求补正。→ 生成器把这三条做成硬校验。
2. **App 名称必须与软著名称一致**（或至少包含关系成立），否则**应用商店审核不通过**。
   → 我们这里：软著全称 `ShuyoNote 数友笔记`，而应用显示名（`tauri.conf.json` 的
   `productName`）是 **`ShuyoNote`** —— 全称**包含**应用名，属于安全方向；
   但**注册前请以各商店当期规则再确认一次**，必要时把商店里的应用名写成
   `ShuyoNote 数友笔记`（改的是商店后台的名称，不是安装包里的 `productName`）。

## 四、命名与版本的一处约定

登记版本号 `V1.90.1` 与 `package.json` 一致。**下次发版后如果还要用软著**，
不必重新登记（软著保护的是这个软件，不是某个版本）；但**首次登记时提交的版本要与申请表一致**，
而申请表上的"开发完成日期"应早于或等于你提交的日期。

2. 说明书的**界面截图**（草稿里以 `【待补截图】` 标出）；
3. 申请表里"开发完成日期"的口径（建议用首次对外发布的日期，或与仓库首次提交对齐）。
