## 0. 一句话

> **四个产品都吃 MCP，缺的是客户端这一侧的「面」—— 而这个面的形状不是设计偏好，是被三条硬约束钉死的：钥匙只在应用进程内存、没有 OS keyring、个人空间 E2EE 把服务端路线排除。**

⇒ 于是「让它们用上 ShuyoNote」**不等于**「做一个笔记 API」，等于**在应用进程内开一个受权限模型约束的入口**。

---

## 1. 用户诉求（原话，不转写）

- 原话是：「**如何能让 dsh/codebuddy/workbuddy/Claude code 等产品使用 shuyonote？**」
- 追问后收敛到一句：**MCP / CLI / API 三选一怎么选？** —— 那句追问本身就把范围指对了，而答案是**不是三选一**（见方案 §5）。
- ⚠️ 本需求**不把"接上"当成目标**：能连上但读不到加密空间、或能写但绕过用户确认，都算**不满足**。

## 2. 决定"要什么"的那几条读数

> 完整取证（10 条，含 `file:line`）在[方案 §3](../plans/2026-09-28-agent-mcp-integration-plan.md)。**这里只列决定本需求形状的那几条，不复述全表。**

| # | 读数 | 判据（**别信这张表，跑它**） | 它决定了哪条需求 |
|---|---|---|---|
| 1 | 四个产品**都原生支持 MCP**（Claude Code / CodeBuddy IDE+CLI / WorkBuddy / DSH） | 各自官方文档（方案 §8 附链接与核实程度） | 走 MCP，不改客户端 |
| 2 | 客户端这一侧 **MCP 零命中**、面向外部进程的通道**一条都没有** | `rg -i "\bmcp\b" src src-tauri scripts package.json` ⇒ 0 | 要新开一个面 |
| 3 | **钥匙只在应用进程内存**（「用完即散，不落盘」），且**没有接任何 OS keyring** | `src-tauri/src/space_crypto.rs`；`Cargo.toml` 里 `keyring`/`wincred`/`secret-service` 零命中 | **桥不能自己开库**；必须落在应用进程内 |
| 4 | 能力注册表 **25 条 / 其中 `ai:true` 10 条**，每条带 `permission`、`scope`、LLM 可读 `desc` | `node -e "const c=require('./capabilities/capabilities.json');console.log(c.capabilities.length, c.capabilities.filter(x=>x.ai).length)"` | 工具面**照抄注册表**，不新造语义工具 |
| 5 | 权限与审计**只有一个校验点** | `src-tauri/src/plugins.rs::dispatch_capability` | 外部调用必须走它 |
| 6 | 四个客户端的**共同传输只有 stdio**（DSH 无 SSE；WorkBuddy 只文档了 stdio） | 方案 §8 | 桥的对外面用 stdio |

## 3. 要什么

1. **同一份配置形状接四家**：桥对外只提供 **stdio**，四家各自用自己那份配置接上（配置片段见方案 §8，不在本文件抄）。
2. **工具面＝注册表里 `ai:true` 的那批**；**M1 只上只读**（8 条）。写能力（`pages.create` / `blocks.append`）在"用户确认"这条链被证明对**外部**调用同样成立之前，不上。
3. **权限与审计不新开第二条路**：外部会话的每次调用与插件调用**同等**经过唯一校验点（含 `space_locked` 语义）。
4. **未解锁要"大声失败"**：锁定/未解锁 ⇒ 明确报错，**不许返回空结果** —— 否则 agent 会把"读不到"读成"库里没有"，那正是[全库 AI 覆盖方案 §15.10](../plans/2026-09-17-knowledge-base-ai-coverage-plan.md) 防的同一件事。
5. **关掉即失效**：用户在应用里关掉「外部接入」⇒ 旧 token **立刻**不能用（不是"下次重启才失效"）。
6. **用户看得见**：应用内能看到"外部接入开着 / 有几个会话在用"，每次外部调用可在审计轨迹里查。

## 4. 不要什么（明确排除，免得范围膨胀）

| 不做 | 为什么 |
|---|---|
| ❌ **不做服务端笔记 API** | 个人空间 E2EE、服务端只做透明中继不解析 payload（读数 §0 的决定；口径以[数据可见边界](../sync-server-data-boundary.md)为准）。团队空间虽见明文，但那是同步 API，不是读取面 |
| ❌ **不让桥自己开库** | 钥匙只在应用内存（读数 #3）；且会复制一套查询语义（软删 / 工作空间过滤 / `content_json` 收口）⇒ **第二份真相源**，漂移不报错 |
| ❌ **不把 mesh 网格窗口改造成 MCP 通道** | 它默认关闭、没配 token 时鉴权直接放行、手写 HTTP 无 JSON-RPC 基建 ⇒ 会造出**第二套鉴权** |
| ❌ **M1 不放开写** | 写一律草稿 + 用户确认（`src/lib/ai/apply.ts` 是唯一落库处）；`--allow-write` 属 M2 且要单独拍板 |
| ❌ **不写"用户向接入文档"** | 文档先于功能是本仓踩过的坑（见 `docs/README.md` 那条"新增文档不登记"的邻居规矩）。等 M1 真跑通再写 |
| ❌ **不新开第二条鉴权** | 见规格 `INV-MCP-single-authz`（这是本层第一条不变式） |

## 5. 边界（如实说，不把推断写成结论）

1. **全部取证是静态读代码**（＋一位只读子代理的独立复核，决定性读数已复算）；**没有运行过应用、没有跑过一次真实 MCP 连接**。
2. **DSH 那份配置格式可信、端到端未验证** —— 它取自 DSH 自己包内的模板与 `Config` schema，但没人改过 profile、也没起过真 server。
3. **`src-tauri/tauri.conf.json` 的 `app.security` 未逐条读完** ⇒ 方案 §3 第 7 条那条结论是"命令只挂 WebView IPC ＋ 无 socket/管道/HTTP 依赖零命中"，**不是**对 CSP / asset 协议的穷尽核查。
4. **上下文成本（10 条 desc ＝ 1631 字符）是未过分词器的粗估**，不是实测 token 数。
5. **本需求不预设 M2（写回）与 M3（多空间/治理）的形态**，但 §3 的**第 3、4、5 条对它们同样适用**。
