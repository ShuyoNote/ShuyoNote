# `docs/specs/` —— 规格层（本仓）

> **这一层的存在理由**：把「我们声称系统会这样」变成**每条都能指到一条会红的判据**。
> 依据：`AI-NATIVE-DEV.md` §5.1（2026-09-27 定案：**按仓引入**，试点目录用 `<repo>/docs/specs/`，不叫 `openspec/`）
> ＋ `_workspace/notes/2026-09-27-spec-layer-pilot-criteria.md`（判据先行的设计）。
> 同形先例：`shuyo-community/docs/specs/`（另一条线 2026-09-28 落地的那份，字段形状与本节一致 —— 两份是**同一套规范的两个实例**，不是两份规范）。

## 是什么

**当前契约。** 一条不变式 = 一句「无论怎么改都不许破的规矩」，挂在**一条会红的判据**上。

## 不是什么（这三条比上面那条更重要）

| 不是 | 为什么 |
|---|---|
| ❌ **不是过程记录** | 过程（怎么想、踩了什么坑、施工单）在 `docs/plans/`。**规格层只放「现在仍然必须成立」的东西。** |
| ❌ **不是第二个真相源** | 口径住在**判据自己的注册表与脚本头部**里（本仓是 `scripts/lib/gates.mjs` 的 `label` / `incident`）。本层只写 **id + 口径（逐字引用） + 判据指针 + 「看过它红」的证据**，**不复述实现、不重写口径、不列「怎么判」**（理由同 `AGENTS.md` §1 开头那句：抄了就会出现第二份真相源）。 |
| ❌ **不是散文的收容所** | ⚠️ **没有判据兜着的不变式，不许进这一层。** 它们留在 plan 文档里，直到判据立起来。否则这一层会变成「读起来很安心、其实没人守」的东西 —— 而**这恰恰是它想消灭的状态**。 |

## 每条不变式的四个字段（缺一即视为「半配置」）

> ⚠️ **收录条件是三条**（2026-09-28 自查后写全 —— 原先只写了两条，而我实际在用三条）：
> ① 能指到**一条会红的判据**；② 那条判据有**「看过它红」的证据**（账本按脚本 sha 绑定）；
> ③ **证据能原地重做**（判据得有「再注入」的口子：`--root` ／ 位置参数 ／ `--self-test` ／ 已写明的假根配方）。
> 缺第③条，判据一改第②条就补不回来 ⇒ 例：`check-pdfjs-worker-shim` 满足②、暂时不满足③（`--root` 夹具被撤回）⇒ 不收。

```text
id          INV-<域>-<短名>          稳定标识；改口径不许改 id（改 id = 删除 + 新增）
口径        一句话；从判据的真源**逐字引用**，不在此重写
判据        scripts/check-<名>.mjs [--self-test] [--root/--repo/位置参数 等注入方式]
会红证据    ✅ 有（给出证明命令与期望非 0 退出码 + 账本里的 sha） ／ ❌ 无（⇒ 该条还不该待在这一层）
```

本仓的两条承重证明通道（`scripts/lib/gates.mjs` 与本仓 `AGENTS.md` §3 的口径）：
- **跑 cargo 的判据** ⇒ Rust 判据（cargo）的「看过它红」证据走 `_workspace/mutation-evidence.json` 的 `_repo_mutations`（⚠️ 产品仓**没有** `scripts/criteria-mutations.json` 这个文件 —— 那句话在指一个不存在的通道 ✗，2026-09-29 订正）（改坏源码 ⇒ 用例变红）；

> ⚠️ **2026-09-29 订正（Windows 侧裁决 ①）**：产品仓里引用 `criteria-mutations.json` 的地方都在指一个**不存在的通道** ⇒ 正确措辞是：
> Rust 判据（cargo）的「看过它红」证据走 `_workspace/mutation-evidence.json` 的 `_repo_mutations`（⚠️ 产品仓**没有** `scripts/criteria-mutations.json` 这个文件 —— 那句话在指一个不存在的通道 ✗，2026-09-29 订正）
> 取证：`grep -rn criteria-mutations docs/ scripts/` 在产品仓命中 6 处、而该文件不存在；工作区/信箱里那些指的是 **community 仓**那份（**存在**）⇒ **改的范围只有产品仓**（别把对的地方也改错）。
- **静态扫描 / 纯函数判据** ⇒ 脚本自己的 `--self-test`（正例 + 负例两边都验），
  **或**工作区那本 `_workspace/mutation-evidence.json` 里的 D2 证据（`exit` / `gateSha256` / `finding`，**判据代码一改就自动过期**）。

## 现状（诚实版，2026-09-28 普查）

- 本仓 `scripts/` 下有一批 `check-*.mjs`（不含 `*.test.mjs`），**其中哪些满足本层准入、本层现在几条，一律以命令为准**：
  `grep -c "^| \*\*INV-" docs/specs/INVARIANTS.md`（数本层实际条目）与 `ls scripts/check-*.mjs | wc -l`（数判据总量）。
  ⚠️ **这里原先写死"只有 17 条 ⇒ INVARIANTS.md 就是这 17 条"，2026-09-28 被 AMD 侧当场抓出已过期（实际 27 条）** ——
  写死的计数会过期，**判据只能是命令**（与 `AI-NATIVE-DEV.md` §11 那条同源）。
- **其余 28 条不入本层**，理由分两类（普查与复现命令见 `_workspace/notes/2026-09-28-spec-layer-readiness.md`）：
  1. 约 **20 条**是纯 Node 判据但**还缺「可跑性」**（得能在夹具根 / 位置参数上被弄红）⇒ **补一条，进一条**；
     ⚠️ **「可跑性」必须按规则验，不能按门禁验**（2026-09-28 实测）：`check-workflow-yaml.mjs` 的目录参数**只覆盖窄规则**，
     国密四件套那条**不在里面** —— 它那条的承重证明在兄弟测试文件里（D3 通道）。⇒ 补可跑性之前，
     **先用夹具把目标规则弄红一次**，再往这一层写 `✅`；
  2. **14 条平台绑定**（真 APK ／ macOS 宿主 ／ 真 Chromium ／ 打包产物 ／ Tongsuo）⇒ **造不出夹具来证明它会红**，
     它们的门禁走「带理由的豁免」。本层对这类只能写**「当前环境无法证明」** —— 不写，也不假装。
- 本目录目前是**人手写**的。按规范它最终应当是**生成物**（真相源加 `invariant` 字段 ⇒ 生成 `INVARIANTS.md` ⇒ 等值门禁钉字节）。
  **生成器与等值门禁属下一步**；本目录先以手写形态落地，但**字段形状按生成物设计**，以便将来机器迁移时不必重写内容。

## 边界（如实说）

- ⚠️ `INVARIANTS.md` 的「会红证据」一列**必须能对上账本**：账本里那条证据的 `gateSha256` 一旦与磁盘上的脚本不一致（＝判据代码被改过），
  **那条不变式就要从表里撤下来**（先重做证据，再放回）。⇒ 这一列不是装饰，是**可核的**。
- `check-doc-links` 扫本仓所有 `.md` ⇒ 本目录内的相对链接**自动**被它管住，不需要新增一条链接检查。
- 跨仓契约（对外表述红线 / 定价口径）**不在此处** —— 它们各有唯一出处（见 `AI-NATIVE-DEV.md` §8），本层不复制。
