## 3. 要什么（MUST）

| # | 要什么 | 为什么是它（不是别的） |
|---|---|---|
| **M1** | ⭐ **讨论**长在**已有的空间与页面**上** | 复用"空间＝成员/角色/审计/密钥"这一整套 ✓；`comments` 已经带 `space_id` ＋ `page_id` ＋ `parent_id` ✓ |
| **M2** | **页级线程**：评论可被回复，**恰好两层**（回复的回复归到根） | 一层的 `parent_id` 能存，但**树怎么长是产品决定** ⇒ 必须写死，否则界面越长越乱 ✗ |
| **M3** | **空间级频道**：一个空间内可以有多条讨论线，各自的**未读独立正确** | 现在 `comments.page_id NOT NULL` ⇒ **没有"不含页的讨论"载体** ✗（见规格 §2） |
| **M4** | **通知与在线**：@ 提醒、未读、谁在线（⛔ 按**用户×空间**，不是按用户 ✗） | 现在通知是用户级、在线是用户级 ⇒ 都要**加空间维度** ✓ |
| **M5** | ⭐ **讨论可以变成知识**（显式动作） | §27.3② 的硬要求：「**不是"聊天记录留着"**」⇒ 必须有一个用户动作（如"把这段结论落成笔记"）✓ |
| **M6** | ⭐ **讨论只在团队空间出现** | 个人空间没有第二个人（"讨论"＝自己看自己 ✗）；且个人空间 E2E（服务端只落密文）⇒ 服务端**读不到**评论正文 ✗ |
| **M7** | **被移出空间 ⇒ 该空间讨论立刻读不到**（含已建立的实时连接） | 空间是**唯一的权限边界** ✓；⛔ 现在 SSE **建连后不复检权限** ✗ |
