## 3. 声明面长什么样（**本文件要定的就是这一段**）

### 3.1 谁声明

| 谁 | 声明什么 | 何时生效 |
|---|---|---|
| **产品（默认）** | 个人档允许的目标集合、团队档允许的目标集合 | 出厂即生效，仓内可核 ✓ |

### 3.2 声明在哪（**唯一一处**，两边界都可读）

**推荐：仓内一个机器可读文件 `network-targets.json`（仓根，与 `package.json` 同级）。**

- 为什么放**真文件**而不是规格里的表格：规格是散文，判据要 `JSON.parse` 得到**结构**；
  真文件能被 Node 侧门禁读 ✓、也能被 Rust 侧 `include_str!` 进编译期 ✓ ⇒ **一处声明、两侧同一个字节**。
- 为什么**不是** Rust 里的常量 ＋ TS 里的镜像：那两个地方必然漂移（本仓最贵的一课：一条判据被抄了 7 份 ✗）。
- 形状（草案，**字段名在实现前由 owner 过一眼**）：

```json
{
  "version": 1,
  "personal": {
    "note": "个人空间：只准本机（回环）与同网段；⛔ 不许出现任何公网 host",
    "targets": []
  },
  "team": {
    "note": "团队空间：逐条对 docs/sync-server-data-boundary.md（人核那份）",
    "targets": [{ "host": "sync.shuyo.cn", "why": "团队同步服务端（商业组件）", "carrier": "sync" }]
  }
}
```

- `personal.targets` **为空**才是今天的产品口径（"个人侧不出本机" ✓）；
  若将来要放开（见 §4 的冲突），**先改这份清单** ⇒ 改动**看得见、可追溯** ✓。

### 3.3 怎么核（**判据的形状**，实现留到方案 A）

`scripts/check-network-targets.mjs`（**待立**，不在本方案里落地）应当能判三件事：

1. **清单本身合法**：`personal` / `team` 两档都在；每个 `target.host` 能解析且带 `why` ＋ `carrier` ✓。
2. **个人档不含公网**：`personal.targets` 里的 host 必须落在回环（`127.0.0.0/8`、`::1`）或私网段
   （`10/8`、`172.16/12`、`192.168/16`、链路本地）—— ⛔ 出现任何公网 host ⇒ **红** ✓。
3. **代码里的出网点与清单对得上**（白名单式）：扫出网调用点（如 `ai.rs` 的 provider 端点构造、
   桥的绑定、`mesh` 的基址），**每个都必须落在一个"已声明的 carrier"文件里**；
   出现**新的、没声明过的出网点** ⇒ **红**（挡的是"悄悄加一处外连"✓）。
   ⚠️ 反向也要核：**声明了却没有任何载体**（`carrier` 指的文件不存在／那里不出网）⇒ 也红（挡"清单里写着、代码里没人用"✓）。
