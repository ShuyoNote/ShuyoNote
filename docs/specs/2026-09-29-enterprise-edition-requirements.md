## 0. 定位（一句话）
```text
**企业版 = 多人协作用的、可自建、可私有、按空间可选加密的同步与协同服务。**
  · 与竞品**同类**（服务端明文 ＋ 成员/权限/审计 ＋ 内容级治理）
  · 但**多两项它们做不到的**：**可自建/私有化** ＋ **按空间可选加密**
```

## 1. 需求（**MUST** —— 定死，逐条可判）
### 1.1 性能
| # | 需求 | 指标（验收） |
|---|---|---|
| P1 | **文字到达 ≤100ms**（同空间内） | 编辑到对方看到 ≤100ms（P95） |
| P2 | **边打边到**（撤两层防抖） | 编辑后 ≤50ms 发出（无 400ms/600ms 防抖） |
| P3 | **有光标/在场** | 能看到同页其他人的位置 |
| P4 | **单空间并发 ≥5 万台设备** | 压测：N=50000 时 P95 延迟不劣化 |
| P5 | **并发写 ≥3 万/秒** | 压测：3 万写/秒下不丢、P95 不劣化 |
| P6 | **并发读 ≈20 万次发送/秒** | 出带宽 ≈100 MB/s 内（L4 后不查库） |

### 1.2 规模与扩容
| # | 需求 | 指标 |
|---|---|---|
| S1 | **单空间 ≥5 万设备** | 见 P4 |
| S2 | **空间数可横向扩** | 加数据节点 ⇒ 空间数近似线性 |
| S3 | **连接数可横向扩** | 加网关 ⇒ 连接数近似线性 |
| S4 | ⚠️ **单空间上限的卡点是"写"**（已算清） | 若需 >8 万 ⇒ 必须做 **seq 按页分片**（属 D 阶段） |

### 1.3 治理（企业必需）
| # | 需求 |
|---|---|
| G1 | **成员/角色**（viewer/editor ＋ 可扩展角色） |
| G2 | **审计**（可导出、可检索） |
| G3 | **内容级治理**：水印／密级／DLP／全文检索 ⇒ ⚠️ **只在明文空间提供** |
| G4 | **SSO/SCIM**（可做，元数据类） |

### 1.4 交付与部署
| # | 需求 |
|---|---|
| D1 | **可自建/私有化**：**单文件起**，也能**分片部署**（网关 ＋ 数据节点） |
| D2 | **零依赖起跑**（单机 SQLite 即可用） |
| D3 | **客户端开源（AGPL-3.0）**；服务端独立商业授权 |
| D4 | ⚠️ **两边不许互相内嵌**（`INV-LIC-no-server-in-client`） |

### 1.5 ⭐ 按空间**可选加密**（owner 裁定 —— 保留用户选择的权利）
| # | 需求 |
|---|---|
| E1 | **团队空间有两档，由用户/空间选**：**明文**（默认）／**加密** |
| E2 | **明文空间** ⇒ 服务端可读 ⇒ **全能治理**（G3 全量） |
| E3 | **加密空间** ⇒ 服务端**只知元数据** ⇒ 强保密 ＋ **元数据级治理** |
| E4 | ⚠️ **加密的代价只在开启时才付**（密钥分发与轮换） |
| E5 | ⚠️ 加密空间下：**按页订阅用"页级不透明键"**（服务端不知道是哪一页） |

## 2. 明确**不做**（WON'T —— 定死，免得反复）
```text
❌ **不做"单空间 20 万+"** —— 除非把 seq 按页分片（那是 D 阶段，不在本需求内）
❌ **不做设备直连**（团队版不提供 —— owner §14 裁定）
❌ **不做"服务端读内容"以外的治理**（水印等要求明文；加密空间只到元数据级）
❌ **不做 Office 保真**（公式/图表/PPT 保真度不追竞品）
❌ **不做 IM/日历/审批一体**
❌ **不做强制加密**（加密永远是用户的选择 —— E1）
```

## 3. 与竞品的关系（**对标目标**）
```text
**结构性赢（它们做不到）**：可自建/私有化｜客户端开源｜离线｜数据主权｜成本（自建一次性）｜
  ⭐ **按空间可选加密**｜⭐ **"用户能选"本身**
**追平/反超**：延迟｜单空间并发｜协同粒度（页级）｜横向扩容｜权限与审计
**让出一档**：加密空间里的内容级治理（**那是用户自己选的**）
**仍会输（接受）**：运维门槛｜成熟度｜Office 保真｜IM生态｜合规认证
```

## 4. 不变式（**要判据的**）
```text
INV-ENT-optional-encryption-is-a-choice
  加密**永远是用户的选择**（不许默认开、不许强制、也不许取消该选项）。
  判据：明文空间与加密空间**都能创建**；且"加密"在界面上是**可选**而非默认。

INV-ENT-write-is-the-ceiling
  **单空间的上限由"写"决定** ⇒ 不许在文档/宣传里声称"加机器就能到 20 万"。
  判据：文案里区分"空间数可扩"与"单空间上限受写限"。

INV-ENT-governance-follows-space-kind
  **内容级治理只对明文空间承诺**；加密空间**只承诺元数据级治理**。
  判据：加密空间下**不出现**"全文检索/水印"这类承诺（或明确标注不可用）。

INV-ENT-self-host-first
  企业版**必须能单机零依赖跑起来**（不许把"分片部署"变成必需项）。
  判据：单机单文件部署即可完成一次完整协作（含成员/权限/审计）。
```

## 5. 阶段（**做这个需求的顺序**）
```text
**A 手感**（不扩容）：增量 payload → 先发后落库 → 光标
**B 降阶**（到万级）：L4a/L4b（零风险）→ L4c → **按页订阅 ＋ 页级不透明键**
**C 横向扩容**（空间数/连接数）：连接与数据分离 ＋ 按空间分片
**D 可选加密**：按空间的两档 ＋ 密钥分发/轮换（**只在用户开启时付**）
**E 以后**：seq 按页分片（才能谈单空间 20 万）
```

## 6. 一句话
```text
**企业版定了：**延迟 ≤100ms、单空间 ≥5 万、读可扩写受限、治理齐全、
**可自建**、**按空间可选加密** ——
而"不做"的也定死了（不做设备直连、不做强制加密、不做单空间 20 万、不追 Office 保真与 IM）。
```
