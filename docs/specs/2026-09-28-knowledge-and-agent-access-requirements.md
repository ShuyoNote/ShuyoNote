## 3. 要什么

1. **一份本体，从注册表生成**（25 条 ⇒ 本体表），**不许手抄第二份** ✗
   —— 判据：注册表改了 ⇒ 本体必须跟着改（对账门禁 ✓）
2. **本体是对外契约**：改 id／删能力／改语义 ⇒ **必须 bump `apiVersion`**
   —— 判据：不 bump ⇒ 红 ✓（机制已在 ✓，缺的是强制 ✓）
3. **外部只读面不含写能力**：M1 工具面里 **`kind === 'write'` 的条数 = 0**
   —— 判据：可机检 ✓（⚠️ 不是查不存在的 `isWrite` ✗）
4. **工具描述不许泄漏内部**：描述里不出现仓内路径与内部字段名 —— 判据：可机检 ✓
5. **按空间分档**：个人空间**一分内容不出本机**（含检索/索引）；团队空间按 `docs/sync-server-data-boundary.md` 的口径
   —— 判据：个人空间侧抓包看不到明文/向量出网 ✓ ／ 团队侧按已声明口径 ✓
6. **审计能分辨主体**：人 / 插件 / 外部 Agent 三类可区分，且外部调用与插件调用**同一轨迹**
   —— 判据：删掉那一处审计调用 ⇒ 红 ✓；（⚠️ 先要定主体标识字段 —— 现为**未定**，是 Phase 4 入口条件 ✓）
7. **一切皆派生物**：索引、wiki、地图都能**重建**，且**同一查询同一结果集**（与 App 内一致）
   —— 判据：删索引 ⇒ 功能不降级 ✓ ／ 重建后结果一致 ✓
8. **给人看的生成物可核**：每条断言**带回链**；**源改了会标脏**；页脚写明"派生，非出处"
   —— 判据：三条都能机检 ✓
9. **锁定/未解锁要大声失败**：明确报错，**不许返回空结果**（"读不到" ≠ "库里没有"）
   —— 判据：承重通道上的判据（同 MCP 规格 `INV-MCP-locked-fails-loud` ✓）
10. **同一套语义**：外部经桥调用与 App 内调用**走同一校验点、同一过滤语义**（软删／工作空间／`content_json` 收口）
    —— 判据：同一查询两条路径结果集相同 ✓

## 4. 不要什么（明确排除，免得范围膨胀）

| 不做 | 为什么 |
|---|---|
| ❌ **个人空间的内容/向量出网** | 端到端加密（服务端只落密文）：`docs/sync-server-data-boundary.md:33` |
| ❌ **第二份能力清单 / 第二套检索语义** | 会漂移且不报错；注册表 25 条是唯一出处 ✓ |
| ❌ **两个版本分叉** | 实现按**两种空间**（运行期策略、可回退 ✓）；"个人版/企业版"只作包装口径 ✓ |
| ❌ **为 ontology 而 ontology** | 本体是**派生物**，描述**结构**不描述内容 ✓ |
| ❌ **抄外部综述的前提**（"内容在云上、可版本、可共享"） | 我们的前提是"内容只在用户机器上" ⇒ 形态不同 ✓（该综述的三层分工／评估口径可参考 ✓） |
| ❌ **wiki 与规范正文并存当真相** | 第二真相源；wiki 必须标"派生，非出处"，正文不许引用 wiki ✓ |
| ❌ **先写用户向文档** | 文档先于功能是本仓踩过的坑（同 `2026-09-28-mcp-host-requirements.md` §4） |
| ❌ **工具描述里的内部路径** | 工具面＝对外暴露面 ✓ |
