# 插件配方（第一批可发布清单）

> 面向**社区发布**：每个插件一句话定位 + 它要哪些权限 + 怎么装。可直接贴到社区
> 「模板 / 主题 / 插件配方」分类里。
>
> 为什么是这一份：插件生态的冷启动瓶颈不是能力条数，而是**"有哪些能用的插件"**——
> [分发策略](plans/2026-09-10-plugin-distribution-strategy.md) 里的闸门是"作者文档 + 至少 3 个
> 真实插件"，而第一批由我们自己先做（「一方先行」）。下面这些**都能直接装来用**，源码在
> [`examples/plugins/`](../examples/plugins/)，也全部进了回归测试（`cargo test` / 作者 CLI /
> 类型检查三处）。

## 安装（三步）

1. 打开「插件管理 → 打开插件目录」；
2. 把某个插件目录整个复制进去（**目录名必须与 `manifest.json` 里的 `id` 一致**）；
3. 回到面板点「校验」→ 看清权限与理由 → 「启用」。

新装的插件**默认未启用**，所有写操作都会先给你一份草稿，你确认后才落库。
想自己改或自己写：作者文档见 [`plugin-api.md`](plugin-api.md)。

## 清单

| 插件 | 一句话定位 | 要什么权限 | 怎么用 |
|---|---|---|---|
| **周回顾** `weekly-review` | 把最近 N 天动过的页面汇成一篇「回顾」草稿（清单 + 统计） | 读页面标题与更新时间；新建页面（草稿） | 命令面板 → 「生成回顾」（可填天数/条数） |
| **陈旧页巡检** `stale-triage` | 找出 N 天没更新的页面，批量打 #待整理 | 读页面；读标签；加标签（草稿） | 命令面板 → 「找出久未更新的页面」 |
| **孤立页面巡检** `orphan-pages` | 找出没人链过去的「孤岛」，生成清单草稿 | 读页面；读反向链接；新建页面（草稿） | 命令面板 → 「找出孤立页面」 |
| **当前页导出 Markdown** `page-to-md` | 把当前打开的页面写成一份 `.md` | 读当前页段落；导出文件（**存哪里由你选**） | 命令面板 → 「导出：用「当前页导出 Markdown」保存为 .md」 |
| **CSV 转表格** `csv-table` | 选中 `.csv`/`.tsv` → Markdown 表格放进新页面 | 新建页面（草稿） | 命令面板 → 「用「CSV 转表格」导入表格」→ 选文件 |
| **检索汇总** `search-collect` | 关键词检索 → 一页清单草稿（资料收集） | 读页面；新建页面（草稿） | 命令面板 → 「把检索结果整理成一页」 |
| **页面状态** `page-status` | 给当前页标状态（待办/进行中/已完成） | 读属性定义；写属性（草稿）；加标签（草稿） | 命令面板 → 「设置当前页状态」（**属性优先，没有「状态」属性就用同名标签兜底**） |
| **活动摘要** `activity-digest` | 把「同步完成」「附件导入完成」记成一条摘要：日志明细 + 同步真有推拉时提示一次 | 插件自己的日志与私有数据（**读不到你的笔记**） | 事件 `sync.completed` / `import.finished`；命令面板 → 「看活动摘要」 |
| **附件信息** `attachment-report` | 在文件列表里右键 → 报告这个附件的名字/大小/类型与在所属页里的位置 | 只读附件元数据 | 文件列表 → 右键任一项 → 「插件命令」 |
| **阅读看板** `reading-board` | 一张「最近更新」浮层表（天数/条数**在设置里调**）+ 一个「本月新增」**右侧常驻面板** | 无（零代码声明式视图） | 命令面板 → 「插件视图：最近更新」；右侧竖条 → 「本月新增」 |
| **护眼主题** `eye-care-theme` | 暖白背景 + 降蓝正文 | 无（零代码主题） | 启用即生效；停用即恢复 |
| **高对比主题** `high-contrast-theme` | 纯黑纯白，投屏 / 投影 / 老花 | 无（零代码主题） | 同上 |

> **权限一栏请照实写进社区帖**（尤其"导出文件是明文、不随空间加密"这一条）：
> 用户是在看清权限与理由之后才点启用的，帖子里含糊其辞等于让他盲装。

## 发布时可以直接用的三段话

- **主题类**（`eye-care-theme` / `high-contrast-theme`）：零代码插件，只有一个 `manifest.json`——
  没有一行可执行的代码，所以信任成本和装一个主题一样。启用即生效、停用即恢复，不写入任何配置文件。
- **工具类**（`page-to-md` / `csv-table` / `search-collect`）：都要么读、要么**产出草稿**。
  写笔记一律先给草稿等你确认；导出的文件由你在系统保存对话框里选位置，点取消就什么都没写。
- **整理类**（`weekly-review` / `stale-triage` / `orphan-pages` / `page-status`）：只解决
  "一堆页面需要有人看一眼"这件事——它们不会替你改笔记，只会把值得看的那几页整理成一份草稿。

## 发布：让别人也能一键装（索引 + 签名）

上面「安装（三步）」是**手动**的把目录拷进去。想让别人一条 URL 就装上，需要一份**索引**——
一个静态 JSON，放在任何能被访问到的位置（代码托管站的 release / Pages / 企业内网 / 自己的服务器）。
规范全文见[分发策略 §3.1](plans/2026-09-10-plugin-distribution-strategy.md)，可照抄的样例在
[`plugin-index.example.json`](plugin-index.example.json)。

**1. 打包**（包内**根目录**就是插件目录；多包一层也没关系——应用会自动下钻一层）：

```bash
cd examples/plugins && zip -r /tmp/weekly-review-1.0.0.zip weekly-review
```

**2. 算 sha256 和体积**（`sha256` 是**必填**的：应用拿它校验下载到的包，对不上就拒绝安装）：

```bash
shasum -a 256 /tmp/weekly-review-1.0.0.zip     # macOS / Linux
sha256sum /tmp/weekly-review-1.0.0.zip         # Linux
wc -c < /tmp/weekly-review-1.0.0.zip           # size
```
```powershell
Get-FileHash .\weekly-review-1.0.0.zip -Algorithm SHA256   # Windows
(Get-Item .\weekly-review-1.0.0.zip).Length
```

**3. 写进索引**：把 `id / version / apiVersion / minAppVersion / runtime / permissions(含 reason) /
license / downloadUrl / size / sha256` 填好。**权限理由请照实写**——用户在确认框里读到的是它，
含糊其辞等于让他盲装。

**4.（可选但强烈建议）签一份索引签名**，让用户能用公钥确认「这份索引没被人换过」：

```bash
minisign -Sm plugin-index.json        # 生成 plugin-index.json.minisig，与索引放同一目录
minisign -G -p mykey.pub              # 还没密钥就先建一对；私钥自己收好，公钥发给用户
```

用户在应用里填**索引地址**（必须 https）与**公钥**（可选，minisign 的裸 base64 或
`mykey.pub` 文件内容都认）：填了公钥就必须取到 `.minisig` 并校验通过，否则**直接失败**——
不会"取不到签名就跳过校验"。

**想先在本地把这条路走通**（不必先有服务器）：仓库里有一个人工验收用的小工具——
它把示例插件打成 zip、就地起一个**只监听 127.0.0.1** 的服务器并按规范生成索引：

```bash
node scripts/plugin-index-demo.mjs weekly-review 8787
# 然后把打印出来的 http://127.0.0.1:8787/plugin-index.json 填进「从索引安装（给 URL）」

# 演一次升级：先按上面的步骤装 1.0.0，然后换个端口 + 抬个版本号再来一遍，
# 面板上的按钮就会变成「升级到 9.9.9」
node scripts/plugin-index-demo.mjs weekly-review 8788 --version 9.9.9
```
（`--version` 只改**副本**里的版本号，不会动仓库里的示例文件；索引里的版本与包内 manifest 的版本始终一致。）
（明文 http 只允许本机回环地址，正是给这种自托调试用的；样例索引 `docs/plugin-index.example.json`
也被一条 Rust 测试盯着——规范改了而样例没同步，门禁就会红。）

**应用侧的规矩**（`插件管理 → 从索引安装（给 URL）`）：

- 索引与包都只走 **https**（唯一的例外是本机回环地址，给自托调试用）；
- 装之前按索引里的 `sha256` 校验包，先校验后落盘；`size` 与实际不符也拒；
- 界面显示**来源**（索引拥有者 + 域名）与**签名状态**（验过 / 没验过，两者一眼能分辨）；
- **没有人工审查**：能装不等于可信；装完默认未启用，权限逐条确认后才启用；
- 阶段 2 才做**发布者签名**（`signature` 字段）：现在索引里带了它也只是显示"带了、未校验"。

> **升级**：同一个 `id` 换个更高的 `version`（连同新的 `downloadUrl` / `size` / `sha256`）写进索引，
> 已装用户的按钮就变成「升级到 vX」；应用会整体替换并**先备份后动手**（装不上回滚到旧版），
> **不会**把用户的启用状态冲掉。如果新版本多声明了权限/事件，用户会看到「新增了哪几项权限」，
> 并且插件会**先被暂停**，等他重新确认才恢复运行——发布说明里提前讲一句会更好。
> 明确写更低的版本号会被拒（防误操作）；要降级得先卸载。
>
> 撤回：索引里把 `revokedAt` 填上（可附 `revokedReason`），应用会显示它但**不给装**。

## 想加更多插件时

- **同一个人写的配方帖请合成一篇**（"某某的三件套"），不要把社区刷成一个人的清单；
- **别为了凑数发插件**：空插件比没有插件更伤（这条写在分发策略里）；
- 发布前跑一遍 `pnpm plugin:validate <插件目录>`——它会告诉你权限理由缺没缺、manifest 有没有写错；
- 插件更新时**新增权限或事件会让用户看到一次「需重新确认」**（插件会暂停，直到他确认）——
  这是有意的设计，发布说明里值得提前讲一句。
