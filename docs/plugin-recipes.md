# 插件配方（第一批可发布清单）

> 面向**社区发布**：每个插件一句话定位 + 它要哪些权限 + 怎么装。可直接贴到社区
> 「模板 / 主题 / 插件配方」分类里。
>
> 为什么是这一份：插件生态的冷启动瓶颈不是能力条数，而是**"有哪些能用的插件"**——
> [分发策略](plans/2026-09-10-plugin-distribution-strategy.md) 里的闸门是"作者文档 + 至少 3 个
> 真实插件"，而第一批由我们自己先做（「一方先行」）。下面这些**都能直接装来用**，源码在
> [`examples/plugins/`](../examples/plugins/)，也全部进了回归测试（`cargo test` / 作者 CLI /
> 类型检查三处）。

## 安装（三步）

1. 打开「插件管理 → 打开插件目录」；
2. 把某个插件目录整个复制进去（**目录名必须与 `manifest.json` 里的 `id` 一致**）；
3. 回到面板点「校验」→ 看清权限与理由 → 「启用」。

新装的插件**默认未启用**，所有写操作都会先给你一份草稿，你确认后才落库。
想自己改或自己写：作者文档见 [`plugin-api.md`](plugin-api.md)。

## 清单

| 插件 | 一句话定位 | 要什么权限 | 怎么用 |
|---|---|---|---|
| **周回顾** `weekly-review` | 把最近 N 天动过的页面汇成一篇「回顾」草稿（清单 + 统计） | 读页面标题与更新时间；新建页面（草稿） | 命令面板 → 「生成回顾」（可填天数/条数） |
| **陈旧页巡检** `stale-triage` | 找出 N 天没更新的页面，批量打 #待整理 | 读页面；读标签；加标签（草稿） | 命令面板 → 「找出久未更新的页面」 |
| **孤立页面巡检** `orphan-pages` | 找出没人链过去的「孤岛」，生成清单草稿 | 读页面；读反向链接；新建页面（草稿） | 命令面板 → 「找出孤立页面」 |
| **当前页导出 Markdown** `page-to-md` | 把当前打开的页面写成一份 `.md` | 读当前页段落；导出文件（**存哪里由你选**） | 命令面板 → 「导出：用「当前页导出 Markdown」保存为 .md」 |
| **CSV 转表格** `csv-table` | 选中 `.csv`/`.tsv` → Markdown 表格放进新页面 | 新建页面（草稿） | 命令面板 → 「用「CSV 转表格」导入表格」→ 选文件 |
| **检索汇总** `search-collect` | 关键词检索 → 一页清单草稿（资料收集） | 读页面；新建页面（草稿） | 命令面板 → 「把检索结果整理成一页」 |
| **页面状态** `page-status` | 给当前页标状态（待办/进行中/已完成） | 读属性定义；写属性（草稿）；加标签（草稿） | 命令面板 → 「设置当前页状态」（**属性优先，没有「状态」属性就用同名标签兜底**） |
| **阅读看板** `reading-board` | 一张「最近更新」表 + 汇总，天数/条数**在设置里调** | 无（零代码声明式视图） | 命令面板 → 「插件视图：最近更新」 |
| **护眼主题** `eye-care-theme` | 暖白背景 + 降蓝正文 | 无（零代码主题） | 启用即生效；停用即恢复 |
| **高对比主题** `high-contrast-theme` | 纯黑纯白，投屏 / 投影 / 老花 | 无（零代码主题） | 同上 |

> **权限一栏请照实写进社区帖**（尤其"导出文件是明文、不随空间加密"这一条）：
> 用户是在看清权限与理由之后才点启用的，帖子里含糊其辞等于让他盲装。

## 发布时可以直接用的三段话

- **主题类**（`eye-care-theme` / `high-contrast-theme`）：零代码插件，只有一个 `manifest.json`——
  没有一行可执行的代码，所以信任成本和装一个主题一样。启用即生效、停用即恢复，不写入任何配置文件。
- **工具类**（`page-to-md` / `csv-table` / `search-collect`）：都要么读、要么**产出草稿**。
  写笔记一律先给草稿等你确认；导出的文件由你在系统保存对话框里选位置，点取消就什么都没写。
- **整理类**（`weekly-review` / `stale-triage` / `orphan-pages` / `page-status`）：只解决
  "一堆页面需要有人看一眼"这件事——它们不会替你改笔记，只会把值得看的那几页整理成一份草稿。

## 想加更多插件时

- **同一个人写的配方帖请合成一篇**（"某某的三件套"），不要把社区刷成一个人的清单；
- **别为了凑数发插件**：空插件比没有插件更伤（这条写在分发策略里）；
- 发布前跑一遍 `pnpm plugin:validate <插件目录>`——它会告诉你权限理由缺没缺、manifest 有没有写错；
- 插件更新时**新增权限或事件会让用户看到一次「需重新确认」**（插件会暂停，直到他确认）——
  这是有意的设计，发布说明里值得提前讲一句。
