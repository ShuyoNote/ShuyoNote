## 1. GitCode Release（shuyo-cn/ShuyoNote）

```text
① 把 GitHub 的 5 个资产下载到本机（路径只作示例）：
   src-tauri/target/release/bundle/nsis/ShuyoNote_2.1.16_x64-setup.exe
   src-tauri/target/release/bundle/deb/ShuyoNote_2.1.16_amd64.deb
   src-tauri/target/release/bundle/appimage/ShuyoNote_2.1.16_amd64.AppImage
   src-tauri/target/release/bundle/apk/ShuyoNote_2.1.16_android-arm64-release.apk
   （.sha256 与 apk 同目录）
② 用发版脚本（令牌只进环境变量，⛔ 不回显、不进聊天/日志）：
   $env:GITCODE_TOKEN = '<令牌>'       # 从密钥文件读，不要粘贴到终端历史
   node scripts/release.mjs --no-build --artifacts `
     ShuyoNote_2.1.16_x64-setup.exe,ShuyoNote_2.1.16_amd64.deb,ShuyoNote_2.1.16_amd64.AppImage `
     --android-apk src-tauri/target/release/bundle/apk/ShuyoNote_2.1.16_android-arm64-release.apk
   （macOS 三个资产也一并上传：dmg / app.tar.gz / app.tar.gz.sig）
③ 额外必传：Web 包 `ShuyoNote_2.1.16_web.zip`（见 §0；sha256 已给）
   —— 与安装包**同一次发版**放进 GitCode release，缺了会出现「检查到新版本但 /app 刷新无效」
   （2.1.16 的故障就来自这一格；2.1.10 有、2.1.16 第一版漏）
④ 判据：
   gitcode release 页出现 v2.1.16，三平台＋APK＋**Web zip**＋latest.json 齐全；
   `node scripts/check-release-state.mjs` = **24/24**（win exe + linux deb + apk + sha256 + 通道版本一致）
```
