# 「项目网站导航」方案（M25 P2：外部站点入口，决策/建议）

> 一句话：ShuyoNote 是**本地优先 · 离网可用**的笔记工具，外部项目网站做的是**「可发现但克制、绝不阻塞、绝不跟踪」的出口**，而不是把用户推向 SaaS/账号/云服务。它承接内置帮助的溢出（深度教程 / 发布 / 社区 / 反馈），但**永远不成为核心路径**。
> 状态：**决策/建议**（利弊分析 + 入口设计），**未实装**。定位为 [帮助系统方案（M25）](2026-08-27-help-system-plan.md) 的 **P2 层细化**。

---

## 1. 背景与界定

所谓「让用户方便导航到项目网站」，指**应用内**到**外部站点**的跳转入口。外部站点至少三类，风险和定位不同，**必须分开对待**：

| 类型 | 例子 | 侧重 | 风险 |
|------|------|------|------|
| **开源项目主页/仓库** | gitcode 仓库页 | 透明、可信、下载、贡献 | 低 |
| **文档/帮助静态站** | M25 P2 的外部站（复用 M21 静态 wiki 导出） | 深度教程、FAQ、版本说明 | 低 |
| **营销性落地页** | 带账号/注册/转化的站点 | 拉新、转化、线索 | 高（与本地优先冲突） |

> 对本地优先工具，**第三类与前两类要严格区分**；本方案只承接前两类。

---

## 2. 利弊分析与决策

### 2.1 好处
- **承接内置帮助的溢出**：内置「使用指南」页（M25 P1）只能精简；深度教程、视频、FAQ、版本说明放外部站，显著降低答疑负担。
- **版本与发布触达**：用户能自检新版本、看 changelog、拿安装包，减少「不知道要升级/去哪下」。
- **社区与反馈闭环**：一键到 issue / 讨论区提 bug、要功能，迭代更快；对开源项目尤其重要。
- **建立可信度（尤其 AGPL）**：可见的项目主页 + LICENSE + 透明度说明，让用户确认「我装的是官方原版」，也是防钓鱼/防冒牌替换的手段。
- **保持应用界面精简**：深度内容推到 Web，应用内 UI 不膨胀。
- **促活与长尾**：功能清单 / 路线图让用户用满功能，也更容易贡献 / 打星 / 赞助。

### 2.2 坏处 / 风险
- **削弱「本地优先」承诺**：核心路径若依赖外部站（帮助、更新都要联网），离线 / 断网用户（正是目标人群）感觉被打折；隐私敏感用户看到「打开浏览器」极易反感。
- **断网体验断裂**：内置引导必须能完全离线完成；一旦「帮助 = 开浏览器且没网」体验直接报废。
- **隐私 / 采集顾虑**：外链若带 `utm` / `ref` / 埋点参数就是隐性跟踪，对以隐私为卖点的应用是毒药；也构成数据外泄面。
- **死链与漂移**：站点迁移/下线即链失效，需重定向策略；且 **外部文档极易与 App 版本脱节**（曾出过「快捷键清单几处不准」），双源不一致反而失信任。
- **滑向 SaaS 的风险**：漏斗到带账号/云服务的网站，与本地优先定位和 AGPL sync-server 哲学冲突；用户会担心本地数据被收编。
- **侵入感 / 广告感**：弹窗、横幅、「访问我们的网站」用多了像广告，弄脏一个每天打开的工具的质感。
- **维护成本**：多一个需长期跟进的表面。

### 2.3 决策
**做，但要做成「可发现但克制、绝不阻塞、绝不跟踪」的被动出口。** 具体不变量：
1. **离线优先**——网站只作补充，绝不作必须路径。
2. **不跟踪**——不带埋点 / `utm` / `ref`；不因点击外链上报任何事件。
3. **不阻塞**——不弹窗、不强引导、不打断；入口全部是被动、可跳过。
4. **可关闭**——提供「禁用外部导航」设置，尊重隐私用户。

## 3. 入口设计（落地）

### 3.1 入口集合（全部被动、不打扰）
| 入口 | 位置 | 动作 |
|------|------|------|
| **「关于」对话框** | 设置 / 帮助 | 显示版本、许可（AGPL-3.0）、项目主页 / 文档 / 发布 / 问题四个链接 |
| **「检查更新」** | 设置 | 打开发布页（或新增版本自检） |
| **帮助页脚注** | 内置「使用指南」页底部 | 「想深入了解？访问项目站点 / 文档」 |
| **「开源与反馈」区块** | 关于 / 脚注统一渲染 | 项目主页 · 文档 · 发布 · 问题，四个干净链接 |

> **不做**：启动弹窗、悬浮横幅、页面内「去官网看我」的强引导。

### 3.2 「关于」对话框内容结构
- 应用名 / 图标 / 版本号（读 `appVersion`）。
- 许可：**AGPL-3.0**（注明 sync-server 网络托管需同开源）。
- 一句定位（本地优先 · 类 Notion）。
- **「开源与反馈」**：`项目主页` · `文档` · `发布` · `问题`（用 `external shell.open` / `window.open` 打开浏览器）。
- **「禁用外部导航」开关**（见 3.4）。

### 3.3 链接策略（干净链接）
- 只链四个稳定 URL：项目主页 / 文档 / 发布 / 问题；**不带** `utm` / `ref` / 跟踪参数。
- 由**单一来源**（如 `src/lib/links.ts`）定义，供「关于」「检查更新」「脚注」共用，避免散落硬编码。
- 重定向：站点迁移时靠服务端 301 / 重定向保持旧链有效。

### 3.4 隐私开关
- 设置项：「**允许跳转到外部项目网站**」（默认开？——建议**默认开但无任何埋点**；若要更激进，可默认关）。
- 关闭后：所有外部链接显示但点击不跳（或显示「外部导航已禁用」提示），不影响离线功能。

### 3.5 站点自控
- 站点应放在**自己可稳定控制**的域（或仓库 Pages，如 gitcode 的 pages），**优先于**第三方营销站。
- 主页侧重 **透明 + 文档 + 下载**，而非「拉新转化」；不引导注册 / 账号 / 云服务。

### 3.6 双源一致性
- 外部站文档由 `src/lib/shortcuts.ts` / `guide.ts` / `covers.ts` 等**单一来源生成或引用**，避免再次出现「快捷键清单不准」这类双源漂移。
- 内置「使用指南」页（M25 P1）仍为**权威、可离线**；外部站是「想深挖才去」，不是替代。

## 5. 验收标准

- 「关于」对话框：版本 / 许可正确（当前 v1.59.177，AGPL-3.0），四链接可达且 URL 干净（无跟踪参数）。
- 「禁用外部导航」开关：关闭后外链不跳转，离线功能不受影响；设置持久化。
- 内置「使用指南」页脚注指向站点；外部站若下线，应用内无死链依赖（帮助页本身可离线）。
- 不新增在线埋点：无网络上报事件。
- `npx tsc --noEmit` / `node scripts/smoke-web.mjs`（新增断言全绿不减少）/ `pnpm build` / `cargo check`（应无新 Rust 命令）。

## 6. 边界与诚实标注

- **不做**：在线客服/工单/应用内分析、带账号的营销落地页、打断式引导弹窗、外链埋点统计。
- **外部站不是主形态**：帮助主形态仍是内置「使用指南」页（可离线、可搜索、可导出）；外部站仅作发现渠道与深度补充。
- **不可靠网络下不降级**：外部站不可达时，应用内所有功能照常；不因断网弹错/降级。
- **AGPL 隐含约束**：页面/站点若作网络托管且非私有部署，需遵循同开源要求——本方案只做链接出口，不承担托管逻辑，无额外许可风险。
- **多语言**：本阶段仅中文；i18n 不在范围。
