## 3. 必须改的四条

### ① 加密选型：改用**国密**（owner 2026-10-09 拍 ✓）
本仓加密身份是**国密**：`sm-crypto` = SM4-CBC ＋ HMAC-SM3（应用层 AEAD）✓，库级 SQLCipher 走 Tongsuo ✓。
方案 §9 原选 AES-256-GCM ＋ Argon2id ＋ BIP-39 ✗ ⇒ **同一个产品里出现两套加密身份** ✗（对外口径不好答）。
⇒ **落地口径**：备份信封沿用国密 —— **SM4-CBC ＋ HMAC-SM3（EtM）** ✓，DEK 用 **SM2** 包 ✓，
口令派生沿用仓库既有的 PBKDF2 侧（`sm-crypto` feature 已含 `pbkdf2` ✓）✓。
⛔ 这条属仓规「动加密相关必须先问」⇒ 已由 owner 拍 ✓；**实现时不许再自选算法** ✗。

### ② 方案漏了一条硬约束：**在线备份 API 对加密库不支持**
`backup.rs:41` 逐字：「**`backup is not supported with encrypted databases`**；两边同钥才成功（产物是**密文**）」。
代码的实际处置：`snapshot_spaces()` 里按 `space_db_is_encrypted(&path)` 分叉 ✓，并有测试
`snapshot_spaces_keys_the_encrypted_space_and_names_what_it_skips` 专门钉住"跳过什么、如实报什么" ✓。
⇒ **方案 §5.3 那句"不锁库、不阻塞写入"只对未加密库成立** ✗ ⇒ 必须补写：**加密空间怎么拿一致快照**
（先 checkpoint/WAL 收口 ＋ 整文件拷贝 ✓，或"同钥前提下用 SQLCipher 侧接口"✓），且**跳过项要如实报** ✗ 不许静默少数据 ✓。

### ③ `--backup-once` 无头模式＝一块**独立**工作（不是加个 flag）
`main.rs` 无参数解析 ✗ ⇒ 要做：参数解析 ✓ ＋ **不建窗口的启动路径** ✓（Tauri 窗口应用要单独设计 ✓）＋
三平台计划任务/launchd/systemd 的**注册与撤销** ✓ ＋ 用户可见开关与隐私说明 ✓。

### ④ 「恢复到新目录」**不改**（owner 2026-10-09 拍 ✓）
方案 §10 要默认恢复到新目录 ✗；本仓 `import_backup` 是**合并导入** ✓（`backup.rs:16` 提到 merge import ✓）。
⇒ **保持现状** ✓（零风险 ✓、不改用户习惯 ✓），只把「覆盖/合并前的确认」**加严**一点 ✓。
⚠️ 若将来要改语义：那是**用户可见行为** ⇒ 必须 owner 拍 ✓，且要一并想清"新目录恢复完**怎么切过去**"（应用数据目录是固定的 ✗）。
