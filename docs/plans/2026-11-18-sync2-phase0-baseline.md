## 3. 这一版**量得到**什么

- 单轮拉取耗时分布（`ms`：p50 / p95 / max、`>1s` / `>100ms` 条数）；
- 缺口：多少轮 `gap>0`、合计缺多少条；
- 每次拉取带回多少条（`fetched` / `applied`）；
- 按空间 / 按对端（编号后）的轮数与耗时 —— 这是 F2/F3 判断"哪条路慢"的最小区分度。

## 4. 这一版**量不到**什么（F2/F3 还缺的基线）

| §13.12 要的 | 现状 | 为什么量不到 |
|---|---|---|
| **改 → 对端可见延迟**（p50/p95） | ❌ 空 | 要「保存时刻」与「对端拉完时刻」**跨机对齐同一时钟**；日志里没有共同时钟 ⇒ ⛔ 不许拿本机 `ms` 冒充 |
| 通知 / 轮询的端到端时延 | ❌ 空 | 同上（F1 真机那次只有同侧读数：保存→公告 ≤1.75 s、收到公告→拉完 ≤1 s，⛔ 不能相减） |
| 设备 × 空间水位差 | ⚠️ 部分 | 空间级的本机 `gap` 有；「谁缺谁的数据」要 `mesh_watermarks` 逐台读数（O1 已落，见交接单） |
| 重启 / 换网 / 休眠后的恢复时间 | ❌ 空 | 日志里只有断连类 `recovered_after_ms`，本批一次没出现；换网/休眠**没有任何埋点** |
| 心跳与推送的耗电、流量 | ❌ 空 | 没有任何耗电/流量读数；要平台级采样，不是本仓日志能给 |

⇒ 结论：**F2（反熵）/ F3（调度自适应）现在有"轮耗时 + 缺口"的底，但没有"改→可见"和"恢复时间"的底。**
下一步若要做 Phase 0 完整版，最省的是：**给「保存时刻」与「对端拉完时刻」各打一条带同一来源时钟的行**
（同一台机器上打两个时刻才能相减；跨机只能各报各的，⛔ 不相减）。
