## 3. 这一版**量得到**什么

- 单轮拉取耗时分布（`ms`：p50 / p95 / max、`>1s` / `>100ms` 条数）；
- 缺口：多少轮 `gap>0`、合计缺多少条；
- 每次拉取带回多少条（`fetched` / `applied`）；
- 按空间 / 按对端（编号后）的轮数与耗时 —— 这是 F2/F3 判断"哪条路慢"的最小区分度。

## 4. 这一版**量不到**什么（F2/F3 还缺的基线）

| §13.12 要的 | 现状 | 为什么量不到 |
|---|---|---|
| **改 → 对端可见延迟**（p50/p95） | ❌ 空 | 要「保存时刻」与「对端拉完时刻」**跨机对齐同一时钟**；日志里没有共同时钟 ⇒ ⛔ 不许拿本机 `ms` 冒充 |
| 通知 / 轮询的端到端时延 | ❌ 空 | 同上（F1 真机那次只有同侧读数：保存→公告 ≤1.75 s、收到公告→拉完 ≤1 s，⛔ 不能相减） |
| 设备 × 空间水位差 | ⚠️ 部分 | 空间级的本机 `gap` 有；「谁缺谁的数据」要 `mesh_watermarks` 逐台读数（O1 已落，见交接单） |
| 重启 / 换网 / 休眠后的恢复时间 | ❌ 空 | 日志里只有断连类 `recovered_after_ms`，本批一次没出现；换网/休眠**没有任何埋点** |
| 心跳与推送的耗电、流量 | ❌ 空 | 没有任何耗电/流量读数；要平台级采样，不是本仓日志能给 |

⇒ 结论：**F2（反熵）/ F3（调度自适应）现在有"轮耗时 + 缺口"的底，但没有"改→可见"和"恢复时间"的底。**
下一步若要做 Phase 0 完整版，最省的是：**给「保存时刻」与「对端拉完时刻」各打一条带同一来源时钟的行**
（同一台机器上打两个时刻才能相减；跨机只能各报各的，⛔ 不相减）。

## 4.5 ⭐ 埋点已加（2026-11-18，owner 拍「动埋点」）——但**还没有真读数**

上面 §4 那两格「量不到」，其中**两段是可以量的**（只要承认"跨机不可相减"）：

| 段名 | 起点 | 终点 | 谁打的 |
|---|---|---|---|
| `save_to_announce` | 本地保存那一刻（`request_round_now_from_source`） | 那条带 `dirty` 的公告**真的发出去**那一刻 | `lan_state.rs::latency_line` |
| `announce_to_round_done` | 收到对端 `dirty` 公告那一刻（`request_round_now_from_peer`） | 被它唤醒的那一轮**跑完** | 同上 |

- 形状：`[sync-latency] seg=<段名> ms=<差>`；**默认一个字都不打** —— 只在
  `SHUYONOTE_LAN_DEBUG_ANNOUNCE` 开着时输出（与 `announce_recv_line` 同一个开关）。
- 口径三条（都有判据）：起点 ≤0 ⇒ **不打**（⛔ 不拿 0 当"0 毫秒"）；终点早于起点 ⇒ 记 **0**（⛔ 不写负数）；
  起点用 `swap(0)` **消费掉**（⛔ 不许跨轮复用成假读数）。
- ⛔ **仍然量不到端到端**：`保存 → 对端可见 = ① + 传输 + ②`，中间那一段要共同时钟。
  ⇒ 报告里**分开列**，永不把两段拼成"端到端"（判据 `expect(text).not.toContain("端到端 =")`）。
- ⚠️ **没有真读数**：本机当前没有开着 debug 开关跑过一轮（dev 应用未启动）⇒
  这一格**是空的**，⛔ 不写 0、⛔ 不宣称"改→可见已量"。

做法：`SHUYONOTE_LAN_DEBUG_ANNOUNCE=1` 起 dev（`--remote-debugging-port=9222`），用 CDP 调**真的**
`save_page`（不是改库、不是伪造），读日志。

| 会话 | 保存 → 公告发出 |
|---|---|
| A（15:28:07） | **238 ms** |
| A（之后一次保存 → 15:31:21 才发出） | **74,386 ms**（≈74 s） |
| B（15:31:34） | **123 ms** |

**这是双峰的**，比读数本身更要紧：

- **快支**：≈0.1–0.24 s（保存后那一轮事件轮真的跑起来 ⇒ 立刻公告）；
- **慢支**：**几十秒**（这次 74 s）—— 保存没有换来"立刻公告"，`dirty` 的公告搭了后面某个 30 s 节拍。
  ⚠️ 74 s **远超** F1 已拍的验收口径「保存后 ≤10 s 对端拉到」⇒ **慢支这半边必须先查清**，
  否则 F1 那条"已通过"只在快支上成立。

⚠️ 三条如实标注：
1. 样本只有 **3 条**（两个会话）⇒ 不足以当分位数，只是**存在性**证据（"慢支真的会到 74 s"）；
2. 慢支的**机理未定位**（候选：`event_round_ready` 的在飞/合并窗把这一次唤醒挡下、而 `ANNOUNCE_DIRTY_PENDING`
   只在"轮真的跑"那一支才置 ⇒ 那一次保存的 `dirty` 就等下一轮；30 s 公告节拍放大了后果）。
   ⛔ 不写成"已解释"，也⛔ 不写成"已修"；
3. 这两份日志里**没有 `[sync-metrics]`**（本轮没真的拉到东西）⇒ 轮耗时基线仍取 §2 那批旧日志。
