## 2. 产品定位与路线

### 2.1 为什么必须是 Tauri 原生壳（Android / iOS）

移动端不是「把 Web 页面塞进浏览器」。核心承诺是**本地优先 / 数据主权 / 离线**，而 WebView 壳  
（加载 `dist-web` ＋ IndexedDB）会直接违背它：

| 能力    | Tauri 原生壳                | WebView 壳                        |
| ----- | ------------------------ | -------------------------------- |
| 加密    | SQLCipher 真加密，与桌面同一套     | IndexedDB，无同等级加密                 |
| 数据落地  | 应用私有目录里的真实文件，可备份、可搬移     | 浏览器存储，可能被系统回收                    |
| 多设备同步 | ✅ 与桌面同一套                 | **产品决定 2026-09-15：Web 版不开多设备同步** |
| 插件    | ✅ 完整（Boa 运行时）            | ❌ 浏览器跑不了 Rust `boa_engine`       |
| PDF   | 原生 PDFium（默认）＋ pdf.js 回退 | 只有 pdf.js                        |
| 体积    | 大（已做过压缩）                 | 小                                |

一句判据：**平台能跑 Tauri 就走 Tauri 原生壳**；跑不了才退 WebView 壳，并如实标注该平台是  
**能力子集**（当前只有鸿蒙 ArkWeb 属这一类）。

### 2.2 四条路线与 owner 拍板（R203）

| 级别        | 内容                                       | 结论                                                                                                |
| --------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 甲 · 响应式模式 | 同一个 App，靠宽度媒体查询换组件                       | ⛔ **到顶了**：横屏 792×360 被判成桌面、`useMobile()` 有副作用、手机 ⚙️ 打开桌面对话框被裁、存完落阅读屏、工具栏要让开悬浮 ☰ … 每条都是「给桌面加例外」的症状 |
| 乙 · UI 单立 | 移动自己的入口 / 导航栈 / 设计令牌 / 设置面；与桌面共用 Rust 内核 | ✅ **owner 拍「走」**（阶段 1–2）                                                                          |
| 丙 · 交付单立  | 独立版本号 / 渠道 / CI job / 验收包 / 商店素材         | ✅ **owner 拍「走」**（阶段 3）                                                                            |
| 丁 · 代码仓单立 | 拆成独立仓                                    | ⛔ **不做**：Rust 内核会变成两份真相源                                                                          |

### 2.3 四条长期义务（「做成产品线」的代价，owner 已确认）

1. **上架**：苹果开发者账号；国内安卓各商店需软著＋备案。
2. **合规材料**：隐私政策、备案号、软著 —— 当前文档与界面里仍是占位符。
3. **持续发版**：每次改动两端都要编、签、验、审。
4. **真机验收**：只有 owner 能做（设备：华为 Mate 40，`UJN0221310000547`）。

### 2.4 明确的「不」清单（结构性，不是嫌麻烦）

- ⛔ **不拆仓**、⛔ **不 fork 一份 Rust 内核**。
- ⛔ **不在 Android/iOS 上用 WebView 壳替代 Tauri**（除非 Tauri 在该平台不可达）。
- ⛔ **不把「桌面能跑」当成「手机能跑」**：触摸没有 hover、软键盘会改可视区、返回键会退应用。
- ⛔ **不为凑门禁基线往移动设置里塞桌面入口**（R192 的口径）。

## 7. 交互与设计规范

### 7.1 形态判定（阶段 0 的单一出处）

`src/lib/platform/shape.ts` 只导出纯函数/常量，⛔ 无订阅、无副作用：

| 判定 | 规则 | 用途 |
|---|---|---|
| `isNarrowViewport(w)` | `w ≤ 768` | 布局是否换窄屏形态（侧栏抽屉、整屏叠加） |
| `isShortViewport(h)` | `h ≤ 520` | 浮层是否取整屏/内部滚动 |
| `isMobileOverlayViewport(w,h)` | 窄**或**矮 | 浮层形态 |
| `isMobileViewport()` | `matchMedia('(max-width:768px)')` | 只在需要浏览器能力时用 |
| `hasCoarsePointer()` | `(hover:none)` | 触屏能力；**不并入宽度口径** |

**为什么不用 `useMobile()` 判断「是不是手机」**：它有副作用（进窄屏会强制关侧栏）；第二个订阅者会把
用户打开的抽屉压回去（实测三条断言全红）。布局看宽度、浮层看宽高、能力看指针，三件事分开。

### 7.2 触控与命中区

- 可点控件 **≥44×44**；底栏项高 56；FAB 56×56；工具栏 6 项在 390 档一屏装得下（`right=366≤390`）。
- 快速记录屏**不挂底栏**（`App.tsx` 的 `showTabs: mobileScreen !== "capture"`）；它的回家路是左上「‹ 返回」＋安卓返回栈。
- 320×568 档工具栏仍有 46px 溢出 ⇒ 靠 `overflow-x:auto` **横滑可达**；⛔ 不用 `overflow:hidden` 藏。
- 触屏没有 hover：靠 `:hover` 才显形的操作在手机上**等于不存在**（历史事故：22×22 的删除/导出）。

### 7.3 安全区与软键盘

- 底部用 `--sab`；底栏高 `56 + --sab`；内容让位靠 `.m-tabshell` 的**唯一一处** `padding-bottom: 64 + sab`；
  快速记录用 `.m-tabshell--no-tabs`（没有底栏，不预留 64px）。
- `index.html` 的 viewport 带 `interactive-widget=resizes-content` ⇒ 键盘弹起时内容区缩短，
  底部工具栏自然位于键盘上方。
- 顶部状态栏/刘海：Android 上 `env(safe-area-inset-*)` 可能为 0，壳层另有 inset 变量；别假设 iOS 语义。

### 7.4 返回键与浮层

- 新增浮层必须登记进 `verify-mobile-overlays.mjs` 的 `OVERLAYS`；否则安卓返回键**直接退出应用**。
- 手机专属屏若不在所有视口渲染，不塞进 `OVERLAYS`（会造假红）；直接 `pushOverlay(id, close)` 接同一套栈。
- 相机/相册/文件选择器等系统界面返回不归我们管。

### 7.5 文案与诚实呈现

- 读不到 ⇒ 说读不到；没做 ⇒ `disabled` ＋ `title` 写原因；⛔ 不做「点了没反应」的假按钮。
- ⛔ 不把 `device_id` 写进用户可见句子；身份行只用「设备名＋短标识」。
- ⛔ 不渲染没有出处的状态词（如「已配对」没有读数就不写）；⛔ 不渲染「去开加密」这种目的地只在桌面的假动作。
- 占位符（隐私政策/备案号）必须显式写「待填」，不编造。

### 7.6 设计令牌（2026-10-20 起：浅色为主）

- 390×844 设计；**视觉基线＝浅色重设计**（[`2026-10-20-redesign/README.md`](./mockups/2026-10-20-redesign/README.md)）：
  `--bg #FFFFFF`、`--surface #FFFFFF`、卡片描边 `#E5E8EE`、文字 `#1F2329`、主色 `--accent #3370FF`、
  选中/浅底 `--accent-soft #EBF1FF`；分类色红 `#F54A45` / 橙 `#FF8A1E` / 绿 `#00B578`。
- 卡片统一圆角 12–16、胶囊 999；主行动用品牌蓝渐变（`#3370FF → #5B8CFF`）；状态胶囊用「浅底实色字」。
- ⛔ 不自创品牌色、不新增主题；字体只用系统族。
- **双主题**：token 化实现仍要支持浅/深色；**深色观感未验**。⚠️ 浅色重设计已落到 CSS（2026-10-20），
  但**真机观感未签**（M-P1-11）。

## 10. 交付、版本与合规

### 10.1 版本

- **唯一事实源**：`mobile-version.json` 的 `mobileVersion`＝`1.92.24`。
- **不许低于桌面号**（R204）：手机上是 1.92.x，往回跳会让用户看到「版本变低」。
- `scripts/write-mobile-version.mjs` 写 `tauri.android.versionName` 与 `versionCode`；
  `versionCode = major*1000000 + minor*1000 + patch`。
- `MOBILE_APP_VERSION` 经 `vite.config.ts` 的 define 注入 `APP_VERSION` ⇒ 启动页/关于屏显示同一个号。
- 门禁 `check-mobile-app-version`：事实源恰好一处、不是桌面号别名、不低于桌面号。

### 10.2 Android 构建与签名

| 项 | 自检包（`android.yml`） | 发版件（`release.yml` android job） |
|---|---|---|
| 触发 | 手动 / 本文件变更 / `dev`、`main` 相关路径 | tag 发版（`release` needs android） |
| 测试钩子 | `VITE_TEST_HOOKS=1`（job 级） | **任何层级都不设**，构建前显式断言为空 |
| 产物 | `android-apk-aarch64-signed-test-hooks`、unsigned | `android-release-apk`＋`.sha256` |
| 签名 | 正式密钥，`apksigner verify` 后与硬编码 SHA-256 比对 | 同左（逐字一致） |
| ABI | arm64-v8a | 断言恰为 arm64-v8a |
| 失败影响 | 只影响自检 | **Android 失败阻断整个 Release**（宁可晚发，不发半套） |

- 只出 APK，不出 AAB（apksigner 签不了 AAB；本产品不走 Play 的 AAB 路径）。
- 壳适配层由脚本注入（`gen/` 不入库）：`android-mobile-shell`、`platform-verifier`、`app-icon`、
  `app-name`、`splash-theme`、`portrait-lock`、`pdfium` 等；两条 workflow 同名步骤由 `check:release-parity` 核对。
