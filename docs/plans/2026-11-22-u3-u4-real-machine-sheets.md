## A. U4 片4：块级同块冲突（Windows A ⇄ AMD B）

### 前置（缺一条不做）

```text
1) 两台跑同一 dev 构建：各自 `git rev-parse --short HEAD`，短 SHA 必须一致并把值记下来。
2) 同一 Wi-Fi/网段、LAN 已配对；只用测试空间。
3) 先让同一页两边收敛：打开同一页、等一轮成功，记最后一次成功时刻。
4) A 起日志（窗口别关）：
   cd C:\Users\cnzen\zhai\repos\ShuyoNote
   $env:SHUYONOTE_MESH_AUTOSYNC="0"   # 只暂停 A 的自动轮；手动同步照旧
   pnpm tauri dev 2>&1 | Tee-Object -FilePath _tmp\scratch\u4-block-<HHMM>.log
5) B 不设该变量；B 的 Wi-Fi 开关要够得着。
```

### 步骤（造同块同位置冲突）

```text
1) A 新建页 `U4-BLOCK-<HHMM>`，正文 3 个项目符号块：
   · U4-B1 原始
   · U4-B2 原始句（两台同时改这一句）
   · U4-B3 原始
2) 等 A→B 同步完成；B 打开同页确认 3 块、文字一致。记「基线：3 块」。
3) A 把第 2 块改成 `A 改的同一句`，只改一次，等保存完成。
4) B **关 Wi-Fi**，把第 2 块改成 `B 改的同一句`，只改一次，等保存完成。
5) B 开 Wi-Fi；A 点「立即同步」（自动轮仍暂停）。
6) 观察 A 是否出现 `role=status` 冲突提示条：标题应为「这一页有 N 处冲突」；
   单块冲突时**不应**出现批量按钮（批量只在 N>1）。
```

### 每一步记录

```text
· 时间：A 改完 / B 改完 / B 回网 / A 手动同步 / 提示条出现（人读秒表；⛔ 跨机日志不相减）
· 页面：标题、3 个块是否都在、第 2 块显示哪句
· 提示条：标题、摘要行、建议/两难行、按钮「定位 / 留本地 / 用远端」是否都在
· 日志：A 的 `u4-block-*.log` 里 `[mesh]` 本轮成功/失败；出现 `[crdt]`/`[a1]` 原样抄
· 数据侧：选「留本地」后 B 是否收到 A 版；再验反向「用远端」
```

### 判据

```text
✓ 3 个项目符号块一个不少（⛔ 块变两份/空块）
✓ 第 2 块两版都能找回：提示条出现，且「留本地 / 用远端」都能执行
✓ 无静默覆盖：提示条出现前，A 的第 2 块没被 B 版换掉
✓ 人工裁决入口可见：摘要＋建议/两难＋按钮；单块时批量按钮不出现
✓ 选一侧后能收敛：留本地 ⇒ B 看到 A 版；再验反向
✗ 任一块消失/变空 ⇒ 立即停、留证
✗ 内容被换但无提示条 ⇒ 不算通过；若内容混合，记「疑似 A1 路径」，另开 A1 验收
✗ 提示条出现但按钮点不动/报错 ⇒ 不算通过
```

### 失败留证与回滚

```text
1) 截图：编辑器（含 3 块）＋ 提示条（摘要/建议/按钮）＋ 标题。
2) A：同步面板 → 局域网同步状态卡 → 连接体检 →「复制诊断包」；粘进交接单。
3) 保留 `u4-block-*.log`；⛔ 不清日志、⛔ 不重装/重配对掩盖现场。
4) 先别删页；用「留本地」或「用远端」结掉冲突，另一版在版本历史里。
5) 删 `SHUYONOTE_MESH_AUTOSYNC` 并重启 A，恢复自动轮。
6) 重测另建新页（新标题），⛔ 不在旧页反复覆盖当新读数。
```

### 已知边界

```text
· 本单是块级 `page_conflicts`（同 rev 不同内容）；页级血统冲突是另一条路（handoff §15）。
· 只有两边都改同一块才成立；一边没改 ⇒ 不落冲突行，正常。
· 用 CDP/直接改库造出的冲突不得冒充真机读数。
```

## B. U3 片4：失败重试（60s 间隔 / 401）

### 前置

```text
1) A=Windows、B=AMD，同一 dev 构建（短 SHA 一致），同一 Wi-Fi、已配对。
2) 只留一个测试空间参与同步；A 不要编辑页面（避免前端自动保存触发事件轮）。
3) A 起日志：
   cd C:\Users\cnzen\zhai\repos\ShuyoNote
   pnpm tauri dev 2>&1 | Tee-Object -FilePath _tmp\scratch\u3-retry-<HHMM>.log
4) 记下 B 的 IPv4（下一步防火墙用）；⛔ 不把 IP 写进对外材料。
5) ⭐ **2026-11-26 真机补上的前提（原单漏了）**：**B 必须先有新数据可拉** ——
   两边完全同步、没有新数据时，A 的"拉取"在本地**短路**（日志 `ok fetched=0 cursor=298 max=298`），
   **不发任何请求** ⇒ 阻断不会产生失败 ⇒ 加速重试阶梯永远不启动（实测空转 20 分钟，零失败）。
   ⇒ 做法：**先阻断，再让 B 改一页保存**，A 下一轮才会真去拉并超时。
   ⚠️ 顺带实测：数据面可能走 **UDP/QUIC**（只堵 TCP 8788 时拉取照样成功）；
      要造"完全不可达"必须按**远端 IP 全协议**封（`-Protocol Any -RemoteAddress <B_IP>`）。
   ⚠️ 本机防火墙三档默认是**关**的 ⇒ 规则不生效；测试期间需临时开当前档（Public），测完关回去。
   ⛔ **2026-11-26 实测：即使"先开 Public ＋ 全协议封 .190"，A 仍在阻断期间成功拉取过一次**
      （`fetched=3 applied=3 since=298 max_seq=314`）⇒ **防火墙封锁没能可靠地让拉取失败**；
      原因未定位（不是系统代理：`ProxyEnable=0`）。⇒ 下一次试**别的造超时手段**：
      · **手动地址黑洞**（未验证）：把该对端的手动地址改成不可路由 IP（如 `http://10.255.255.1:8788`）⇒ SYN 超时；
      · 或 B 侧**退出 app**（得到的是"连接被拒"，按单子原文**不算超时**，只记错误码）。
      ⚠️ 结论：**U3 的 60s 超时路径至今没有真机读数**，⛔ 不许写成"通过"或"跳过"。
```

### 60s 超时路径（目标 60→120→300→600，4 次后停）

```text
1) 先成功一轮，确认「上次成功」有值、`autoRetryStopped` 未显示。
2) 制造超时（优先 B）：
   ① B 退出 app（A 会先得到连接被拒，记录实际错误码，不算超时）；
   ② B 关 Wi-Fi（可能快速失败，记录错误码）；
   ③ A 用管理员 PowerShell 阻断到 B:8788（drop ⇒ 超时）：
      New-NetFirewallRule -DisplayName "U3-block-8788" -Direction Outbound -Action Block `
        -Protocol TCP -RemoteAddress <B_IP> -RemotePort 8788
3) 从 A 下一次后台轮失败开始计时；此后⛔ 不点「立即同步」/⛔ 不编辑页面，让自动重试自己跑。
4) 记录 A 日志 `[mesh] 后台一轮：开跑（…）` 相邻间隔；正常约 60s→120s→300s→600s；
   第 4 次失败后应出现「已停止自动重试」。
5) 面板出现 `data-testid="auto-retry-stopped"`：
   「自动重试已停止（连续 N 次网络类失败）—— 用上面的「立即同步」或「全部空间立即同步」手动重试。」
6) 恢复：`Remove-NetFirewallRule -DisplayName "U3-block-8788"`，点「立即同步」→ 成功、stopped 消失、streak 清零。
```

### 401 路径（目标：身份类零自动重试）

```text
1) 先成功一轮，记 A 当前设备名单。
2) 让 A 离线/退出 app。
3) B：同步面板 →「已配对设备」→ 对 A「撤销配对」→ 确认；记 B 的 toast。
4) A 重启联网，触发一次同步（面板或「立即同步」）。
5) 观察 A：应是 401/被移出 类，给一句话＋按钮（重试/体检/复制诊断/去配对）；
   ⛔ 不应出现 60s 加速重试；`autoRetryStopped` 不应为真。
6) 若 A 先收到 U2 反向通知（「没有配对秘密」）⇒ 如实记路径，⛔ 不算 401 通过。
```

### 记录什么

```text
· 时间线：首次失败 T0；自动开跑 T1..T4；停止时刻；恢复时刻；401 失败与按钮出现时刻
· 间隔：T1-T0、T2-T1…（同机日志/秒表；⛔ 跨机墙钟不相减）
· 读数：`autoRetryStopped`、`autoRetryStreak`、失败行原文、`sync_history` 最近几条、诊断包
· `next_retry` 目前**没有上屏字段**（前端类型只有 autoRetryStopped/Streak）；
  ⛔ 不编界面读数；以日志开跑间隔为准，需要精确值写“需现场确认”
```

### 判据

```text
✓ 60s 路径：首间隔约 55–75s；其后约 110–140s、280–330s、570–650s（同机日志）
✓ 第 4 次失败后停止；面板出现停止标记；手动「立即同步」能恢复
✓ 原因变化/成功 ⇒ streak 清零（撤故障后验证一次）
✓ 401：零自动重试；失败行给重新配对/邀请动作；⛔ 不出现 60s 加速
✗ 第 4 次后仍自动重试，或 401 触发加速 ⇒ 停，按缺陷处理
✗ 日志已停止但面板不显示停止标记 ⇒ 不算通过
✗ 为变绿去点手动同步/改系统时间 ⇒ 该次读数作废
```

### 止损、留证、回滚

```text
· 超过 10 分钟无第 1 次自动开跑 ⇒ 停；保留日志＋诊断包，记“未触发”。
· 任一次重试导致页面/附件变化 ⇒ 立即停，按数据事故留证。
· 401 若把 A 的卡删掉/变成没配对 ⇒ 记录实际路径；用「生成邀请→接入」重新配对恢复，
  ⛔ 不手改数据库、⛔ 不拿 U2 恢复动作冒充 401 判据。
· 回滚：删防火墙规则、B 回网/开 app、A 重新配对；⛔ 不删任何笔记/附件。
```
