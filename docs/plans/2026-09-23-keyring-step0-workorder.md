# 第 0 步施工单：**钥匙袋（keyring）**（2026-09-23）

> 上位：[加密作用域决策稿](2026-09-23-encryption-scope-decision.md) §3 的**第 0 步**；
> 前提口径：[数据可见边界](../sync-server-data-boundary.md) §0.5。
>
> 一句话：**把"每空间一把随机密钥"用主密钥包裹起来的那套格式先定死并落地** ——
> 它是"按空间"（第 1 步）和"换设备能解开"（0b）**共同的底座**，而且本步**不接线**，
> 存量行为一字不动。

## 1. 形状（三层）

```
口令 ──(Argon2id ＋ 公开的盐/参数)──▶ 主密钥（只在内存，不落盘）
                                        │  包裹 wrap
                   ┌────────────────────┼────────────────────┐
                   ▼                    ▼                    ▼
             📦空间A的盒子          📦空间B的盒子          📦空间C的盒子
              （A 的随机密钥）       （B 的随机密钥）       （C 的随机密钥）
```

**公开材料**（＝可以同步、可以放服务端的那一份）就是一整个 JSON：盐 ＋ KDF 参数 ＋ 每个空间一个盒子。
它**不含**口令、也**不含**裸密钥 ⇒ 看到它不等于能解开；但它是**离线爆破的目标**，
所以强度落在主口令 ＋ KDF 参数上（决策稿 §5.2）。

```jsonc
{
  "v": 1,                                  // 格式版本；不认识 ⇒ 报错，不猜
  "kdf": { "algo": "argon2id", "salt_hex": "…", "m_kib": 19456, "t": 2, "p": 1, "sm_iterations": null },
  "spaces": { "space-a": { "box_hex": "…" }, "space-b": { "box_hex": "…" } }
}
```

盒子里装的明文是 `u32(be) 空间id长度 ‖ 空间id ‖ 32 字节密钥` ⇒ **盒子与空间绑死**：
把"空间 B 的盒子"塞到"空间 A"的位置，解开时逐字节核对 ⇒ **当场报错**，而不是给出一把错钥匙。

## 2. 已落地（0a，2026-09-23）

| 件 | 位置 | 说明 |
|---|---|---|
| 模块 | `src-tauri/src/keyring.rs`（**`pub mod`，不接线**） | `Keyring` / `KdfParams` / `WrappedBox`：`new` / `to_json` / `from_json` / `wrap` / `unwrap_key` / `rotate` / `remove` ＋ `random_space_key()` |
| 随机数收口 | `crypto::random_32()` | 与 `random_salt()` 同一个 `OsRng` 入口 —— 不另开一条 CSPRNG 路径 |
| 加密复用 | `crypto::encrypt/decrypt(AppKeys)` | **不写第二份加密**：盒子与 wire 共用同一套 AEAD 与密文头（含国密构建 v2 路径），所以"本构建解不开"的话术也现成 |

**判据 5 条（全绿，`-Filter keyring`）**：

```
current_params_match_the_library_default
    ★ 记下的 Argon2id 参数必须**就是**库默认（否则"存参数"从第一天起就是错的；库默认哪天变它会红）
wrap_unwrap_roundtrip_and_the_public_half_leaks_no_key
    往返取回同一把；★ 公开材料里**不许**出现裸密钥或口令；盐必须在里面；同一份材料读回来仍可解
a_box_is_bound_to_its_space_and_a_wrong_master_or_tamper_is_loud
    换空间名 ⇒ 报错；错主密钥 ⇒ 报错；改一个字节 ⇒ 认证失败；袋里没这个空间 ⇒ 报错（不猜、不新建）
unknown_version_and_mismatched_kdf_params_are_refused_not_guessed
    v 不认识 ⇒ 报错；KDF 参数不一致 ⇒ **在派生之前**拒绝（否则会伪装成"口令错"）
rotation_touches_only_that_space
    ★ 轮换只动那一个空间（别的空间与盐都不动）—— 这正是"每空间随机密钥"换来的
```

⚠️ 一处**判据逼出来的设计约束**：`AppKeys` **故意没有** `Debug`（密钥材料不该能被打印进日志）⇒
判据里不能用 `unwrap_err()`，只能 `match`。写下来，免得下一个人为了好写给密钥加 `Debug`。

## 3. 还差两块（都在本"第 0 步"之内，但各自要单独一片）

### 0a-2：**参数驱动派生**

今天 `derive_master` 走 `crypto::derive_app_keys`（库默认参数），本步只做到"**参数不一致就报错**"。
真正按存下来的参数派生要动"全应用密钥派生"那条路：
- `Argon2::new(Params::new(m_kib, t, p, …))` ＋ SM 侧迭代数进参数；
- **判据**：① 用 `KdfParams::current()` 派生的字节与今天**逐字节相同**（等价性，保证不改行为）；
  ② 换一组参数 ⇒ 两把钥匙不同、且老袋子仍按**它自己记的**参数解开；
  ③ 解锁耗时读数（本机 ＋ 低端设备）—— 参数取值要据此定（决策稿 §7.2）。
- **为什么单独一片**：它改的是所有加密数据共同依赖的那条路，出错面是"整库打不开"。

### 0b：**把公开材料放到"第二台设备拿得到"的地方**（要动服务端仓）

今天公开材料只能**手工搬**（导出/导入这份 JSON）。要"输一次口令就自动拿到钥匙"，得让公开材料可同步：
- 服务端侧：一个"每用户/每空间一份公开材料"的存放与取回（**明文存是安全的**：它是密文）；
- 客户端侧：登录/解锁后拉一次，解出各空间密钥；
- **判据**：① 第二台设备只凭"口令 ＋ 公开材料"能解开（端到端实测）；② 公开材料被篡改 ⇒ 解不开且报错
  （不是静默给出错钥匙）；③ 服务端**读不到**任何密钥（它只有盒子）。
- ⚠️ 这一条要那个仓（`shuyonote-sync-server`）配合 ⇒ 排在第 1 步之后、与第 2 步并行都不阻塞。

## 4. 与第 1/2 步的接口（先说好，免得接线时各写各的）

1. **第 1 步（按空间）**：`encryption_enabled` 从"读 meta.db 一个标志"改成"按空间查"；
   `key_space_conn` 打开某个空间库时，用它**自己**的钥匙（从钥匙袋解出）—— 于是"锁 A 不影响 B"才有可能。
2. **第 2 步（闸门）**：绑定同步关系那一刻检查"这个空间（个人空间）在钥匙袋里有盒子吗"；
   没有 ⇒ **拦住**并引导设口令；团队空间**直接放行**（不查钥匙袋）。
3. **第 3 步（存量迁移）**：把已加密空间的钥匙搬进钥匙袋（一次性、幂等、失败有痕）。
4. 主密钥**永不落盘**；钥匙袋本体落哪、以及是否随公开材料同步，由 0b 定。

## 5. 本步**不做**的

- ❌ **不接线**：`encryption_enabled` / `key_space_conn` / `encrypt_payload` 一字不动（存量行为零变化）；
- ❌ 不做双读、不做存量迁移（那是第 3 步，且口径已允许"要求一起升"）；
- ❌ 不落盘主密钥、不在日志里打印任何密钥材料（`AppKeys` 没有 `Debug` 就是这条的落地）；
- ❌ 不自己实现加密/随机数（一律走 `crypto`）。
