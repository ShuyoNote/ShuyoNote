# 聚合邮箱（邮件即笔记）落地文档

> 状态：**规划，建议**。定位：本地优先的桌面生产力工具，把**多个邮箱账号聚合成一个收件箱**，并让邮件**一键转成笔记 / 任务**进入知识库——**capture-first**，而非一个与 Thunderbird/Outlook 竞争的全功能邮件客户端。
> 敏感/商业化部分（付费边界、OAuth 应用凭据、凭据保险库、服务端设想）见私有 `shuyonote-sync-server` 仓库 `docs/email-aggregate-monetization.md`。

## 1. 一句话定位

**邮件 = 知识库的输入管道。** 用户在 ShuyoNote 里聚合多个邮箱，阅读后不再"看完就扔"，而是**转成带属性的笔记 / 任务**，进入本地优先、可搜索、可反链、可加标签、可进数据库视图的知识体系。与现有「本地优先 + 自建同步 + E1 加密 + AI」的定位一脉相承。

## 2. 为什么做（痛点 / 价值）

- **碎片信息无法沉淀**：邮件里的决策、合同、发票、待办，读完即散，难以复用。
- **转任务断层**：邮箱里的"该办的事"要手动抄到笔记/Todo，且无上下文。
- **数据主权**：云邮箱聚合服务（第三方收信）违背"数据不出机器"；本地聚合更贴合定位。
- **AI 放大器**：已有 AI 薄 Agent，可自动总结长线程、提炼行动项、分类归档、草拟回复——邮件是最佳 AI 场景之一。
- **差异化**：Notion/Amplenote 是"email-in"，但缺少**多账号聚合 + 本地优先 + 任务化 + AI** 的组合。

## 3. 范围界定（做 / 不做）

**做：**
- 多账号 **IMAP 聚合**（统一收件流；账号可增删、独立凭据）。
- 统一阅读流（标题 / 发件人 / 时间 / 摘要），读信即浏览。
- **一键「存为笔记 / 存为任务 / 归档到某页」**（核心 capture 能力）。
- 附件进**内容寻址附件库**；邮件字段→**属性**（from / to / subject / date / labels）。
- 标签映射、**AI 总结/提炼行动项**（P1）。

**不做（明确边界，防范围失控）：**
- 不做一个功能对标的完整邮件客户端（线程树 / 文件夹深度管理 / 签名 / 加密邮件 / 发送编排）。
- 不做云同步邮件；邮件留在本机，离线可读。
- 不做批量导入历史的"邮箱迁移器"（首版做近期增量即可）。

## 4. 技术可行性（客户端侧）

| 能力 | 方式 | 备注 |
|---|---|---|
| 拉取 | Rust `imap` / `async-imap` + `mailparse` | 增量按 `UIDNEXT` / `UNSEEN`；`spawn_blocking` 不阻塞命令线程 |
| 邮件→笔记 | 邮件体 → Lexical 页 | 复用现有页生成；附件 → `write_attachment_bytes`（内容寻址） |
| 字段 | from / to / subject / date / labels → **属性** | 复用属性 / 数据库视图 |
| 转任务 | 建页 + 任务/截止属性 | 复用任务化样式 |
| AI | 总结 / 提炼行动项 | 复用现有薄 Agent + 语义检索 |
| 认证 | **IMAP 应用密码 / 企业 IMAP**（P0）；OAuth2（P2，见私有文档） | 先绕开 OAuth 门槛 |
| 存储 | 本地优先，复用 `meta.db` / `spaces/*.db` / `attachments` | 随 outbox/changes 同步；大附件需考虑体积 |

## 5. 里程碑

| 阶段 | 内容 | 交付物 |
|---|---|---|
| **P0（MVP）** | 账号配置（IMAP + 应用密码）→ 拉近期邮件 → 统一阅读流 →「存为笔记 / 存为任务」 | 一个能用的"收件箱 → 知识库"链路 |
| **P1** | 多账号聚合、AI 总结/行动项、标签映射、附件进库 | 有聚合与 AI 加成 |
| **P2（视情况）** | SMTP 回复、完整文件夹/线程同步、对邮件启用 E1 端到端加密 | 更完整，但边界风险上升 |

## 6. 验收清单（P0）

- [ ] 添加一个 IMAP 账号（应用密码，非 OAuth）成功，能列出收件箱。
- [ ] 拉取新增（按 `UNSEEN` / `UIDNEXT`）成功，不重复拉取。
- [ ] 阅读流按时间倒序展示（标题/发件人/时间）。
- [ ] **存为笔记**：邮件体生成页面，字段成属性，附件入库。
- [ ] **存为任务**：生成带截止日期的任务页。
- [ ] 断网可读已拉取的邮件（本地优先）。
- [ ] 凭据不明文落盘（依赖 E1 或系统凭据库，见私有文档）。
- [ ] 大附件 / 大邮箱不阻塞 UI（流式 + 后台）。

## 7. 风险与决策点

- **OAuth 门槛**：Gmail/Outlook 消费账号已禁基础认证，必须 OAuth2（注册 + 验证）。**P0 用应用密码/企业 IMAP 绕开**，把 OAuth 作为后续决策。
- **凭据安全**：`meta.db` 当前**明文**存凭据，**不可直接存邮箱密码/OAuth token**；须先做 E1 加密扩展或系统凭据库（见私有文档）。
- **性能/体积**：多账号大邮箱 → 磁盘/内存/搜索/首拉耗时；需流式 + 增量 + 上限。
- **范围失控**：随时提醒"这是知识库输入管道，不是邮件客户端"。
- **决策点 ①** 范围：收件箱+转笔记（轻，推荐） vs 完整收发客户端（重，慎）。
- **决策点 ②** 认证：应用密码/企业 IMAP（先） vs Gmail/Outlook OAuth（后，接受注册+验证成本）。

## 9. 边界与约束

- 与隐私红线一致：邮件默认本机；同步为**变更日志级**（en 若开则密文）。
- 商业组件：若邮件聚合进入团队版/自建（服务端聚合），属商业授权，**不在本公开仓库**——见私有 `docs/email-aggregate-monetization.md`。
- Web 版：浏览器无法连 IMAP，**邮箱功能为桌面专属**；Web 端显示"请用桌面版"挪到同步提示同一模式。
