# 「数据库 = 透镜」贯通方案

> 目标：把 ShuyoNote 的数据库从「手动集合 + 表格/看板」升级为**数据工作台**——数据库是「页面属性之上的可配置视角」，支持**查询型成员规则**（保存的查询）、**多套保存视图**、**ref 关联属性**（打通关系图/反链）与**公式/汇总**。遵循[设计哲学](../design-philosophy.md)「数据库是透镜，不是 schema」。

## 1. 背景与竞品对照

| 竞品 | 数据库能力 | 关键点 |
|------|-----------|--------|
| Notion | 数据库 = 手动集合 + 多视图 | 视图即配置，同一批数据多呈现 |
| Obsidian Dataview | 数据库 = 查询规则 | 「所有 page 且 property=X」的派生视图；数据在 frontmatter |
| 思源数据库 | 数据库块（表格/看板/画廊） | 块即行、属性即列、聚合 |
| ShuyoNote 现状 | 数据库页（kind='database'）+ 7 视图 + 汇总条 | 列/视图语义有了，但**缺查询型成员规则与多视图保存、ref 贯通、公式** |

**结论**：ShuyoNote 已有「属性定义共享 + 7 视图 + 汇总」，下一步让它「活」起来：**查询规则（自动收页）+ 保存视图 + ref 关联 + 公式**，从「表格」到「数据工作台」。

## 2. 现状盘点（代码已核实）

- `attr_defs`（共享属性定义）+ `page_props`（页面值）+ `database_columns`（库列）+ `query_database`（行查询）。
- 前端 `DatabaseView`：7 视图（表格/画廊/看板/列表/日历/时间轴/目录），列管理、单元格内联编辑、排序/过滤、`board_by_attr`。
- `M4` 聚合：select 按值计数、number 合计/均值（前端聚合）。
- 数据库页 `kind='database'`；数据库模板（M9.2b）可预设列。

## 3. 核心概念

- **数据库 = 透镜**：视图/成员规则透视「页面 + 属性」；数据只在页面。
- **两种成员**：
  - 手动集合（已有）：把页面加入数据库。
  - **查询规则**（新增）：如 `状态=进行中 且 标签=工作 且 kind=page` 自动收页（保存的查询/派生数据库）。
- **多套保存视图**：一个数据库可存多个 `{列, 排序, 过滤, 分组, 视图类型}` 配置，可切换/命名。
- **ref = 关联边**：`ref` 属性引用其他页面/块，既是数据库列，也是**关系图的一条边 + 反链**（打通数据库与图谱）。
- **公式 / 汇总**：计算列（`= 数量 × 单价`）、跨库 rollup、按分布聚合（已有 M4 前端聚合，公式为增量）。

## 4. 数据模型

```
-- 保存视图配置（一库多视图）
CREATE TABLE IF NOT EXISTS db_views (
  id          TEXT PRIMARY KEY,
  db_page_id  TEXT NOT NULL,
  name        TEXT NOT NULL,
  view_type   TEXT NOT NULL,           -- table|kanban|gallery|list|calendar|timeline|directory
  config      TEXT NOT NULL DEFAULT '{}',  -- {columns,sort,filter,group} JSON
  sort_order  REAL NOT NULL DEFAULT 0,
  created_at  INTEGER NOT NULL
);

-- 查询规则（成员规则，存数据库页）
-- 复用 database_columns.db_page_id 所在行的 config，或新增 rule_json 列
ALTER TABLE pages ADD COLUMN db_rule TEXT NOT NULL DEFAULT '{}';  -- 仅 kind='database' 使用
```

- `query_database` 扩展：接受 `rule`（过滤条件），在「手动加入 + 规则」两种成员间取并集/交集。
- ref 关联：`page_props` 的 `ref` 值已是 `p:<id>`/`b:<id>`；查询时解析为目标页面/块 + 可作为图查询输入。

## 5. 前端设计

### 5.1 查询型数据库
- 数据库页设置里可配「成员规则」（按属性/标签/kind 过滤），保存为 `db_rule`；列表 = 手动加入 ∪ 规则命中。
- 空状态区分「手动添加」与「按规则自动收页」。

### 5.2 多视图保存
- `DatabaseView` 顶部视图切换器 + 「＋ 保存视图」→ 命名并存为 `db_views`；可切换/重命名/删除视图。
- 每个视图独立 `{列/排序/过滤/分组}`。

### 5.3 ref 列交互
- `ref` 单元格：点开选择页面/块（复用 `BlockSelectorPlugin` + 页面搜索）；显示目标标题，点击跳转。
- ref 列在关系图/反链里呈现为一条边。

### 5.4 公式列
- 单元格公式（如 `金额 = 数量 × 单价`）、按行计算、前端即时算；跨库 `rollup` 用 `count/sum/avg`。
- 复用 M4 汇总条，扩展为可配置公式列。

## 6. 后端命令（新增/改造）

| 命令 | 说明 |
|------|------|
| `set_db_rule(db_page_id, rule_json)` | 保存成员规则 |
| `query_database` 改造 | 支持 rule（规则收页 + 手动成员的并集）；返回带 `ref` 解析的列 |
| `save_db_view(db_page_id, name, view_type, config)` / `list_db_views` / `delete_db_view` | 多视图保存 |
| `resolve_refs(page_id)` | 解析 ref 属性 → 目标页面/块信息（供 ref 列显示与图谱） |
| `compute_formula(db_page_id, formula)` | 计算列/汇总（或前端算，先前端） |

## 7. 实施顺序（里程碑）

- **M13.1（保存视图）**：`db_views` 表 + `save/list/delete_db_view` + 前端视图切换器与多配置保存。验收：一个数据库可存/切多套视图。
- **M13.2（查询型数据库）**：`db_rule` + `query_database` 支持规则 + 前端成员规则配置。验收：按规则自动收页的「派生数据库」。
- **M13.3（ref 贯通）**：ref 列选择 + 跳转 + 关系图/反链边。验收：ref 关联成为图边并可点击导航。
- **M13.4（公式，可选）**：计算列 + 汇总/rollup。

## 8. 测试与验收标准

- [ ] 一个数据库可保存/切换多套视图（各自独立的列/排序/过滤/分组）。
- [ ] 配置成员规则后，符合规则的页面被自动纳入数据库（派生数据库）。
- [ ] 手动加入与规则收集的页面在列表中并存/去重正确。
- [ ] ref 属性作为列显示目标标题、可点击跳转，并在关系图/反链中出现该关联边。
- [ ] 公式列按行计算正确；汇总条/统计正确。
- [ ] 属性/标签/数据库、关系图、反链语义一致（同一数据多处呈现不漂移）。
- [ ] 同步 / 版本历史不受影响（视图/规则随数据库页走）。

## 9. 风险与取舍

- **查询型数据库的成员语义**：要明确「手动 ∪ 规则」还是「规则为主」；建议「手动加入 + 可选规则交集」，避免自动收页把手动内容冲掉。
- **ref 贯通是重点也是难点**：ref 既要当列、又要当图边、又要可点击；先做「列显示 + 跳转」，再入图。
- **公式**：先做前端计算列（本地优先、离线快），跨库 rollup 后置；避免复杂公式引擎（V8 等）引入——用受限表达式即可。
- **别过度约束**：数据库仍是透镜，不把页面降级为行；保持「页面可随时当笔记编辑」。

## 10. 结论

「数据库 = 透镜」贯通（保存视图 / 查询规则 / ref 关联 / 公式）把 ShuyoNote 从「表格/看板」升级为**数据工作台**，且与关系图/反链打通。按 M13.1 → M13.4 收紧推进；配置取「手动 + 规则」混合，公式先前端。配套理念见[设计哲学](../design-philosophy.md)。
