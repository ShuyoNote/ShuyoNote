## 1. 一句话

**已配置好的一台设备**（A）点「生成邀请」，得到一段**有时效、一次性、可撤销**的邀请（二维码／链接／文件）；
**新设备**（B）用它**一次接入**：登记 A、让 A 登记 B、拿到「接线」所需的东西 ⇒ 之后两台正常同步。
⛔ 不改变现有「附近设备点一下信任」和「严格模式抄码」两条路。

## 2. 目标 / 非目标

**目标**
1. B 从「拿到邀请」到「可同步」**≤1 分钟**（人手只点两下：A 生成、B 接入）。
2. **未持有邀请的第三方无法加入**（邀请是凭证，不是"喊一声"）。
3. 邀请**可失效**：10 分钟到期、用一次即作废、发起方可在使用前撤销。
4. 复用现有件：载荷编解码、比对码、`decide_device_pair_import`、`remember_peer_card`——⛔ 不写第二套配对实现。

**非目标（本片不做）**
- ⛔ 跨网／中继路线的邀请（中继数据面仍不进正式包，另期）。
- ⛔ 自动加入（B 上必须**人点一次**「接入」）。
- ⛔ 邀请里带**页面内容**（需求 §4 FR-1 明写「不含页面内容」）。
- ⛔ 设备撤销／换机／密钥轮换（那是 U2；本片只提供"邀请可撤销"这一格）。

## 3. 线格式（草案，`InvitePayload`）

在现有 `DevicePairPayload` 上**加三格**（老码缺省 ⇒ 仍是"普通抄码"，行为不变）：

```text
v            : u32   = 2（老码 = 1；v=2 缺 exp/nonce/sig ⇒ 大声拒，不猜）
bind         : String  照旧（可抄的通配绑定写法）
addrs        : [String] 新增可选：发起方当前可达的 「IP:端口」（广播被 AP 过滤时 B 直接连；非秘密）
token        : String  照旧（⚠️ 1C 之后它不是凭证；真正放行靠公钥签名）
fp           : String  照旧
from_device_id : String 发起方设备号（照旧，必填）
to_device_id : String  新增可选：**指定给哪台**（R110 的既有语义；空＝谁先拿到谁用）
pubkey       : String  发起方 Ed25519 公钥（照旧，必填）
exp          : i64     新增：到期时刻（unix ms；**签发 + 10 分钟**）
nonce        : String  新增：128 bit 随机（十六进制 32 字符；⛔ 不是口令）
sig          : String  新增：发起方对「除 sig 外全部字段」的签名（Ed25519）
```

- 熵：`nonce` **128 bit**（≥ 需求 §13.10 ⑤ 的 80 bit）。
- 有效期：**10 分钟**；`to_device_id` 有值 ⇒ 只有那台能采纳（不是给它 ⇒ 大声拒）。
- `deny_unknown_fields` 照旧：多一个字段 ⇒ 拒收（不静默忽略）。
- ⛔ 邀请**里不含**：页面内容、空间钥匙、主口令、任何能直接解开加密空间的东西。

## 4. 流程

```text
A（已配置设备）：
  ① 人点「生成邀请」（⛔ 不许后台自动生成）
  ② 屏幕显示：链接/二维码/文件 ＋ 「10 分钟内有效，只能用一次」＋ 绑定信息（哪台、哪个空间）
  ③ 邀请落**发起方台账**（未用/已用/已撤销）—— 撤销就是把台账那行标掉
B（新设备）：
  ① 打开链接 / 扫码 / 选文件 / 粘贴
  ② 复述给对方看：「来自 <设备名＋短标识>，绑定 <空间名>，有效至 HH:MM」—— 人确认这一步在 B 上
  ③ 点「接入」⇒ 连上 A（先试发现层公告；不行就用邀请里的 addrs）
  ④ A 校验：nonce 未用过、未过期、未撤销、签名对、to_device_id 匹配（若指定）
  ⑤ 双向登记：B 登记 A 的卡 ＋ 本机要出示的那份；A 登记 B（复用 remember_peer_card）
  ⑥ 台账把 nonce 标「已用」；B 显示「已接入」；失败一律**大声拒**并给原因
```

⚠️ 加密空间：邀请只解决「接线」；**主口令仍由人在 B 上输入一次**（现有口径不变）。
邀请里是否要顺带带 `PairingPayload.material`（省掉第二次搬钥匙）⇒ 见 §7 待拍 ①。

## 5. 安全模型（威胁 → 补偿）

| 威胁 | 补偿 |
|---|---|
| 邀请被同网段的人看到/截获 | 10 分钟 + 一次 + 可撤销；不含密钥材料（若拍 ①=A） |
| 重放旧邀请 | nonce 台账：用一次即作废；过期拒 |
| 伪造邀请（说自己是谁） | `sig` = 发起方 Ed25519 签名；B 与发现层拿到的 pubkey 交叉核对 |
| 未持有邀请者硬连窗口 | A 的窗口只放行「持有有效邀请且公钥匹配」的连接；其余大声拒 |
| B 冒领别人的邀请 | `to_device_id` 指定时严格比对；不匹配大声拒 |
| 邀请里泄漏密钥材料（若拍 ①=B） | 只能靠熵 + TTL；⚠️ 拿到的人可**离线猜主口令** ⇒ 这是 ① 的取舍本体 |
| 被信任设备被冒充 | 沿用 2026-10-11「一键信任」的兜底：信任前摆身份 + 逐台可撤回（本片不削弱） |

## 6. 判据（每条都要能**看它红**）

1. **熵**：nonce 长度 < 32 hex ⇒ 拒（变异：把生成改短 ⇒ 必须红）。
2. **过期**：`now > exp` ⇒ 拒（变异：去掉 exp 校验 ⇒ 必须红）。
3. **重放**：同一 nonce 第二次 ⇒ 拒（变异：不查台账 ⇒ 必须红）。
4. **撤销**：台账标撤销后 ⇒ 拒。
5. **to_device_id**：指定给别人 ⇒ 拒且不写任何字节。
6. **签名**：改一个字节 ⇒ 拒（沿用 `check_code` 的"整份载荷"口径）。
7. **回归**：老 `DevicePairPayload`（v1）路径逐字节行为不变（现有判据照旧绿）。
8. **不变量**：`INV-NS-pairing-code-length-kept`（比对码 60 bit 下限）**不许缩短**；若拍 ②=A（免人工核对），必须**显式改** `check-pairing-requires-proof` 并记录理由，⛔ 不许静默放开。

## 7. 已拍板（owner 2026-11-12）

- **① ✅ A｜邀请里不带「搬钥匙」材料**：邀请只负责把设备接上；加密空间的主口令仍由人在新设备上输一次。
  ⇒ 线格式**没有** `material` 字段（§3 不变）。
- **② ✅ A｜默认免人工核对**：邀请的高熵（128 bit）＋ 10 分钟 ＋ 一次 ＋ 可撤销就是凭证。
