## 1. 一句话结论

```text
**四者不是四个功能，是一件事的两面**：Ontology 是骨架、RAG 是访问、LLM Wiki 是给人看的产出，
而 MCP 是**把这三样交给外部 Agent 用的那扇门** ✓
⇒ 于是"本体"同时成了 App 的内部结构**和**对外的接口契约 ⇒ 一切取舍都从这条长出来 ✓
```

## 2. 三层 ＋ 两种空间（一张图）

```text
        Ontology（骨架／契约：能力 25 条 · 空间 · 主体 · 证据）
              │  提供"切分与过滤口径" ＋ 生成物骨架
              ▼
        RAG（访问：本机检索 · 块级 · 权限 · 审计）
              │  提供"可引用的证据"（每条带 file:line／回链）
              ▼
        LLM Wiki（产出：主题页／知识地图／复盘页）
              │  页面写明"由哪些源生成 ＋ 时间 ＋ 模型"；**源一改就标脏**；页脚"派生，非出处"

  ┌───────────── 两种空间（同一版代码、运行期策略）─────────────┐
  │ 个人空间：**一分内容不出本机**（含索引与向量）✓            │
  │ 团队空间：按 `docs/sync-server-data-boundary.md` 已声明口径 ✓│
  └───────────────────────────────────────────────────────────┘

        ⛔ 真源永远只有两个：**用户的笔记** ＋ **仓里的文件**（三层皆派生物 ✓）
```

## 3. 为什么这么切（三条判据，都可核）

1. **"两种空间"而不是"两个版本"**：口径**已写在仓里**（`docs/sync-server-data-boundary.md:33/39/48` ✓）；
   版本分叉＝发行期分叉，会造"两份真相源"（本仓与本工作区都栽过 ✗）；空间是**运行期策略**、可回退 ✓
2. **"本体只有一份源"**：注册表 25 条是唯一出处 ✓；本体表、工具清单、知识地图**都是生成物** ✗
3. **"一律先立判据"**：规格层准入要求"每条不变式挂一条会红的判据" ✓ ⇒ 本方案的第一批工作**不写产品代码**，
   只写**判据**（承重渠道＝本机 Node ✓）

### 4·1 ⭐ 一物三用（本方案最省事的一点）

```text
产品仓自己写着：规格层下一步是「**生成器 ＋ 等值门禁**」（`docs/specs/README.md` ✓）
⇒ 同一个生成器有三个消费者：**① MCP 工具清单 ② 本体表 ③ 知识地图**
⇒ 一次生成、三处消费 ⇒ **从根上消灭"第二份能力清单"** ✗（这正是本仓"门禁清单唯一出处"的同一条课 ✓）
```

## 5. 不做什么（明确排除）

| 不做 | 为什么 |
|---|---|
| ❌ 个人空间的内容或向量出网 | 端到端加密（服务端只落密文）✓ |
| ❌ 第二份能力清单／第二套过滤语义 | 会漂移且不报错 ✓ |
| ❌ 两个版本分叉 | 见 §3 第 1 条 ✓ |
| ❌ 先写用户向文档 | 文档先于功能是本仓踩过的坑 ✓ |
| ❌ 把索引／wiki 当真相源 | 三者皆派生物 ✓ |
| ❌ 在 MCP 那份文档里重写知识层（或反之） | 两份正文＝两份真相源；只写**指针** ✓ |

## 6. 度量（怎么知道它有用 —— 数字以命令为准，不写死 ✗）

```text
检索：**召回率**（造一批"已知答案在库里"的问题）＋ **p95 延迟** ＋ **误报率**
成本：**同一个问题达到达标召回所需的工具调用次数 ≤ N**（N 由首轮实测定 ✓）—— 这直接等于 token 钱 ✓
个人侧：**断网可用** ✓ ／ 常驻内存 ／ 首启下载体积（**今天无读数** ✗，手机端尤要量）
派生物：**删索引后功能不降级** ✓ ／ **重建后同查询同结果集** ✓
生成物：**回链可达率** ／ **标脏延迟**（源改了多久页面变脏 ✓）
```

## 7. 分期（与施工单一一对应；每期都有出口判据）
