# 「工作空间增删改」补全实现方案

> 目标：把 ShuyoNote 的**多工作空间**从「已可用」补全为「完整、可控、可恢复」的隔离容器——空间的**增、删、改**围绕「隔离独立性 + 可恢复性 + 不跨空间泄漏」展开。遵循[设计哲学](design-philosophy.md)「空间是隔离容器，不是文件夹」与 [多空间方案](plans/2026-08-22-multi-workspace-plan.md) 的 M10 红色边界。

## 1. 背景与竞品对照

| 竞品 | 空间/工作区管理 | 关键点 |
|------|----------------|--------|
| Notion | Workspace 增删/切换/权限 | 完全隔离，切换器，各自页面树/权限 |
| Obsidian | Vault 新建/切换 | 一个文件夹一个 vault，互不关联 |
| 思源笔记 | 文档库/子文档库 | 顶层容器，独立文档树 |
| ShuyoNote 现状 | 多空间**基础已可用** | 缺「**增**（种子首页）/ **改**（按 id 重命名 / 空间级设置）/ **删**（物理清理、导出提醒）」的完整闭环 |

## 2. 现状盘点（代码已核实）

| 操作 | 现状 | 缺口 |
|------|------|------|
| 增 `create_workspace` | 插入 + 设为活动空间 | **未 seed 默认首页/欢迎页** |
| 删 `delete_workspace` | 软删（`workspaces.deleted_at`）+ 二次确认 + 活动空间回退（已实现） | 无「删除前导出提醒」；物理清理归 M14，不在正常删除 |
| 改 `rename_workspace` | **只重命名活动空间**（按 active，无 id 入参） | **无法改指定空间**；`WorkspaceMeta` 仅暴露 id/name/created_at/updated_at |
| 空间级设置 | `workspaces` 表已加 `icon`/`sort_order`/`theme`/`settings`/`deleted_at` | 字段存在但**未在模型/UI 暴露**（无图标/主题/排序） |
| 列表/切换 | 完整 | 良好 |

## 3. 核心概念：增删改的三层语义

- **增**：创建即成为活动空间 + **每空间默认首页**；独立页面树根、空标签/回收站/关系图、独立同步命名空间、独立 E2EE 密钥；**不继承其他空间内容**。
- **删**：**墓碑软删 + 导出提醒 + 二次确认**；删除活动空间自动回退最早未删空间（已实现）；**物理清理归「空间清理」**（`purge_deleted_workspace`，M14）。空间块图/反链留在空间内 → 删除不产生跨空间悬空。
- **改**：重命名**按 id 指定**；空间级设置（图标 / 排序 / 主题）——表字段已就绪，需在模型与 UI 暴露（每空间主题为 Phase 3 可选）。

## 4. 数据模型

`workspaces` 表现有列：`id, name, created_at, updated_at` + 已迁移追加 `icon, sort_order, theme, settings, deleted_at`。

- 扩展 `WorkspaceMeta` → 增加 `icon` / `sort_order` / `theme`（`Option<String>`，默认空 = 跟随应用）。
- 每空间设置（名称/图标/主题/排序）作用于**指定空间**；应用级主题仍默认，空间主题为可选覆盖。

## 5. 后端命令

```rust
create_workspace(name?) -> WorkspaceMeta   // 改造：种子默认首页（kind='page' 根页）
rename_workspace(id, name)                 // 改造：按 id 重命名（替代仅活动空间）
set_workspace_settings(id, { icon?, theme?, sort_order? })
list_workspaces() -> [WorkspaceMeta]        // 更新：含 icon/sort_order/theme
delete_workspace(id)                        // 保留软删；前端删除前提示「先导出/备份」
```

> 物理清理（`purge_deleted_workspace`）归入 **M14 空间清理**，不混入普通删除。

## 6. 前端设计

- **空间切换器**：空间项显示图标（`icon`）+ 名称 + 排序；「新建空间」后自动进入新空间（含首页）。
- **空间菜单**：悬停/右键 → 重命名（改名）、编辑图标/主题、删除（二次确认 + 导出提醒）。
- **新建默认首页**：建空间后 `create_page` 一棵根页（如「我的空间」/欢迎页），保证新空间不是纯空白。
- **删除前导出提醒**：在确认对话框里提示「建议先导出备份再删除」。

## 7. 实施顺序（里程碑）

- **M10.2b 空间增删改补全**：`create_workspace` 种子默认首页；`rename_workspace(id, name)` 按 id 重命名；删除前导出提醒。
- **M10.3b 空间级设置落地**：`WorkspaceMeta` 增 `icon/sort_order/theme`；侧栏空间项显示图标 + 排序；`set_workspace_settings`；每空间主题（可选覆盖）。
- **M14 空间清理联动**：`purge_deleted_workspace` 物理删除软删空间及其页树/引用；与「清空回收站 / 清理孤立附件」同属存储管理。

## 8. 测试与验收标准

- [ ] 新建空间后自动进入，且**有默认首页**（不再是纯空白）；其他空间内容不受影响（隔离）。
- [ ] `rename_workspace(id, name)` 能改指定空间名（含非活动空间），旧重命名行为回归兼容。
- [ ] 空间项显示图标/排序；`set_workspace_settings` 持久化并在切换器反映。
- [ ] 删除前提示「建议先导出/备份」，二次确认后才软删；删除活动空间自动回退。
- [ ] 物理清理仅经「空间清理」入口触发（不混入普通删除），且确认零悬空。
- [ ] 同步/加密：增删空间不影响其他空间同步线与各自 E2EE 密钥。

## 9. 风险与取舍

- **rename 兼容**：把 `rename_workspace` 改为按 id，需保留按 active 的调用或同步迁移前端调用点，避免破坏现「重命名当前空间」。
- **种子首页**：新空间首页是可恢复的普通页面，非硬编码；别让「建空间」变得重。
- **软删与物理清理分离**：普通删除保持软删可恢复；物理清理放「空间清理」，避免误伤。
- **每空间主题**：MVP 先应用级，空间主题做可选覆盖（Phase 3），避免扩大状态面。
- **别退化成文件夹**：空间是顶层隔离容器，不引入「空间内再分层」冗余。

## 10. 结论

「工作空间增删改」把多空间从「能建/能切」补全为「**完整闭环**」：建则种首页、删则软删+提醒、改则按 id + 空间级设置；物理清理归「空间清理」。按 M10.2b → M10.3b 收紧推进，红色边界（块图空间内、别退化成文件夹、可恢复性优先）不变。配套设计理念见[设计哲学](design-philosophy.md)。
