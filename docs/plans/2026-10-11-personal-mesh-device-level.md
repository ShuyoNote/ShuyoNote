## 9. ⭐ 订正（2026-10-11 实测之后 ✗ —— ⭐ 本节覆盖 §2／§3 的形状 ✓）

### 9.1 ⭐ 设备级的键**不是** `'ws-personal'` ✗，⭐ 而是"⭐ 空 `space_id` 那一格 ✗"✓

```
⭐ 实测 ✗：⭐ `'ws-personal'` 只在夹具里（⭐ 生产零命中 ✓）⇒ ⭐ 拿它当键就要**造一个假工作区** ✗，
   ⭐ 而 `ensure_local_profile_row` 明写着"⭐ 已删的工作区不许建档案 ✗"（⭐ `sync.rs:4408` ✓）⇒ ⭐ 那条路是歪的 ✓
⭐ ⭐ 正解 ✗：⭐ "⭐ 个人空间 ✗"本身在生产里就是按 ⭐ **`space_id` 为空** ✗ 认的（⭐ `sync.rs:909/1071/1093/2108` ✓）
   ⇒ ⭐ 设备级 ＝ ⭐ ⭐ **一律读写"⭐ 空 `space_id` ✗"那一格** ✗ ✓ —— ⭐ 键不用新造 ✓，⭐ 语义自然对上 ✓
⭐ 即 ✗：⭐ `read_setting(c, "mesh_bind", "")` ／ ⭐ `write_setting(…, "")` ✗ ✓（⭐ 原来传的是各空间的 `space_id` ✓）
```

### 9.2 ⭐ `mesh_room` 要**搬进 KV** ✗（⭐ 而不是留在 `sync_profiles` 里 ✗）

```
⚠️ ⭐ 它现在住在 `sync_profiles.mesh_room` ✗（⭐ 键 `ws_id` ✓）⇒ ⭐ 三个选择 ✓：
   ⭐ 甲 ⭐ 留在原地 ＋ ⭐ 用一个"⭐ 真的存在的 `ws_id` ✗" ⇒ ⚠️ 要求那个工作区真在 `meta.workspaces` ✓，
     ⭐ 而"⭐ 个人空间 ✗"**不一定有**一个固定 id ✗ ⇒ ⭐ 还得先造一个 ＝ ⭐ 又一份真相源 ✓
   ⭐ 乙 ⭐ ⭐ **搬进同一张 KV ✗**（⭐ 键同 `mesh_bind` 的形状 ✓，⭐ 空间一格留空 ✓）⇒ ⭐ **推荐** ✓
     ＋ ⭐ 理由：⭐ 三格从此**同一个存储、⭐ 同一个键形状** ✗ ⇒ ⭐ "⭐ 设备级 ✗"只是**一处口径** ✓，
       ⛔ 不是三处特例 ✓；⭐ 而且**不用碰 `meta.workspaces`** ✓
   ⭐ 丙 ⭐ 新开一张"⭐ 设备级设置 ✗"表 ⇒ ⚠️ 为一个键开一张表 ✓，⭐ 不划算 ✓
⭐ 迁移 ✗：⭐ 读旧的 `sync_profiles.mesh_room`（⭐ 各个人空间那几行 ✓）⇒ ⭐ 取**第一个非空** ✗
   （⭐ 定序：⭐ 按 `ws_id` 排 ✓ ⇒ ⭐ 结果确定 ✓）＋ ⭐ **记一行日志说出取了谁** ✗ ＋ ⭐ ⛔ 旧列不删 ✓（⭐ 可回退 ✓）
   ⚠️ ⭐ 因为**没有时间戳** ✗（⭐ §8 ① ✓），⭐ "⭐ 取最近改过的 ✗"做不到 ⇒ ⭐ 只能"⭐ 取第一个非空 ＋ ⭐ 说明白 ✗"✓
```

### 9.3 ⭐ 对端表那一条 ⚠️（⭐ 这轮**没量**✗，⭐ 别当已定 ✓）

```
⚠️ ⭐ `mesh_paired_devices` 是按 `space_id` 存的 ✗（⭐ `mesh.rs:815` ✓）⇒ ⭐ 设备级是否**连它一起升** ✗
   ⭐ 是**产品口径**问题 ✓：⭐ "⭐ 这台设备认过谁 ✗" 听着像设备级 ✓，⭐ 但"⭐ 某个空间只认某几台 ✗"也可能是需求 ✓
   ⇒ ⭐ ⛔ 本方案**不动它** ✓，⭐ 先把 `mesh_bind`／`mesh_token`／`mesh_room` 三格做对 ✓（⭐ 一次只变一件事 ✓）
```
