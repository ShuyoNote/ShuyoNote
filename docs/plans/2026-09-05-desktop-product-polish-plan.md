# 桌面端产品打磨计划（2026-09）

> 依据 [产品评价](../product-review.md) 的结论——**桌面是主线**，现阶段重点打磨桌面端产品。
> 四根柱子：**① 同步地基（先稳）→ ② 数据安全 → ③ 桌面体验打磨 → ④ 交付/产品化**。
> 原则：**先让「同步可信」与「数据不丢」，再谈界面与性能**；避免在沙子地基上堆功能。

## 目标（一句话）

把桌面端从「功能极强的本地笔记」打磨为「**可信、顺手、可交付**的本地优先生产力工具」——用户写完不怕同步丢、大工作区不卡、重要操作有兜底、遇到问题能自查。

---

## ① 同步地基（最高优先，必须先稳）

> 现状：功能在，但一致性边界没堵严（历史一堆 400/413/重传/丢变更）。

### 1.1 一致性整改（数据不失）
| 项 | 现状 | 要做 | 验收 |
|---|---|---|---|
| `device_seq` | 早期全 0 被合并 | 确认每设备自增唯一 seq；写入路径强制 | 跨设备不丢变更 |
| 附件哈希 | FNV(16) 与 SHA-256(64) 混用 | 一次性迁移 + 上传自愈（已做 web；桌面核对） | 老附件能同步 |
| `.part` 临时文件 | 曾误当附件上传 → 400 | 已排除；补「下载中断自动重下」 | 大附件中断可恢复 |
| 增量指针 | `last_pushed/pulled_seq` | 确保用完即推进、失败不回退过多 | 不反复全量 |
| 幂等 | push 服务端去重 | 服务端 UNIQUE(space,device,seq) 校验 | 并发不重复 |

### 1.2 回归测试（防回归）
- **跨设备回归脚本**：脚本化「建空间→双端互改→同步→断言两端一致」；纳入 `scripts/` 与 CI。
- **已知问题清单**：把 400/413/重传/哈希不符的**复现 + 判定 + 排查**写进 `docs/SYNC-logbook.md`（或部署手册）。
- 每次 UI/同步改动跑一遍。

### 1.3 自托管文档（让用户能自己排）
- 一页 `docs/SYNC.md`：2TB 上限、`--max-body-mb`、增量/去重、常见错误码（400 哈希/413 体积/401 会话）、`/sync/health` 自检、nginx 同源代理、常见「同步不动」排查（大小/内存/CORS）。

> **价值**：同步稳了，桌面才「敢让用户长期用」；否则主数据源存疑。

## ② 数据安全（兜底不丢）

> 本地优先的关键是「本地永不丢」。

### 2.1 备份与恢复
- 一键「整库备份」到用户选定路径（复制 meta + spaces + attachments，或压缩包）。
- 「恢复」入口 + 校验（导入前预览/校验完整性）。
- 自动备份频率提示（如每 N 天提醒 + `backup-dir`）。

### 2.2 回收站兜底（已建）
- 复用现有回收站（清空/恢复全部/分组/删除时间/角标）；补**主动**清理提示。

### 2.3 导出
- 整工作空间导出（HTML/Markdown/JSON）+ 附件；确认「跨工具可读」。

---

## ③ 桌面体验打磨（用户观感）

> 现状：历史遗留 z-index/弹窗/图标不统一，观感「差一点」。

### 3.1 层级与弹窗统一（已部分做）
- 把 z-index 全部收敛到 `:root` 的 `--z-*` 规范（`content/bar/content-overlay/popover/modal/context/palette/toast`）；
- 弹窗/右键菜单/浮层统一圆角、阴影、动效、图标对齐。

### 3.2 编辑器 / 数据库 / 文件管理 UI 打磨
- 编辑器：选中/拖拽/空行标题/光标/撤销联动的反馈。
- 数据库：视图切换、表格列宽/排序、空态/加载/错误态（已整理工具栏）。
- 文件管理：网格/列表、拖拽上传、预览、右键菜单（已做 SVG+改名+删除）。

### 3.3 空 / 加载 / 错误 / 边界态
- 每个视图的**空态**（无内容引导）、**加载态**（骨架/进度）、**错误态**（可重试）、**边界**（超大/超多）。
- 命令面板 + 快捷键面板（P0 已有，串起来）。

### 3.4 主题与外观
- 明/暗/自动 + 字体/密度一致性；随系统切换无障碍。

---

## ④ 交付 / 产品化（让用户「敢装敢更」）

### 4.1 自动升级（桌面重点）
- `tauri-plugin-updater`：`check()` + 用户点「下载并安装」（**绝不静默重启**）；签名 + `latest.json` + 稳定 HTTPS 端点。

### 4.2 关于 / 许可证 / 免费出口
- 「关于」对话框（版本/AGPL-3.0/四干净链接/隐私开关，已实装）；确认外部静态站出口。

### 4.3 更新节奏
- 收拢频繁版本号；`CHANGELOG` 简明；发布前跑 `smoke-web.mjs` + `cargo test` + 桌面自检。

---

## 优先级 & 节奏

| 阶段 | 内容 | 建议顺序 |
|---|---|---|
| **P0（先做）** | ① 同步一致性整改 + 回归脚本 + 自托管 SYNC 文档 | 1（地基） |
| **P1** | ② 备份/恢复 + 回收站兜底 + 整空间导出 | 2（不丢） |
| **P2** | ③ 层级/弹窗统一 + 空/加载/错误态 + 编辑器/数据库打磨 | 3（观感） |
| **P3** | ④ 自动升级 + 关于/许可证 + 发布节奏收紧 | 4（交付） |

> P0 最重要且回报最大（决定「信任」）；P2 是「耐看」；P3 是「敢发」。

## 如果只做三件事（最小可交付）
1. **同步一致性 + 回归脚本**（地基）。
2. **一键备份/恢复**（不丢）。
3. **自动升级**（敢装敢更）。

> 这三件做完，桌面端就从「能用」到「可信、敢长期用」。
