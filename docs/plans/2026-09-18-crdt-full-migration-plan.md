## 1. 认真评估 CRDT（结论先行）

**CRDT 能/不能：**

| | CRDT 能给 | CRDT 给不了 |
|---|---|---|
| 丢更新 | ✅ 不丢（可交换/结合/幂等），**不需要服务端权威序** | — |
| 同页不同块并发 | ✅ 确定性合并，各自保留 | — |
| **同词/同行两端改** | — | ❌ 仍可能**交错/重复**，用户仍看成乱码 |
| 删除 vs 正在编辑 | 因果语义确定 | ❌ **"A 删了 B 正在编辑的段"**：技术上可合并，**产品上仍需提示** |
| 离线 | ✅ 天然支持 | — |

⇒ **"上了 CRDT 就没有冲突"是误解**：它消灭的是**丢更新**，不是**用户感知的冲突**。
⇒ **冲突提示那一层，无论用不用 CRDT 都必须做**——这也是为什么阶段 1（A）不是白做。

**与 E2EE 的关系（纠正一处常见误判）**：**E2EE 不阻止 CRDT**。
CRDT 不需要服务端理解内容——每个 update 只是**不透明字节**，服务端只做存储/转发/定序。
真正难的是两处：① **压缩/GC**：服务端看不懂 ⇒ **无法替你压缩 update 链**，只能靠客户端定期产出**加密快照**
（**这条直接依赖尚未完成的 P0 密文版本化**）；② **awareness/光标**：加密后转发仍会泄漏时序与体积等元数据。

## 2. 三条路线与"为什么目标是 C 而不是止步于 A"

| 路线 | 覆盖的真实冲突 | 成本 | 风险 |
|---|---|---|---|
| **A. 块级 LWW ＋ 冲突提示** | 同页**改不同块**全保留；同块改 → 保留一方 ＋ 提示可取回 | 低（不改持久化/协议/E2EE） | 低 |
| **B. 部分 CRDT**：正文用 Yjs，元数据/库视图仍 LWW | 正文不丢 | 中高：动持久化/协议/派生索引/版本历史；**两套语义并存**是最易出诡异 bug 的地方 | 中 |
| **C. 全量 CRDT**：正文 ＋ 属性 ＋ 库视图 ＋ 空间结构 | 最彻底 | 高：**七处改动面全动**，且要动闭源服务端与插件契约 | 高（跨层重构 × 加密边界 × 插件契约同时变） |

**已定：目标 = C。** A 不作终点，它是**阶段 1 的过渡**，且其成果（**冲突提示 UI ＋ 块级比较基础**）
在 C 时代**仍然需要**（见 §1 最后一行）⇒ 不会白做。

## 3. 阶段计划（冲刺节奏）

### 阶段 0 · 准备（**立刻做，成本最低，不得跳过**）

1. ✅ **口径**（已完成）：`README.md` 明说"多设备一致 ≠ 实时协作"；
2. **接口收口**（本阶段最重要的一件）：把「**文档内容的读取 / 写入 / 合并**」收口到**一层**
   （例如 `src/lib/docContent.ts` 前端一层 ＋ Rust 侧对应一层），让 C 的替换面从"全仓"缩到"一层"。
   **不做这件事，C 会变成无法收尾的重构。**
3. **CRDT spike（1–2 天，消灭最大未知）**，只回答三个问题：
   - `content_json`（Lexical JSON）**⇄** `ydoc` 双向转换是否可靠；
   - 在 ydoc 下，**导出 / Markdown 往返 / 备份 zip / 每页版本历史**是否仍等价；
   - **E2EE 下的 update 加密 ＋ 加密快照**格式（**顺手把 P0 密文版本化定了**）。
   **交付一句话**：`CRDT spike: 转换=ok|fail / 往返等价=ok|fail / 加密快照=可行|不可行`。

### 阶段 1 · A：块级 LWW ＋ 冲突提示（**过渡，但立刻有用**）
判据（按 `blockId` 逐块比 `seq`）／冲突方**不许静默丢**（落版本历史 ＋ 块上可点提示）／
合并发生在**本地明文**、落库与上行前再加密／派生索引**继续不参与同步**／验收：两端改**不同块**（都保留）、
**同一块**（保留一方 ＋ 可取回）、离线各改再合并。

### 阶段 2 · B：正文 Yjs（元数据仍 LWW）
正文切到 ydoc ＋ update 传输；元数据/库视图保持 LWW。**本阶段的目的是把风险摊开**：
先只让最活跃的部分（正文）不丢，边界处的两套语义**显式写进文档并加断言**。

### 阶段 3 · C：全量
正文＋属性＋库视图＋空间结构全 CRDT；服务端存 **opaque update ＋ 加密快照**；插件契约重定义；
版本历史与 CRDT origin **合成一套**（否则回滚语义打架）。

## 4. 七处改动面（评估结论，按"要改哪些已落地的路径"）

| # | 路径 | 现在 | C 要动什么 | 最贵的三处 |
|---|---|---|---|---|
| 1 | 编辑器持久化 | 一页 = 一份 Lexical JSON | ydoc 二进制 update（`@lexical/yjs`）＋ 双向转换 ＋ 迁移；导出/Markdown/备份从合并后状态重建 | |
| 2 | 同步协议 | outbox ＋ `changes` ＋ 服务端 `seq` 权威序 ＋ 页级 LWW ＋ 墓碑 | 权威序不再需要；日志/墓碑/删除语义重设；**服务端也要改** | |
| 3 | 派生索引 | 可重建、**不参与同步** | 合并后**重新派生**（`content_text` 现在是写入时产出）⇒ 搜索/反链/关系图复核 | |
| 4 | 版本历史 | 每页 50 份快照 | 快照取合并后状态；与 CRDT origin/undo 合成 | |
| 5 | **E2EE / 密钥** | 每空间独立密钥，服务端只见密文 | 逐 update 加密 ＋ **加密快照** ＋ 版本化（**依赖 P0**）＋ 密钥轮换时旧 update | ⚠️ 最贵 |
| 6 | **插件与 AI 读写面** | 按能力读写库行（`page`/`kv.own`/`space_locked`） | "保存边界"消失 ⇒ **能力语义要重定义**（`page.append` 与并发编辑怎么算）——**契约改动** | ⚠️ 最贵 |
| 7 | **测试与门禁** | 31 条门禁/8 组；**Windows 跑不了 `cargo test`** | 加**收敛性测试**（随机乱序 op、多端断言收敛），主要在 Rust 侧 ⇒ 验证压在 AMD/Mac | ⚠️ 最贵 |

---

## 5. 不变量（冲刺中不许破）

1. **不把明文交给服务端**：合并只在本地解密后进行；
2. **派生索引仍可重建、不参与同步**（现有纪律，别扩大冲突面）；
3. **冲突不许静默丢**：任何覆盖路径都要留痕（版本历史 ＋ 提示）；
4. **每个阶段都能回滚**：A/B/C 逐段可停、可退（不许"全换完才第一次能跑"）；
5. **验证纪律**：Windows 跑不了 `cargo test` ⇒ 交叉验证**必须写明被验 commit**（`development.md` §10.5）。

## 6. 触发与退出条件

- **必须推进到 C 的触发**：出现**真实的**"同页同块同时编辑"投诉；或**团队版开始承诺实时协作**；
- **可以停在中途**：spike 证明"加密快照 ＋ update 链"成本不可控 ⇒ 停在 A/B，并把结论写回本文件；
- **任何时候都不做**：把明文上行、或为 CRDT 牺牲"派生索引可重建"这条纪律。
