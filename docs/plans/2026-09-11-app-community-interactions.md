# ShuyoNote × 数友社区：互动方案（优先级 + 分阶段）

> 2026-09-11 · **状态：方案，未实施** · 本轮只有这份文档，没有代码改动。

---

## 一、先定一条底线

**数据主权：任何"自动上传"默认关闭；上传前必须给出清单，并由人手动确认。**

诊断包、笔记片段、插件包、草稿——一律如此。这个产品的一切建立在"数据在自己手里"上，
而**互动功能最容易在这里背叛它**：一个"顺手帮你同步"的开关，就足以把前面所有主张作废。
下面每一条都服从这条底线，需要例外的地方会单独写明。

---

## 二、现状：两边已经有什么

判断"接通"还是"新建"，只看已有的东西。

| ShuyoNote（应用） | 数友社区（站点） |
|---|---|
| 本地优先、SQLCipher 加密库 | 帖子 / 评论 / 标签 / 专题 / 板块 |
| 附件**内容寻址**（`/attachments/<sha256>`） | 评论**已支持贴图**（2026-09-11 起） |
| **插件系统**：JS 运行时 + 权限 + 视图（`rail` / `overlay`）+ 触发器 / 事件 | **插件配方**（12 个成品）+ **插件 API 教程** + 「给插件作者」专题 |
| **插件索引：发布者密钥 + 包签名校验 + 撤销名单 + 来源白名单（仅 https / 回环）+ 解压防 zip-slip + sha256 先校验后解压** | 全文检索（FTS）+ 通知流（SSE）+ 关注 / 私信 |
| 邮件转笔记、备份、PDF 阅读与批注 | 公告（置顶）、**「更新日志」板块**、后台（含新增的删帖） |

**结论**：**分发的信任基础在应用侧已经建好了**（签名、撤销、来源限制、完整性）；
社区侧缺的不是"能发内容"，而是**与应用之间的通道**。所以第一优先级不是"做新功能"，
而是**定义通道**。

## 四、分阶段

### P0：最小闭环 —— `shuyonote://` 协议

**做三件事**：社区帖子可"存进笔记"；帖子里的配方可"导入"；应用里可"分享一段到社区"。

- 协议形态：`shuyonote://save?url=…`、`shuyonote://import?url=…`、`shuyonote://compose?title=…&body=…`；
- **导入一律先给清单再执行**（装什么、要什么权限、来源是谁），与插件权限模型一致；
- **分享默认只带摘要 + 原帖链接**，全文要不要发由人点。

**验收**：社区帖子页出现"存进笔记"入口；应用收到链接后弹出确认框并成功落库；
分享后的帖子带着来源标注。**不做**：自动同步、静默导入、后台轮询。

### P1：身份、讨论与更新（把两边"看成同一个产品"）

- 应用内显示"我的帖子 / 我的插件"（复用登录令牌）；
- 插件详情页显示社区里关于它的讨论（一次检索）；
- **应用检查更新直接读社区的「更新日志」板块**，不再两边各写一遍；
- 问题反馈生成**脱敏诊断包**（版本、插件清单、日志片段，**绝不含笔记内容**），
  弹预览让人删减后再发。

### P2：内容与分发

- **社区精选离线读**：精华帖同步进应用，可离线读——本地优先的社区版；
- **社区作为插件索引来源**：应用"发现插件"能列出社区上架的插件；帖子携带可校验的包
  （sha256 + 发布者签名），应用侧沿用已有的签名/撤销/来源校验，**不新增信任假设**。

## 五、明确不做（附理由）

| 不做 | 理由 |
|---|---|
| 笔记库整体同步到社区 | 与"本地优先"直接冲突；社区不是备份服务 |
| 静默上传（含静默遥测） | 底线条款 |
| 自动安装社区里的插件 | 安装必须由人确认；签名只保证"来源可信"，不保证"你想要" |
| 应用内嵌社区网页 | 维护两套 UI；协议跳转足够 |
| 社区侧存笔记正文副本 | 数据主权主张不允许；只存人主动发布的内容 |

## 六、建议的执行顺序

**P0（1 天量级）→ P1 中的"更新日志单一来源"与"讨论串"（各半天）→ 再评估 P1 其余与 P2。**

理由：P0 全部是"接通"（不改数据模型、不动信任链），能立刻用上；
P2 的插件分发虽然最有产品价值，但它会**改动分发链路**，应当在前面几条把
"应用 ↔ 社区"的通道跑顺之后再动。

## 七、P0 协议规格（先定死这个，两边才能同时开工）

### 动手前查到的现状（决定了第一步该是什么）
- 应用侧插件只有 `updater`，另有 `opener` 与 `single-instance`——**没有 `deep-link`**，
  因此**此刻既注册不了也处理不了** `shuyonote://`；
- `DrawingEditorModal` 里已经在生成 `shuyonote://page/<id>`，但那是**应用内部的链接格式**，
  不是操作系统级协议：它只在应用内部被解析，从浏览器点它不会有任何反应；
- `bundle.targets = ["nsis"]`——注册协议需要同时改 **NSIS 配置**与**安装包行为**。

**结论：先把社区那一半做出来会得到一个死链，比不做更糟。**
所以 P0 的第一步是**把协议定死**（本文档），第二步才是应用侧注册，第三步才是社区侧入口。

### 协议形态（三条，全部只读，全部需要确认）

| 链接 | 语义 | 应用侧行为 |
|---|---|---|
| `shuyonote://save?url=<帖子地址>` | 把该帖子存成一篇笔记 | 抓取正文 → **弹出预览** → 人确认后落库，并写入**来源链接** |
| `shuyonote://import?url=<附件或代码地址>` | 导入配方 / 主题 / 模板 | 先显示**清单**（是什么、来自谁、要什么权限）→ 确认后导入 |
| `shuyonote://compose?title=<标题>&body=<摘要>` | 在应用里起一篇草稿 | 打开编辑器，**内容由人确认后再发** |

### 三条硬约束
1. **只读语义**：这三个链接都**不携带凭据**、不触发上传、不隐式登录——它们只做"把外面的东西拿进来"
   或"起一份草稿"。任何写回社区的动作都在应用里由人点。
2. **一律先确认**：`save` 与 `import` 都必须弹预览；`import` 的预览就是**权限与来源清单**，
   与插件安装同一套 UI 与同一套措辞。
3. **失败要有话说**：链接无效、地址取不到、应用未安装——三种情况都要给出**能读懂的提示**，
   不允许静默失败（这一条来自社区今天的教训：静默失败会被当成"卡死"）。

### 验收标准
- 应用未安装时，社区页面上点「存进笔记」→ 出现"尚未安装 / 复制链接"的提示，**不是死链**；
- 应用已安装时 → 应用被唤起并弹出预览，取消后**不留任何痕迹**；
- `import` 的预览里必须能看到来源与权限，且**取消后不写入任何文件**；
- 三条链接的解析都有测试（纯字符串 → 动作映射，不需要真机）。

### 应用侧需要做的（未做，留给下一轮或由你决定）
1. 引入 `tauri-plugin-deep-link`，在 `tauri.conf.json` 注册 `shuyonote` scheme；
2. NSIS 打包侧注册协议（Windows 上写注册表）并处理"应用已在运行时把链接转给已有实例"
   （`single-instance` 已在依赖里，正好接这一环）；
3. 解析函数与"预览 → 确认"的两步 UI。

## 八、采纳的决定（2026-09-11，与 macOS 侧通信后）

来源：私有信箱 `ShuyoNote-collab` 的 `reply-1` … `reply-5`。**结论以本节为准**，上面各节保留原样以便回溯。

**1. 顺序改成"能力先行、协议后置"（原第七节作废）。**
协议要三平台注册（NSIS / `.desktop` / `Info.plist`，而 macOS 还没发），但**不依赖协议**的两件事可以先做：
「导入配方·主题·模板」与「分享摘要到社区」。协议阶段的第一步是**构建安装包**，不是顺手做掉。

**2. 无协议版的载体（对方按代码核过，我原方案这里说宽了）。**
| 载体 | 实际情况 |
|---|---|
| 插件包 | ✅ 已有两条：从本地文件夹安装、签名索引 + 订阅 |
| 模板 | ✅ 已有导入/导出（模板中心） |
| 主题 | ❌ **不存在**文件格式与导入导出 → 这轮不做 |
| 拖拽落文件 | ⚠️ **只对文件管理器成立**（`FileManagerView.tsx` → `importPaths`），编辑器里没有 drop → **不算已有能力** |

**3. `save?url=` 抓 JSON，不抓 HTML。** 社区给 `GET /api/posts/{id}.json`
（`body_markdown` 直接吐落库源码）+ 页面 `<link rel="alternate" type="application/json">`；用 `id` 当稳定键。
抓取复用 `index_http_client` / `http_get_capped`，白名单：仅 `community.shuyo.cn`、仅 https、
拒带凭据 URL、拒非默认端口、**解析后按 IP 再拒私网与元数据网段**、**重定向落地地址复查**。

**4. 幂等：来源 URL 是稳定键。** 同一帖存第二次 → 「已经存过，打开那篇」；成功记来源 + 时间 + 内容 sha256；取消/失败**零痕迹**。

**5. `compose` 的约束。** URL 约 2000 字符上限 → 只带**摘要 + 原帖链接**；落点要显示，**没有工作区时必须问**；
**草稿先不落库**（未保存 = 零痕迹）；外部字符串只做纯文本转义，永不 `innerHTML`。

**6. "更新日志单一来源"方向改正。** 不是应用去读社区板块，而是**仓库产出** → 社区展示 → 应用读 updater 的 `notes`。这是**减少**一条通道。

**7. 分发（P2 降级为"现在就能跑通"）。** 社区**只托管签名过的清单**，不碰包字节、不持任何发布者私钥。
第一方插件的包由**发版产物**提供（`downloadUrl` 带版本号）；第三方作者自己挂（规范默认）。
索引签名用**社区自己的密钥**；包签名是**发布者密钥**（TOFU）。`minAppVersion` 是硬闸门，按真实需要填。

**8. 分工。** 方案文档归 Windows 侧改；macOS 侧做解析纯函数、抓取白名单、预览/取消零痕迹、
`discussionUrl` 显示（索引规范里已有该字段）、`release.mjs` 产出 `updates.json` 与 `plugin-index.fragment.json`。
Windows 侧做 NSIS 注册表（只写 HKCU、不进 HKCR）、WebView2 行为核对、真机唤起验证。
