## 0. 一句话 ＋ 三句实话

**让客户端自己扮演"中枢"的接收侧，于是同一网段里两台设备**不需要**先有第三个服务端也能同步。**

⚠️ **实话一：本片是重活，不是"把服务端搬进来"。**
许可墙（简报 §1 F6）：客户端 **AGPL-3.0**、服务端**私有商业授权** ⇒ **一行服务端代码都不能内嵌**。
所以本片只能是**照协议独立实现**接收侧 —— 这也是简报把它单独列一片、而不是塞进甲-1 的原因。

⚠️ **实话二：甲-1 单独上线时，用户只在"网段里有一台在代言的设备"时看得到变化**；
甲-2 存在的意义正是**拆掉那个前提**（甲-1 施工单 §0 原话）。

⚠️ **实话三：这一层在「丙」里会被替换，不是被增强。**
简报 §4：丙要**删掉号牌与账本**（`seq` 权威 ＋ log 一起删），换成 HLC ＋ per-peer 水位。
⇒ 本片的判据**只能钉协议行为**（"两台设备能收敛"），**不许把"必须有账本/必须有号牌"钉成判据**，
否则丙要拆两遍（§6）。

## 1. 勘察事实（每条都带落点）

**F1 · 客户端今天到底打哪些端点**（读数：`src-tauri/src/sync.rs` / `sync_stream.rs` 里的真实 URL 模板）：

| 端点 | 落点 | 同步主路必需？ |
|---|---|---|
| `{}/push` | `sync.rs:2041` | **是**（把本机变更送上去） |
| `{}/spaces/{}/changes-stream`（SSE） | `sync_stream.rs:109` | 否（改近实时，可降级成轮询） |
| `{att_base}/attachments` | `sync.rs:2600` | 附件才有 |
| `{}/lineage-claim` | `sync.rs:1627` | CRDT 血统 claim 才有 |
| `{}/spaces/{}/keyring` | `sync.rs:1725` | 钥匙袋（与 B 片有交集，见那张单） |
| `{url}/spaces` ／ `{url}/spaces/{space_id}/members` | `sync.rs:1039` / `1093` | 绑定与成员 |
| `{}/spaces/{}/presence` ／ `{}/spaces/{}/online` | `sync.rs:3263` / `3275` | 否（在线态） |
| `{}/spaces/{}/pages/{}/comments` | `sync.rs:3284` | 否（评论） |
| `{server}/auth/register` ／ `{server}/push` ／ `{server}/spaces` | `sync_stream.rs:775` / `832` / `787` | 注册/绑定那一步 |

⇒ **"接待窗口的最小面"不是两个端点，而是上面这一整串**。所以本片必须**分片**，并且把
"没实现的那几件"变成**显式不支持**（§3）—— 否则用户看到的是"功能悄悄不动"。

**F2 · 号牌与账本在客户端侧的落点**：`sync_profiles.last_pushed_seq` / `last_pulled_seq`
（`sync.rs:18/19`）。⚠️ 同一文件 `:287` 那条注释点明了要害：**必须与 `do_push` 用来挑变更的是同一个值**
—— 号牌"只出一处"这条纪律在本片里会更紧张，因为**发号牌的人换成了对端**。

**F3 · 许可墙是硬的**：客户端 AGPL / 服务端私有 ⇒ 接待窗口只能是**独立实现**。

**F4 · 前置**：甲-1 的**接线那一片还没做**（读数：`PeerTable::new` / `bind_listener` /
`announce_once` / `recv_into` / `resolve_base` 在 `lan.rs` 之外调用点**全部为 0**）。
没有"发现 + 选地址"这一层，接待窗口没有地址可被找到。

## 2. 分片（每片都要能独立验收）

**片 1（最小闭合，本片的主目标）**
`spaces` 绑定 ＋ `push` ＋ `pull`（含号牌与账本）。
判据：**两个客户端进程（环回）之间互换一笔改动后，两侧投影一致，且全程没有第三个进程。**

**片 2（可降级面）**
`changes-stream`（SSE）、`presence`、`online`。
口径：实现不了就退回轮询，或**显式不支持**（§3），不许"开着但没反应"。

**片 3（附件与其余）**
`attachments`、`lineage-claim`、`comments`。

## 3. 降级口径（★ 这一节本身是判据）

接待窗口**没实现**的端点，必须**显式**回答"这一档不支持"，并且**客户端要把它显示出来**。
⚠️ 静默 404 / 空 200 / 一直 pending，是三种最坏的形态：用户看到的是"点了没反应"，
而日志里什么都不像错误。本片的 ④ 判据钉这条。

## 4. 承重判据（本机可验；★ = 退化了就变红）

| # | 判据 | 退化了会怎样 |
|---|---|---|
| ① ★ | **零服务端闭合**：两个客户端进程（环回）互换一笔改动后，两侧投影**逐字节一致** | 本片存在的理由没了 —— 还是得先装服务端 |
| ② ★ | **号牌只出一处**：序号由接待窗口发；两侧看到的 `seq` **单调且不重号**（同一笔改动在重传下只被计一次） | 两边各发一套号牌 ⇒ 冲突裁决错乱，而**两边单测都绿** |
| ③ ★ | **未实现的端点显式说"不支持"**（不是 404/空 200/pending），且客户端把它显示出来 | "功能悄悄不动"，排查只能靠猜 |
| ④ ★ | **许可墙**：接待窗口里不许出现服务端仓库的代码/依赖（做成静态判据，手法照 `check-derived-writers`） | 许可风险，且**编译期没有任何信号** |
| ⑤ | 接待窗口**只在自己网段可达**，不监听公网地址（与简报 §7 边界一致） | 无意中把它暴露成公网服务 |

## 5. 本片不做（逐条写死，免得被读成"甲做完了"）

- **不做** NAT 穿透 / 跨网段 / 中继 / Web 参与（简报 §7 一字不改）；
- **不删**号牌与账本（那是**丙**）；
- **不做**多中枢选举（乙已跳过）；
- **不改** wire 形状、不给 `changes`/`seq` 加列；
- **不复用**服务端任何代码或依赖（F3）；
- **不做**"接待窗口也能接公网"那件事（安全边界，见判据 ⑤）。

## 6. 与丙的关系（写清楚，免得白做一遍）

丙要**删号牌、删账本**（简报 §4）。所以本片的判据**只钉协议行为**（"能收敛"、"号牌单调"），
**不钉实现形态**。具体地：

- ⚠️ **不许**把"必须有 `changes` 账本"写成判据 —— 丙要删它；
- ⚠️ **不许**把"号牌由谁发"焊进客户端可见的状态 —— 丙没有号牌；
- ✅ 可以钉的是：**同一笔改动只被计一次**、**两侧收敛**、**未实现就显式说**。

这三条在丙里**依然成立**（只是换实现），所以它们是本片该钉的东西。
