# 「内联 AI 起草」方案（Inline AI Drafting）

> 目标版本：v1.60.x（提议）。关联：[薄 Agent 接口实现方案](2026-08-24-thin-agent-interface-implementation-plan.md)、[系统架构](../architecture.md)。
> 状态：**规划（建议）**。本方案把 ShuyoNote 的 AI 从「右侧聊天面板 + 二段确认」扩展为「**内嵌在文档流里、流式写入、高亮待定块 + 一组快捷动作**」，对标 wolai / FlowUs / Notion AI 的「AI 起草」体验。

## 1. 背景与目标

- 现状：ShuyoNote 的 AI 是右侧**聊天面板**，写操作走「确认草稿 → 应用」二段式（已验证 M17 薄 Agent 底座）。
- 参考：wolai / FlowUs / Notion AI 提供「**内联起草**」——AI 起草条嵌在文档里，直接**流式写正文**，生成块**高亮**，随后给一组动作（完成/新建页/续写/扩写/重新生成/关闭）。
- 目标：让用户「**对着文档直接让 AI 写**」，所见即所得，同时**不丢确认红线**。

## 2. 目标体验（参考截图流程）

1. **空白页**：标题占位「新页面」，正文占位「输入 `/` 选择，按 `空格` 打开 AI…」→ `/` 或空格唤起内联起草条。
2. **起草条 + 模板下拉**：标题下方一条内嵌输入框（左 ✦ 图标 +「告诉 AI 你想写什么…」，右模型选择 + 发送）。下方「**用 AI 起草**」菜单：文章大纲 / 内容简介 / 社交媒体帖子 / 电子邮件 / 广告文案 / 短篇故事 / …更多。
3. **输入**：如「帮我写一则短篇故事，故事主题/要求是…」。
4. **流式创作**：内容直接**流式写进正文**；底部状态条「**AI 正在创作···**」+「重新生成 R」「停止 ESC」。
5. **生成后**：AI 写入的段落被**高亮**（可整体辨识、处理）；起草条变为「告诉 AI 继续写什么」，下方提示「AI 回复的内容可能与实际结果有偏差，仅供参考。回顾思考过程」+ 赞/踩；动作菜单：**完成 / 创建新页面并插入内容 / 续写 / 扩写内容 / 重新生成 / 关闭**。

## 3. 与现状对比

| 维度 | 现状（聊天面板） | 目标（内联起草） |
|---|---|---|
| 入口 | 右侧 ✦ 面板 | 文档内 `/` 或空格里键唤醒 |
| 写入方式 | 确认草稿后一次性落库 | 流式写入 + **高亮待定块**，认可后落库 |
| 确认边界 | 明确二段式 | 「预览高亮 → 完成」仍是确认边界 |
| 辅助动作 | 确认/弃用 | 完成/新建页/续写/扩写/重新生成/关闭 + R/ESC 快捷键 |
| 思考展示 | 右侧「已深度思考」块 | 仍需展示（可内联或边栏） |

## 4. 职责划分（嵌入式 vs 侧边栏）

两者**共用同一套薄 Agent 核心**（`runAiLoop` + 白名单工具 + 流式 + 思考展示），差异只在**交互面、输出落点、确认模型**。划分原则一句话：**内联 = ``就地动手写``，侧边栏 = ``动脑问/做``**。

| 维度 | 嵌入式（内联）AI 助手 | 侧边栏 AI 助手 |
|---|---|---|
| 核心职责 | **当前文档内的创作/编辑** | **全局问答 / 理解 / 结构化操作** |
| 作用范围 | 当前页、当前光标处 | 整个空间（跨页检索、分析、建页/追加） |
| 输出形态 | 内容**就地流式写入**为高亮「待定块」 | **对话答复** + 结构化**草稿**（建页/追加/反链） |
| 确认模型 | 高亮预览块 →「完成」落库 /「关闭」丢弃 | 草稿卡 →「应用」确认后执行 |
| 典型动作 | 续写 / 扩写 / 重写 / 重新生成 / 新建页插入 | 总结当前页 / 跨页找内容 / 建会议页 / 追加内容 / 反链分析 |
| 上下文 | 以当前页为主（本地、就地） | 全局历史 + 全空间页面（`search_pages`/`read_page`/`get_backlinks`） |
| 对话延续 | 短、任务聚焦（一段写完即「完成」） | 多轮追问（历史 cap 16，支持「再详细点」） |
| 入口 | `/` 或空行内联唤起 | 右侧 ✦ 面板 |

**边界规则**

- **「写进当前文档」→ 内联**：用户在某页编辑，想让 AI 在**光标处**写/扩/改 → 内联，结果即眼前这段文字（高亮 → 完成）。
- **「问、查、跨页、建新结构」→ 侧边栏**：总结、对比、全文检索、新建页面/数据库、往别处追加 → 侧边栏，产出为答复或「确认后执行」的草稿。
- **不重叠**：内联只做「当前页就地」；侧边栏做「全局理解 + 结构动作」，产出落点不同（当前页 vs 作为动作执行），天然不冲突。
- **共用底座**：同一套 `src/lib/ai/` 工具与流式；同一个 `config.enabled`（默认关）、同一 provider/模型；差异只在**前端交互层**。

**快速判断**

- **"帮我写/改/扩一段"** → 内联（写完就地，高亮→完成）。
- **"帮我看看/总结/找/建一个新页"** → 侧边栏（理解 + 全局 + 确认动作）。

## 5. 安全边界（关键，不可让步）

- **写操作先落「预览态」**：AI 生成的内容先作为**高亮的『待定块』**插入编辑器，**不立即写库**；用户点「完成」才 `save_page` 落库，「关闭」则丢弃。
- **保持白名单语义工具**：仍走 `src/lib/ai/` 的受限宿主，不暴露 shell/任意文件/网络；工具执行需要的能力不扩大。
- **默认关闭**：AI 起草能力沿用 `config.enabled`（默认关），需在设置开启。
- **可追溯**：AI 块带来源标记，用户按「回顾思考过程」可看 `reasoning_content`。

## 6. 交互与技术要点

- **内联起草条**：一个随光标出现的输入组件（`/` 或空行内触发），含模板下拉（`src/lib/ai/preview.ts` 已有草稿预览可复用）。
- **流式写入**：复用 `runAiLoop` + `onDelta`/`onThinking`，把增量内容以 `TextNode` 实时插入一个**临时块**；`src/store/ai.ts` 的节流逻辑沿用。
- **高亮待定块**：给临时块加一个标记（CSS 类 `ai-pending` + 主题 token，如 `--ai-highlight`），用 `data-block-id` + `block-*` 能力定位。
- **动作菜单**：完成（落库 + 移除高亮）/ 续写 / 扩写 / 重新生成（清空临时块重跑）/ 关闭（丢弃）。对应 `runAiLoop` 的草稿语义。
- **快捷键**：`R` 重新生成、`ESC` 停止（复用 `run` 的 `stop()`）。
- **新建页**：「创建新页面并插入内容」走现有 `create_page` + `ai/tools.ts` 的 `pageJsonFromText`（已修正 root 缺 `type:"root"` 的问题）。

## 7. 最小闭环（建议先行）

1. `/` 或空行唤起内联起草条 + 模板下拉。
2. 发送后**流式写入**一个高亮 `ai-pending` 块（不落库）。
3. 状态条「AI 正在创作···」+ R/ESC。
4. 完成后动作菜单：**完成（落库）/ 关闭（丢弃）**。
5. 续写 / 扩写 / 重新生成 / 新建页 二期接。

## 8. 关联文件（推测）

- 前端：`src/components/`（新增 `InlineAiDraftBar` / 模板下拉）、`src/editor/`（临时块 + 高亮）、`src/store/ai.ts`（状态）扩展。
- AI 宿主：`src/lib/ai/{host,llm,transport,apply,tools,preview}.ts` 复用，`apply.ts` 评审/落库。
- 安全审核：新增块的「预览→完成」落库路径，仅 `append_block`/`create_page` 受限命令。
