## 3. 第一切片（Slice A）：**只做转换的唯一实现 ＋ 判据**，不碰协议、不碰持久化

理由：§4 的七处改动面里，**面 1（编辑器持久化）**是唯一能**在 Node 侧自验**、且不动 wire／加密／插件契约的一处
（尖刺施工单 §末就建议过"把收敛断言写在 Node 侧，这样 Windows 也能自验"）⇒ 先在它上面切一刀，
把最大的未知从"尖刺脚本"变成"仓里的唯一实现 ＋ 判据"。

- **交付**：`src/lib/crdt/`（新目录）里的 `contentJsonToYDoc` / `yDocToContentJson` —— **唯一实现**（不许再出现第二份转换），
  外加它需要的边界口径（空页、坏 JSON、键序）。
- **必须复用**（不许另写一套）：`lexicalStateValid` 空页归一、`SHUYONOTE_TRANSFORMERS`、块身份**声明字段**、`EDITOR_NODES`。
- **判据**（vitest，Windows 可自验）：① 往返保真（含 18 类自定义节点）② 空页 / `"{}"` / 坏 JSON 的归一
  ③ 键序无关 ④ `blockId` 穿过往返 ⑤ `blockRev` 不参与内容比较。
- **不做**：不改 `content_json` 的落盘形态、不加同步字段、不动服务端、不动插件契约；
  `yjs` / `@lexical/yjs` **不升格为生产依赖**（先在独立试验路径里钉死版本，跑通再谈升格 —— 尖刺的教训是"版本必须写死，否则'当时能跑'无法复现"）。
- **分支**：`feat/crdt-json-ydoc`；验证 `pnpm vitest run src/lib/crdt` ＋ `pnpm run build`（含全套门禁）；不碰 main。
