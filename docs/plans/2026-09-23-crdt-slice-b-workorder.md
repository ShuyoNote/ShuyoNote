## 0. 一句话

Slice A 只证明了"JSON ⇄ ydoc 转换是保真的"；Slice B 要回答的是**这条路怎么接到产品上而不同时改变两件事**：
把"选走 ydoc"做成一个**可关的开关**，关掉时行为与今天**逐字节等价**。

## 1. 必须先拍的三条口径（本片存在的理由；拍不出结论就不许写代码）

| # | 问题 | 候选 | 倾向与理由 |
|---|---|---|---|
| 1 | **混版本降级**：老客户端只写 JSON、新客户端写 ydoc ⇒ 同一页两套形态 | (a) 落盘**仍是 JSON**，ydoc 只作**内存/传输**平面；(b) 落盘换 ydoc ＋ 老客户端只读降级；(c) 双写 ＋ 版本标记 | 倾向 **(a)**：与阶段 1 已跑通的"内存/CRDT 用新形态、落盘/同步用老形态"是**同一手法**，风险面最小；`contentJsonYDoc` 已经就是为这条路写的（两侧都是落盘形态） |
| 2 | **空页那一段的 id 由谁铸** | 保存路径先铸／转换层固定稳定 id（Slice A 现在用 `empty-page`）／空页不落身份 | 倾向 **保存路径先铸**、转换层**继续不造身份**（Slice A 已经为此在缺 id 时**当场报错**）；两设备各铸一套 id ⇒ 同一块变两块 |
| 3 | **派生索引（`content_text` / FTS）在 ydoc 平面下何时重建** | 保存时（今天）／合并后（CRDT 时代） | 阶段 1 的"待重建标记 ＋ 补算器"（写层 §11）是**过渡量**：换 ydoc 后产出点变成"合并后" ⇒ 补算器口径要跟着改，本片至少要把**判据**先立起来 |

## 2. 交付面（只在 §4 面 1 里动，别扩）

1. **开关**：一个默认关闭的选项（名字待定，不进 UI 也行 —— 先供判据与埋点用），关闭时**不改变任何落盘字节**；
2. **接入点**：`src/lib/docContent.ts` 那一层（"只经一层"的门禁 `check-doc-content-access` 已经在看着这里）；
3. **往返不变量**：开关打开时，`读 → 合并 → 写` 全链路仍以**落盘形态**出入（ydoc 只在中间当平面），
   ⇒ 关掉开关得到与今天**逐字节相同**的结果。

## 3. 判据（Node 侧自验 ⇒ Windows 也能跑）

| # | 判据 | 为什么它承重 |
|---|---|---|
| ① | **开关关闭 ⇒ 逐字节等价**：同一批 fixtures 在开/关两种模式下写出的 `content_json` 完全相同 | 迁移不许改未开启用户的行为 —— 这条不绿，后面全是空谈 |
| ② | 开关打开 ⇒ 走 `contentJsonToYDoc` / `yDocToContentJson` 往返后**内容等价**（用 Slice A 那套归一后的比较口径） | 接线接对了没有 |
| ③ | **混版本降级路径**：按 §1 拍板的口径造一例"老形态输入 ＋ 新形态输出"，断言不丢块、不静默改写 | 尖刺 §6 点名要求 |
| ④ | 引用完整性：往返后 `topLevelBlockIds` 不变（块引用/反链不会断） | 这是本产品与"普通 Markdown 编辑器"的差别所在 |
| ⑤ | 派生口径：`content_text` 与 FTS 在两种模式下**都不落后于正文**（或如实标记"待重建"） | 接 §1 第 3 条 |

## 4. 退出条件

1. §1 三条口径**有明确结论**（写进本文件，不是口头）；
2. 上面 5 条判据全绿，且 ① 是"逐字节"级别的；
3. `pnpm run build`（全套门禁）在**当轮 tip** 上绿（阶段 1 与 Slice A 都栽过"只在旧 tip 上跑过"这一条）；
4. 文档索引与 `check-doc-links` 绿。

## 5. 本片**不做**

- 不改服务端、不改 wire/`outbox` 协议、不改插件与 AI 的读写契约（§4 面 2/5/6）；
- 不动版本历史与 undo（§4 面 4）；
- 不把 `yjs` / `@lexical/yjs` 从 devDependencies 升格（升格要单独一次提交 ＋ 说明它对打包产物的影响）。
