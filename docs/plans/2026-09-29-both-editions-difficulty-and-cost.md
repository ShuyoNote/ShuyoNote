# 个人版 ＋ 企业版：**技术难度与实现成本**
> 状态：**已收口**（估算，非实测）。证据：人日逐项引自各依据文档（见 `../specs/2026-09-29-enterprise-edition-requirements.md`）


> 由来：owner 2026-09-29「**个人版和企业版的需求定死，分析一下技术难度和实现成本**」
> 需求出处：[`personal-edition-requirements`](../specs/2026-09-29-personal-edition-requirements.md)
> ／[`enterprise-edition-requirements`](../specs/2026-09-29-enterprise-edition-requirements.md)。
> ⚠️⚠️ **成本是【估算】，不是实测** —— 我按"改哪些文件、要不要动协议/存储/服务端"来估，
> 标为"人日"（1 人日 ≈ 1 个熟练开发者 1 天，含自测与判据）。**不承诺**，供排序用。

## 1. 个人版（13 条需求）—— **总量 ≈ 9~15 人日**
| 需求 | 难度 | 成本 | 依赖 / 风险 |
|---|---|---|---|
| **U1 配对进设备直连** | **中** | **3~5 人日** | ✅ 零件已有（`pairing_export/import`）；⚠️ 要把它接到设备直连上 |
| **U2 配对必须人验证** | 低 | **0.5 人日** | ✅ 机制已有（比对码）；只需"不许跳过" |
| **U3 两端码不一致⇒停** | 低 | **0.5 人日** | 文案＋分支 |
| **U4 码长不缩短** | **0** | **0** | ✅ 已经是对的（不动） |
| **U5 地址自动（通配＋枚举）** | **中** | **1~2 人日** | ⚠️ **要推翻一条既有判据**（`mesh.rs:1916` 的 `0.0.0.0 ⇒ Err`） |
| **U6 端到端自动** | **中** | （含在 U1） | 靠"设备对秘密"存储 ＋ 自动认证 |
| **U7 发现＋5 秒节拍** | **0** | **0** | ✅ 已有 |
| **U8 一窗多空间** | **中~高** | **3~5 人日** | ⚠️ 要改窗口模型（今天 per-space）＋ 连带动"窗口级口令" |
| **U9 口令强度＋文案** | 低 | **0.5 人日** | 纯前端＋一条校验 |
| **U10 静态加密可选** | **0** | **0** | ✅ 已有（`space_crypto`） |
| **U11 逐台解除配对** | **中** | （含在 U1） | 靠"设备对秘密"的**粒度**（每对一份） |
| **U12 虚拟局域网** | 低 | **~~1~~ 3~4 人日**（⚠️ 2026-09-29 实测上调） | ⚠️ **原写「1 人日＝主要是文档＋文案」是错的**：实测发现**代码也要改** —— `100.64/10`（Tailscale 默认段）过不了 `is_lan_only`，而 `checked_bind` 是**拒绝启动** ⇒ **两处网段表**（`mesh.rs` ＋ `lan.rs`）＋ 一条两把尺一致性判据（已落 `798fa157`） |
| **U13 不许过度承诺** | **0** | **0** | 文案纪律 |
> **⇒ 个人版只需动客户端（Rust 内核 ＋ 面板）；不碰服务端、不碰协议。**

## 2. 企业版（六组需求）—— **总量 ≈ 100~190 人日**
| 阶段 | 项 | 难度 | 成本 | 依赖 / 风险 |
|---|---|---|---|---|
| **A 手感** | ①**增量 payload**（整页→update） | **中~高** | **5~8 人日** | 要让"增量被留下"（今天只存整份 state） |
| | ②**先发后落库**（撤两层防抖） | 中 | **2~3 人日** | 要拍"撤防抖" |
| | ③**光标** | **中~高** | **5~8 人日** | 新协议＋广播（与"附近设备"共用 UDP） |
| **B 降阶** | ④**L4a/L4b**（帧带 seq＋跳号回退） | **低~中** | **2~3 人日** | ✅ **零风险**（不改取数行为） |
| | ⑤**L4c**（服务端转发增量） | **高** | **8~15 人日** | ⚠️ 动服务端（私有仓）＋ 客户端取数路径 |
| | ⑥**按页订阅＋不透明键** | **很高** | **15~25 人日** | ⚠️ 新协议＋路由表＋退订纪律＋**要拍元数据边界** |
| **C 横向** | ⑦**连接与数据分离** | **高** | **10~20 人日** | ⚠️ 要拍部署形态 |
| | ⑧**seq 改空间级** | **中~高** | **5~10 人日** | ⚠️ 动存储模型（无真实用户 ⇒ 可重建库） |
| **D 可选加密** | ⑨**按空间两档＋密钥分发/轮换** | **很高** | **20~40 人日** | 🔴 **最难的一块**（我只算过、**未实测**） |
| **E 治理** | ⑩**权限角色＋审计导出** | 中 | **5~8 人日** | — |
| | ⑪**内容级治理**（水印/密级/DLP/检索） | **高** | **20~40 人日** | 每项都不小；⚠️ **仅明文空间** |

## 3. ⭐ 合起来看（三张排序）
### 3.1 按"性价比"排（先做哪个）
```text
① **L4a/L4b**（2~3 人日，**零风险**）⇒ 安全网就位
② **个人版的 ①②③④**（≈5~8 人日）⇒ 个人版**立刻有入口**
③ **先发后落库**（2~3 人日）⇒ 手感立刻改善
④ **增量 payload**（5~8 人日）⇒ 手感 + 为 L4 铺路
⑤ **地址自动**（1~2 人日，个人版）
```
### 3.2 按"风险"排
```text
🔴 **⑨ 可选加密**（密钥分发/轮换）—— 最难、未实测、无先例
🔴 **⑥ 按页订阅** —— 要拍元数据边界（页级不透明键）
🟡 ⑦ 连接与数据分离 —— 要拍部署形态
🟡 ⑧ seq 改空间级 —— 动存储模型
🟡 ① 增量 payload —— 要改"存什么"（今天只存整份）
```

## 4. ⚠️ 成本估算的**不确定性**（诚实）
```text
· 这些是**人日估算**，**不是**实测工期 ⇒ 误差可能 ±50%
· 最大的不确定在 **⑨ 可选加密**（无先例、要设计密钥轮换）与 **⑥ 按页订阅**（协议改动大）
· ⚠️ 而**两处"零成本"是因为已经做完了**：静态加密（`space_crypto`）／发现与 5 秒节拍
· 还有一类**没计入**的成本：**判据与测试**（本仓要求"每条不变式有判据"）——
   ⚠️ 按本仓惯例，新增判据的成本**可能占到实现成本的 30~50%** ⇒ 上面的数**偏乐观**
```

## 5. 一句话
```text
**个人版 ≈ 9~15 人日**（**只动客户端**，零件大多已有；最紧的是"配对进设备直连"）
**企业版 ≈ 100~190 人日**（要动协议/存储/服务端；**最难是"可选加密"与"按页订阅"**）
⇒ 而**最省的第一步**：**L4a/L4b（2~3 人日、零风险）＋ 个人版那四件（5~8 人日）** ——
   两者互不依赖，可并行 ⇒ **约两周内个人版有入口、企业版安全网就位**。
```
