# B 片施工单：换设备零服务器（二维码 / 短码 PAKE 搬公开材料，2026-09-25）

> 上位：[局域网 P2P 拓扑决策简报](2026-09-24-lan-p2p-topology-decision.md) §5／§10
> （简报原话：**「B 片与这三档全部正交，应当独立并行 —— 它是『零服务器 ＋ 立刻可验』的那一件，
> 而且甲和丙都要用它做配对」**）。owner 2026-09-24 拍板：甲做阶段 1、丙当目标、跳过乙；
> 顺序 **甲 → B → 丙**，但 B 片**不等甲-1 接线完成**即可开工（正交）。
>
> ⚠️ 本片**不改 wire 形状、不动既有 schema 列、不引新依赖、不内嵌任何服务端代码**。

## 0. 一句话 ＋ 先说实话

**把「第二台设备要用的那份东西」从设备 A 搬到设备 B，全程不经过任何服务器。**

⚠️ **实话一：搬的是公开材料，不是密钥。** 搬的那份东西已经存在且有名字 ——
`Keyring::to_json()`（`src-tauri/src/keyring.rs:191`），它含 `v` / `kdf`（**算法名 ＋ 盐 ＋ 参数**）/
`spaces`（每个空间一个**盒子**＝密文）。**公开材料里不许出现裸密钥或口令**，这条已有 ★ 判据钉着
（`keyring.rs` 里那条 `to_json` 判据；它还要求盐**必须在**里面 —— 第二台设备没有盐就推不出同一把钥匙）。

⚠️ **实话二：公开材料不是"随便传都行"。** 「盒子 ＋ 口令 ⇒ 空间密钥」⇒ 谁录下通道里的字节，
谁就能**回家离线爆破口令**。这一条决定了下面两条通道的安全要求不同：
**二维码是"看一眼就对"的旁路（不经过网络），短码必须 PAKE**（见 §1 F6）。

⚠️ **实话三：本片的价值不在"能传"，在"**换设备时不会把本机已有的东西弄坏**"。**
采纳侧已经有 `adopt_material(c, json, overwrite) -> AdoptReport`（`space_crypto.rs:109`）——
`overwrite` 这个参数的存在本身就说明有人担心过"覆盖"。判据要钉死它（§4 ③）。

## 1. 勘察事实（每条都带落点或读数）

| # | 事实 | 证据 |
|---|---|---|
| F1 | **要搬的东西已经存在，且有单一出处** | `Keyring::to_json()` / `from_json()`（`keyring.rs:191/197`）；后者**版本不认识就报错（不猜）** |
| F2 | **已有"存/取/采纳"三件套**，本片只做"搬" | `space_crypto.rs`：`stored_material`（82）/ `adopt_material` ＋ `AdoptReport`（94/109）/ `carry_keyring`（60）/ `store_keyring`（70） |
| F3 | **公开材料的真实尺寸（本机实测，2026-09-25）** | 临时测量判据（跑完已删）读数：1 个空间 pretty **434** / compact **360** B；3 个 918/806；5 个 1402/1252；10 个 2612/**2367**；20 个 5032/**4597** B |
| F4 | **现在的搬运通道是服务端** | `sync.rs:1725` 打的是 `{}/spaces/{}/keyring` ⇒ 本片要的是**不经服务器**的另一条 |
| F5 | **设备指纹已经有落点** | `LanAnnounce.fp`（`lan.rs`），字段注释原话："本片只透传与展示（**配对/防呆留给 B 片**）" |
| F6 | **威胁模型决定了通道选择** | 公开材料 ＋ 口令 ⇒ 空间密钥 ⇒ 录制通道者可以**离线爆破**。二维码不经过网络（看一眼即得）；短码熵极低（6 位数字 ≈ 20 bit）⇒ **必须 PAKE**，否则一次被动窃听就够了 |

**F3 的直接结论**：二维码 version 40-L 的上限是 **2953 字节** ⇒ 用 compact JSON 时
**≤10 个空间**单张够（2367 B）；**20 个空间 4597 B 装不下**。所以"超容量怎么办"不是假想情况（§4 ④）。

## 2. 全部内容（三件）

**① 配对载荷**（一个新结构，**不是**直接扔 `to_json()` 的原文）

- 含：载荷版本 / 公开材料 / **设备指纹** / （可选）"这份材料给哪个空间用"的提示；
- ⚠️ **不许往里塞多余信息**：载荷可能被印在二维码上给旁边的人看见 ⇒ 只放"给第二台设备用"必需的东西，
  否则等于把本机装了哪些空间写在纸上；
- 编码：compact JSON（F3 已经量过 pretty 比 compact 大 ~10%，按 2953 字节算，这 10% 就是 2~3 个空间）。

**② 两条通道**

- **二维码**：A 显示、B 扫。不经过网络 ⇒ 是"物理在场"这条信任根的载体；
- **短码 PAKE**：A 显示 6~8 位短码、B 输入。**必须 PAKE**（F6）；短码本身**不进载荷**；
- 两条通道产出的载荷**必须是同一种**（同一个解析入口），否则等于两套实现。

**③ 采纳侧的防呆**

- 走 `adopt_material`；`overwrite` 必须由**用户确认**驱动，不能由"解析成功"驱动；
- `AdoptReport` 要说得出"这次**新增/覆盖**了哪些空间" —— 静默覆盖是本片最该防的一件（§4 ③）。

## 3. 接线点

- 采纳：`adopt_material`（已有）；
- 指纹：写进 `LanAnnounce.fp`（字段已有，本片开始**真的填**）；
- 界面入口：「换设备 / 导入钥匙袋」那一处（与现有"打开已有空间"并列）；
- ⚠️ **不碰**服务端那条 keyring 通道（`{}/spaces/{}/keyring`）—— 它今天在工作，本片是**加一条**不经过服务器的路。

## 4. 承重判据（本机可验；★ = 退化了就变红）

| # | 判据 | 退化了会怎样 |
|---|---|---|
| ① ★ | 两条通道各自**往返**一次，B 拿到与 A **同一份**公开材料（用同一句口令能推出同一把空间密钥） | 换设备这条链是断的，而"显示成功"看起来一切正常 |
| ② ★ | **被动窃听者拿不到材料**：只把通道上的全部转录喂给"没有口令的一方" ⇒ 推不出盒子里的内容；短码通道尤其要钉 | 短码的低熵直接暴露 ⇒ 一次窃听 = 拿到盒子回家爆 |
| ③ ★ | **采纳侧不许静默覆盖**：B 本机已有同 id 的空间 ⇒ 必须显式说"会覆盖什么"并要求确认 | 换设备把本机已有空间弄坏，且**没有任何提示** |
| ④ | 超容量**如实降级**：载荷超过单张二维码容量 ⇒ 明确说"装不下，请用短码/拆码"，**不许截断** | 给一张扫不出来的码，用户只会以为"二维码坏了" |
| ⑤ | 版本不认识 ⇒ 报错不猜（复用 `Keyring::from_json` 的口径） | 新老版本之间静默半通，症状是"钥匙取不出来"而不是"版本不对" |

## 5. 本片不做（逐条写死）

- **不引新依赖**（二维码编解码库要单独评估：它进的是 AGPL 客户端，且要过离线构建）；
- **不做**跨网段 / NAT / 中继 / Web 参与（简报 §7 边界一字不改）；
- **不改** wire 形状、不给 `changes`/`seq` 加东西；
- **不删**服务端那条 keyring 通道（并存，不替换）；
- **不做**私钥 / 证书那套（配对的信任根是**公开材料本身**，见简报 F6）。

## 6. 空间级成员凭证的形状 —— **2026-09-25 定稿**（简报 §8 留给本片回答的那条）

简报 §8 白纸黑字：「**不回答**『空间级成员凭证的形状』（与 §5 的 B 片**同批设计**）」。
本片按 owner 2026-09-25「按建议执行」采用**最小口径**。⚠️ **先答再写码** —— 格式要跟着它走。

> ### 口径：**口令即凭证；没有中心撤销；换钥匙 ＝ 全体重来。**

| 问题 | 答案 |
|---|---|
| ① **是什么** | **一句口令**（就是今天解锁钥匙袋的那句）。公开材料里的「盒子」只有它解得开 ⇒ **有材料 ＋ 有口令 ＝ 进得来**。不引入第二种凭证。 |
| ② **谁签发** | **没有人签发**。空间密钥是**本地生成、被盒子包住**的（`keyring.rs` 的 `wrap` / `unwrap_key`）；能提供口令并解开盒子的人**就是**成员 ⇒ 与简报 F6「配对的信任根就是 E2EE 的公开材料本身」一致。 |
| ③ **怎么撤销** | **没有单点撤销**。要「踢人」只有一条路：**换钥匙**（`Keyring::wrap` 已有「已有 ⇒ 覆盖：轮换走同一条路」的语义），再把**新的**公开材料重新分发给还在的人。 |
| ④ **已经在网段里的设备怎么被赶走** | **赶不走** —— 只要它还握着旧钥匙。 |

**④ 是本口径最贵的一条代价，必须如实写进产品口径，不许含糊**
（「换钥匙之后，旧设备仍能解开它**已经拿到手**的数据」不是 bug，是「没有中心撤销」的定义）。

### 这条口径对 §2 ① 的直接影响（正因为如此才必须先答）

- 载荷里**不需要**「成员列表」「签名」「邀请令牌」这类字段 ⇒ 形态就是 **「材料 ＋ 设备指纹」**；
- 因此载荷**没有**「谁可以进」的信息 ⇒ **拿到那段码的人就能进** ⇒ 界面必须把它说成
  「**这就是钥匙，别截图发群里**」，**不能**写成「扫一下就能加」；
- 也正因为没有成员列表，**§4 判据 ③（采纳侧不许静默覆盖）** 更加重要：
  唯一还拦得住的一道门就是「**本机已有同 id 空间时，必须显式说会覆盖什么**」。

### ⚠️ 什么时候该推翻这条口径

需要「离职的人**立刻**进不来」或「审计谁进过」时 —— 那是**另一片**
（要有凭证签发与撤销，等于要一个能在局域网外工作的授权中心）。
**不要在本片里偷偷加半个**：加了半个的表象是「看起来能踢人」，实际踢不掉。
