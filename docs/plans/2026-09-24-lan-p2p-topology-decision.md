## 0. 一句话

「同一局域网内能不能多台 P2P」要拆成两问 —— **台数**（今天就没有上限：N 台各自与中枢换增量，
发现层只是一张对端表）与**网状直连**（新问题）。而网状直连的卡点**只有一个**：
**页级 LWW 的权威序（`changes.seq`）只能由一个地方发**。

正文那半边**已经不需要它**（Yjs 自己收敛，F4）；剩下的非正文半边（整页 14 列 ＋ 删除墓碑 ＋ 附件元数据，
F3）**仍然需要一个序** —— 这就是甲/乙/丙 三档的全部差别所在。

## 2. 三档对照

| | **甲** 单中枢 | **乙** 谁在线谁当 | **丙** 真网状 |
|---|---|---|---|
| 台数 | 无上限（N 台各自连中枢） | 无上限 | 无上限 |
| 号牌（权威序）谁发 | 你指定的那台常开设备（＝今天） | 当期那一台（要**交接**） | **没人发** —— 「时间 ＋ 设备号」自己算（HLC） |
| 要搬账本（log）吗 | 不搬（它就是服务端） | ★ **要搬** —— 见 §3 | **没有账本这回事** |
| 中枢 / 某台不在线 | 同网段同步**暂停**（不丢数据，等它回来） | 换一台当 | 照常 |
| wire 协议 | **零改**（同形状 `/push`、`/pull`） | 加选举 ＋ 交接 ＋ 交接期去重 | 换定序（HLC）＋ 记录带版本戳 |
| 本地新增持久状态 | **什么都不用** | 中枢身份 ＋ 交接状态 | 每条记录的版本戳（HLC ＋ 设备号） |
| 「同一笔经两条路到达」 | 不会发生 | **会**（交接期两条账本） | 靠幂等 ＋ **按内容**记水位挡掉 |
| 冲突 / 裁决 UI（`dirty`、待取回存档） | **一字不动** | 要跟着交接改 | **要重做**（那套是为 `seq` 写的） |
| 本机可验 | ✅ 两个进程 ＋ 环回 | 🔶 交接要专门造场景 | 🔶 N 对端可模拟，但要新造仿真夹具 |
| 量级 | **一片** | 「中等」偏大（§3） | 阶段 2 那半 ＋ 裁决重做 |

## 3. 乙的洞：它要一份**客户端手上没有**的账本

乙要「谁在线谁当」，可新中枢**手里没有账本**（F1/F2：账本只在服务端/旧中枢上，客户端推完就不留全量 log）。交接于是只有三条路：

1. **旧中枢必须在场**对账 ⇒ 退化成甲，还多了一堆交接代码；
2. **让每台客户端留全量 log** ⇒ 新表 ＋ 存储随历史增长 ＋ 清理策略 ＋ 水位语义全变；
3. **改成不靠 log** ⇒ 那就是丙。

⇒ **乙是「两头都要」的那一档**：留着序号模型的负担，又额外背上账本归属与交接。
除非有硬理由必须保住 `seq`，**建议跳过乙**。

## 4. 丙其实在**删**东西，不是在加

丙去掉两样：**号牌**（序权威）与**账本**（log）。代价收在三处新增 ＋ 一处重做：

- **HLC 判序** ＝ 纯函数 ＋ 两侧各一份判据（本仓最擅长、最容易本机自验的那一类）；
- **每对端一个水位**（「我见过 A 到某时某刻」）＝ 现有 per-workspace 水位（`sync_profiles.last_pushed_seq`）推广成 per-peer，是**加一列**，不是新机制；
- **附件对端选择**（内容寻址已在，缺的只是「跟谁要哪份」）；
- ＋ 一件要诚实说的：**冲突 / 裁决那一套 UI 是为 `seq` 写的，丙要重做** —— 这是丙真正的大头。

## 5. 建议

**甲做阶段 1，丙做阶段 2 的目标，乙跳过。** 三条理由：

1. **甲当场兑现「不依赖外部服务器」**，且协议零改、一致性零改、判据可本机自验（两个进程 ＋ 环回）；
2. **甲的发现层是丙原封不动要复用的那块砖**（F5）⇒ 先做甲**不浪费**；
3. **丙是唯一「减少机制」的那一档**（删号牌、删账本）⇒ 长期维护成本反而低；把 HLC ＋ per-peer 水位
   当成「阶段 2 的第一片」，与 CRDT 冲刺的节奏同形（先纯函数 ＋ 判据，再接线）。

**B 片（二维码 / 短码 PAKE 搬公开材料）与这三档全部正交**，应当独立并行 —— 它是
「零服务器 ＋ 立刻可验」的那一件，而且**甲和丙都要用它做配对**（F6 之下，配对的信任根就是
E2EE 的公开材料本身：有空间钥匙才读得懂内容，所以局域网链路**不需要**公网令牌那套）。

## 11. 丙 上线之后：**使用场景**（用人话，拍板与验收时看这一节）

先说总口径：**台数今天就没有上限**（N 台各自与中枢换增量），所以丙 改的**不是「能接几台」**，
而是把「**必须有一个地方发号牌**」这件事整条删掉。下面每一格的差别，都能追回同一句：
**「中枢在不在」不再是同步能不能发生的条件。**

### 11.1 会变得不一样的（用户真能感觉到的）

| # | 甲档（今天） | 丙 档 | 用户看到什么 |
|---|---|---|---|
| S1 | 网里必须**有一台常开设备**当中枢；它关机 / 合盖 ⇒ 同网段同步**暂停** | 没有「中枢」这个角色 | 两台都合盖再打开，照常接着同步 —— 不用再约定「谁的电脑不关」 |
| S2 | 中枢＝权威，别的设备围着它转 | 中枢**可以留着**，但降级成「一直在的搬运工」 | 家里那台旧笔记本可以继续常开（省电、少握手），它掉线**不再是一条事故** |
| S3 | 号牌由服务端 / 中枢发，一次一个 | 每条记录自带 `(毫秒, 计数器, 设备号)` | 增量**到达顺序不再要求一致**；谁先连上、谁后连上都不影响最终结果 |
| S4 | 离线设备要「连上中枢」才能并增量 | 两台设备**直接**交换增量 | 高铁上改了三天，回来同一个 Wi-Fi 下直接并 |
| S5 | 「同一笔经两条路到达」不会发生 | 会（网状里天然会） | 由**幂等**兜住：同一版再来一次一字不变（不弹重复、不翻倍） |

### 11.2 不会变的（**别读强**）

- **冲突不会消失**。同一段内容两台同时改仍然是冲突。丙 换的是「谁更新」的**判据**
  （`seq` → HLC 戳），**不是**「没有冲突」。而裁决 UI（`dirty`、待取回存档、冲突提示）是
  **为 `seq` 写的** ⇒ 丙 要**重做**它：这是丙 真正的大头（§4 最后一条），**本片没碰**。
- **不承诺**跨网段 / NAT 穿透 / 中继 / Web 参与（§7）。局域网够不着，仍然显式回落。
- **「看上去更新的那版」与「真实时间」会分家**：戳里的毫秒是**设备自己的表**。表被拨到未来的那台，
  它的改动会在很长一段时间里压过别人 —— **收敛（大家一致）不受影响**，但「谁更新」是按戳走的，
  **别把 HLC 当时间审计**。这条边界在判据里专门钉了一格（§12 的「表偏 ±1 小时」）。
- **不是免费的**：每条过网记录多存一列版本戳（可比、可索引的文本），水位从 per-workspace
  推广成 **per-peer**，附件要能回答「跟谁要哪份」。

### 11.3 三个具体到可以照着演的场景

**场景一：两个人的咖啡馆（两台笔记本，网里没有服务器）**
A 与 B 被发现层认出来（甲-1 那块砖）。A 改了第 3 页的标题、B 改了同一页的另一段。
两条线 A→B、B→A 各送自己的增量：到达顺序无所谓（S3）、重复也无所谓（S5）。
两边打开都是「两处改动都在」，而**这个过程里没有任何一台在发号牌**。
A 先走了，B 继续改；第二天在办公室又遇上 ⇒ B 把昨天那段一起给 A。
因为戳跟着记录走，「上一次同步到哪」这个**全局**水位不再是必需品（那一格变成 per-peer）。

**场景二：家里那台旧笔记本还开着（中枢降级）**
这台机器今天在甲档里是权威。丙 里它仍是网里的一员，只是**碰巧一直在**。
它掉线 ⇒ 另外两台照样互相同步（S1/S2）；它回来 ⇒ 收下错过的那几条，凭戳自己算赢家。
★ **本片的判据就是这条**：同一批消息，「直连」与「经中转者」两趟（**连投递顺序都不同**）
算出来的投影**逐字节相同**（§12）。

**场景三：三个人开会（手机 ＋ 平板 ＋ 笔记本）**
三台互相发现、各自发增量。没有「谁先连上」的要求，也没有「谁当主机」的选举。
散会之后每台都是同一份内容。

### 11.4 一句话回答「为什么值得做」

甲档把「不依赖外部服务器」当场兑现了，但它**依赖网里有一台不关机的设备**；
丙 把**那最后一台**也删掉了 —— 代价收敛在「裁决 UI 重做」这一件上（§4）。
