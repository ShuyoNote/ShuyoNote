> 状态：**施工单**（2026-09-18）。上位文档：[全量 CRDT 冲刺计划](2026-09-18-crdt-full-migration-plan.md) §3 阶段 0。

> 纪律：**独立分支**（建议 `spike/crdt`）、**不合并、不动 main**；结论必须带**被验 commit**（见 `development.md` §10.5）。

## 0. 先钉版本（否则结论不可信）

| 项 | 要求 |
|---|---|
| Lexical | 仓库现用 **0.50**（`质谱青言` 读到，另见 `package.json`）⇒ **`@lexical/yjs` 版本必须与它同源** |
| Yjs | 钉死具体版本并**写进 spike 分支的 package.json**（不要 `^`），否则"当时能跑"无法复现 |
| 样本 | 用**仓库自制**页面样本（不引外部库、不用真实用户数据） |

## 1. 问题一：`content_json ⇄ ydoc` 双向转换可靠吗

**做法**：取**覆盖面最大**的真实结构做往返（不是只试一段纯文本）——至少含：
**分栏（每列独立子编辑器）· 表格 · 代码块 · 公式（块级/行内）· Mermaid · 块引用 · 页面链接 · PDF 批注引用（`pdf://`）· 附件卡片 · 数据库视图块**。

两个方向都要测：
- `Lexical JSON → ydoc → Lexical JSON`
- `ydoc → JSON → ydoc`（第二条防"只能单向"）

**判据**：往返后 ① **编辑器渲染一致**（人工目视）② `content_text` 一致（可自动断言）
③ **节点类型/属性不丢**（若某类型丢失或变形，逐个记下来）。

**产物**：**"往返不等价的节点类型清单"**——这张清单的**长度**就是 C 的真实难度刻度。

## 2. 问题二：ydoc 下**下游**还等价吗

**做法**：同一页在 **JSON 路径**与 **ydoc 路径**下，各跑一遍下游并比对：
导出 HTML / **导出 PDF**（**含我们刚修的那条：图片与网址书签不许为空**）· Markdown 往返 · 整库备份 zip · **每页 50 份版本历史**的写入与回滚。

**判据**：产物**逐项等价**（PDF 那条要比对"有没有图片/书签"，不能只看有没有报错）。

**产物**：差异清单（哪一条不等价、差在哪）。

## 3. 问题三：**E2EE 下的加密快照**可行吗（这条最难）

**背景**：服务端**看不懂内容** ⇒ 它**无法替你压缩 update 链** ⇒ 只能由客户端定期产出**加密快照**。

**做法（草案，spike 里验证可行性即可）**：
1. **每条 update 独立加密**：复用现有 AEAD（`crypto.rs`），**但必须带版本号**——这就是**尚未完成的 P0**；
   spike 里先用"临时版本字节"验证链路，**结论里明确写"依赖 P0"**；
2. **加密快照**：客户端把当前 ydoc 全量状态序列化 → 加密 → 上传；服务端只存 **快照 ＋ 之后的 update 链**；
3. **收敛断言**：两个客户端**只凭"快照 ＋ update 链"**（模拟其中一方长期离线）能收敛到**同一状态**；
   且**全程服务端只见密文**（断言服务端侧拿到的字节不含明文特征）。

**判据**：① 收敛成立（同上）② 服务端只见密文 ③ 快照格式能表达"版本 + 算法 + 保留策略"。

**产物**：**加密快照格式草案**（字段 / 版本 / 保留策略 / 轮换时旧 update 怎么办）＋ 一段可重跑的收敛断言。

## 4. 结论怎么交（**一句话，带被验 commit**）

```
CRDT spike @ <commit>: 转换=ok|fail   往返等价=ok|fail   加密快照=可行|不可行
  转换失败的节点类型：<清单>
  下游不等价的项：<清单>
  加密快照：<依赖 P0 的具体点>
```

**任一为 `fail` 都接受**——那就**停在中途**（A 或 B），并把结论写回
[冲刺计划](2026-09-18-crdt-full-migration-plan.md) §6「触发与退出条件」。spike 的价值在于**早点知道**。

## 5. 谁跑（**这条决定了排期**）

| 问题 | 跑在哪 | 为什么 |
|---|---|---|
| 一（转换）与二（下游） | **前端 / Node** ⇒ **Windows 本机就能跑**（vitest/脚本） | 不依赖 Rust 工具链 |
| 三（收敛断言） | 若落在 **Rust 侧** ⇒ **AMD(WSL2) / Mac** | **Windows 跑不了 `cargo test`（`0xC0000139`）** |

⇒ **建议**：把问题三的收敛断言**尽量写在 Node 侧**（Yjs 本身是 JS 库！）——这样 **Windows 也能自验**，
只把"与生产 `sync.rs` 真实对接"那一段留给 AMD/Mac。**这一条能把 spike 周期压掉一半。**

## 6. 不做什么（防止 spike 变味）

- ❌ 不动 `main`、不合并、不改生产协议（除非是为了验证而加开关，且开关默认关）；
- ❌ 不用真实用户数据做样本；
- ❌ 不在 spike 里顺手"把 C 做一半"——**spike 的成功标准是"给出读数"**，不是"代码量"。
