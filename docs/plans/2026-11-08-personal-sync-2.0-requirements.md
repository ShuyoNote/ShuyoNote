# 个人版同步 2.0（Sync Core）需求说明书

> **状态：实施中（代码/判据大部分已落；真机验收与后续优化见 §12 与状态文档）** ｜ 2026-11-08 起 ｜ 范围：个人付费订阅版的局域网同步、私有中继、后台常驻与 MCP 边界
> **一句话**：没有中继服务器时，局域网同步和本机 MCP 必须完整可用；付费用户想要跨网，用官方安装包在**自己的服务器**上私有部署中继。
> **效果图**：[效果图索引](personal-sync-2.0-mockups/index.html)（01 默认局域网 / 02 连接体检 / 03 私有中继 / 04 后台与 MCP）

## 0. 背景与结论

- 官方 iroh 公共中继服务受资质/运营限制，当前无法开通；
- 电信增值业务资质获取困难，本产品**不运营公共中继**；
- 个人付费订阅版：提供中继安装包与许可证，由用户**私有部署**；
- 因此个人版必须做到：**LAN-first，中继可选；MCP 本机优先、不依赖中继**。

## 1. 目标与非目标

### 1.1 目标

```text
G1 无中继时，同 Wi-Fi/同网段可发现、可同步、可关窗后台同步
G2 无中继时，本机 MCP 完整可用；MCP 生命周期与同步/中继解耦
G3 中继故障不得降低局域网可用性（P0 不变量）
G4 付费用户可用官方安装包私有部署中继，跨网同步；直连优先、中继兜底
G5 同步状态可读、可诊断、可重试；大文件可续传
G6 P3：常驻 Sync Core + 单 QUIC 端点 + 块级 CRDT，形成长期底座
```

### 1.2 非目标

- ⛔ 不运营公共 iroh 中继；
- ⛔ 不承诺“私有部署中继就规避所有备案/资质”——合规责任在部署方；
- ⛔ 不在无 UI 时静默执行危险写；
- ⛔ 不为了“感觉快”而无限提高轮询频率；
- ⛔ 不在公网跨网真机验收前对外宣称跨网已可用。

## 2. 用户与模式

| 模式 | 用户 | 服务器 | 能力 | 默认 |
|---|---|---|---|---|
| A 局域网模式 | 所有个人版 | 不需要 | 发现/同步/附件/后台/MCP 本机 | ✅ 默认 |
| B 私有中继 | 付费订阅有跨网需求 | 用户自己的云主机/NAS | 跨网同步，LAN 优先 | 可选 |
| C 手动/VPN | 高级用户 | 用户已有 VPN/公网地址 | 手动地址/VPN 直连 | 可选 |

## 3. 总体架构

```text
Tauri App（UI）
  │ IPC
  ▼
Sync Core（P3 常驻 daemon；P1 可先为托盘常驻 App）
  ├─ SQLite / 空间库 / 版本历史 / 附件库（唯一长期写者）
  ├─ 设备身份 / 信任 / 许可证
  ├─ 发现：mDNS + UDP + 手动端点 + IPv6 + 多网卡
  ├─ 传输：LAN 直连优先（HTTP/QUIC）；私有中继仅兜底
  ├─ 同步：P1 页级；P3 块级 CRDT + 反熵 + dirty 通知
  ├─ 附件：内容寻址 + 分块 + 断点续传
  ├─ MCP host（默认在 App；可选迁入 daemon）
  └─ 诊断 / 审计 / 健康检查
```

## 4. 功能需求

### FR-1 发现（P1）

- mDNS/Bonjour 作为主发现通道；UDP 广播保留兼容；
- 手动添加 `IP:端口`；支持一次性邀请链接/文件（不含页面内容）；
- 公告携带实际监听端口与短标识；端口被占时回退候选；
- 多网卡/VPN 时能显式选接口；网络切换后重播；IPv4/IPv6；
- 发现失败必须给原因（监听失败/被挡/对端旧版本/无设备）。

**验收**：同 Wi-Fi 自动发现；关闭广播模拟后被挡时，手动地址可连；网络切换 30s 内重新出现。

### FR-2 传输与路径选择（P0/P1/P2/P3）

- **P0 不变量**：中继未配置/不可达时，LAN 同步不受影响；LAN 候选不得被 relay 路线表摘掉；
- 路径优先级：`LAN 直连 > 手动 LAN 地址 > 旧 HTTP fallback > 私有中继（仅跨网/直连失败）`；
- P3：一台设备一个 QUIC/iroh 端点，多空间多 stream；LAN 直连不经过 relay 许可门；
- 私有中继只作为跨网/打洞失败兜底；直连成功时不产生中继流量。

**验收**：

```text
relay 服务器关机 + 配了路线表 + 两机同 Wi-Fi ⇒ LAN 同步成功，无 20s relay 重试拖住整轮
同网时 relay 流量 = 0；跨网直连失败才出现中继流量
```

### FR-3 同步调度（P1/P3）

- 本地编辑后发 dirty 通知（只带“有变化”，不带正文），对端秒级拉取；
- 空闲保持 30–60s 反熵；Wi-Fi-only/电池策略；
- 多对端/多空间有界并发（2–4），单台失败不连坐；
- “全部空间立即同步”、失败一键重试、暂停 N 小时；
- P3：操作日志 + 反熵 + 断点；后台轮次不依赖窗口。

**验收**：本地改动 p95 < 2s 到达；丢包 30% 下不丢数据；对端离线回来自动补齐。

### FR-4 空间身份与冲突（P1/P3）

- P1：按空间状态显示（已同步/差几页/锁着/对端旧版本）；
- P3：稳定 space/room 身份，不再只按名字匹配；同名空间不再自动触发融合提示；
- P3：普通笔记页块级 CRDT；不同块自动合并；同块同位置才提示；
- 旧页迁移：双写 → 影子比对 → 灰度 → 默认；保留旧格式 fallback。

**验收**：同名空间不互相串；两台同时改不同段落 0 人工裁决；同段冲突可回滚；逐页 sha 一致。

### FR-5 附件（P1/P3）

- 内容寻址 + FastCDC 分块 + 清单；
- 只请求缺块、断点续传、进度/取消/重试、去重；
- 先元数据后字节；大文件不阻塞小页面同步；
- 缺失字节显示“不在本机”占位，可重试取回，不回落外机绝对地址。

**验收**：1GB 附件中断后续传成功；重复附件不重复占空间；缺失附件有可操作提示。

### FR-6 后台常驻（P1 托盘 / P3 daemon）

- P1：关窗不退出（托盘常驻）；真正退出才停；开机自启可选；
- P3：Sync Core daemon 独立于 UI；单实例、崩溃自恢复、睡眠/唤醒、更新重启；
- 托盘显示：同步中/已暂停/直连/中继/错误；
- 设置：关窗行为、开机自启、电池省电、仅 Wi-Fi 自动同步。

**验收**：关窗后另一台收到改动；退出后停止；崩溃后自动恢复且不丢数据。

### FR-7 MCP（P1/P3）

- MCP 是本机回环能力：`127.0.0.1 + token`，只绑回环；
- **不依赖中继/登录/同步**；同步暂停、中继不可用、LAN 断开时仍可启动/调用；
- 默认 MCP 在 App；关窗后 MCP 不可用（V1 可接受）；
- 若需“关窗/退出后 MCP 仍可用”：
  - 方案 A：App 托盘常驻（优先，低成本）；
  - 方案 B：P3 迁入 daemon（需单独拍板）；
- 无 UI 时：只读工具可用；危险写**默认拒绝**；依赖前端桥的工具回“需要打开窗口”；
- 单 host、单 token、单审计；禁止 App 与 daemon 各开一个。

**验收**：没有中继、没有网络、同步暂停时，MCP 只读工具仍可调用；危险写在无 UI 时被拒绝并留审计。

### FR-8 私有中继（P2）

- 官方安装包：Linux `tar.gz + install.sh`（systemd），Docker 随后；
- 许可证：订阅/设备位/到期签名；离线宽限；到期只收回跨网；
- 客户端配置：中继 URL + 凭据 + 测试连接 + 状态；
- 中继只转发、不解密内容；用户自己的服务器；
- 文档：部署、TLS/反代、防火墙端口、升级、回滚、合规提醒。

**验收**：按安装包部署 → 客户端测试通过 → 跨网同步；同网仍优先直连；中继关闭 LAN 不受影响。

### FR-9 诊断（P1）

- 连接体检：接口/IP、发现端口、同步窗口、系统代理、对端 TCP 可达、配对秘密、房间匹配、最近一轮；
- 一键复制脱敏诊断包（不含正文/令牌/秘密）；
- 手动添加设备、重新体检、失败重试；
- 每空间/每对端上次同步时间与结果。

### FR-10 安全/隐私/合规

- MCP 只绑回环 + token + Origin/Host 校验；
- 传输加密；私有中继不解密内容；
- 危险写（删除/覆盖）需确认；无 UI 时拒绝；
- 后台 MCP 默认关；托盘可见；空闲自动停；
- 不运营公共中继；用户私有部署的合规责任在部署方/owner 法务确认。

## 5. 分阶段与验收闸门

### P0｜解耦与不变量（1–2 周）

- relay 路线不再摘 LAN；LAN 优先；直连不经过 relay 许可；
- 默认构建无 relay 依赖；
- 测试：relay 关闭 + 路线表 + 同网 ⇒ LAN 成功；
- 设置拆分「局域网同步」与「跨网中继」。

**出口**：中继故障不影响 LAN；旧行为可回滚。

### P1｜局域网基础体验（2–3 周）

- mDNS + 手动地址 + 端口/多网卡/IPv6；
- 并发、dirty 通知、全部空间同步、附件初版；
- 托盘常驻、关窗继续；
- 连接体检 + 诊断包；
- MCP 启动与同步/中继解耦；
- 效果图 01/02/04。

**出口**：无中继、无服务器时，同 Wi-Fi 同步 + 关窗同步 + MCP 本机可用。

### P2｜私有中继（2–4 周）

- 官方安装包、许可证、客户端配置/测试；
- 跨网真机验收；LAN 优先；中继兜底；
- 效果图 03。

**出口**：付费用户私有部署可跨网；中继故障 LAN 正常。

### P3｜架构升级（4–6 周+，可与 P2 部分并行）

- P3-1 Sync Core daemon（单 DB 写者、IPC、托盘、睡眠/唤醒/更新）；
- P3-2 一台设备一个 QUIC/iroh 端点；LAN 直连无 relay；多 stream；旧 HTTP fallback；
- P3-3 普通笔记页块级 CRDT；双写/影子/灰度/回滚；稳定空间身份；
- P3-4 附件分块与实时通知收尾；
- P3-5 MCP 迁入 daemon（可选，需单独拍板）。

**出口**：关窗/退出 UI 后同步继续；冲突大幅减少；一套传输/一套 DB/一套审计；可回滚。

## 7. 非功能指标

```text
空闲 CPU < 1%（后台）；内存可控；不因 10 个空间每 30s 广播造成明显耗电
```

## 8. 待 owner 拍板（白话版）

> 每条给选项与推荐；沉默默认取推荐（零风险选项）。
>
> **2026-11-08 owner 已按推荐拍板：DEC-1～DEC-6 全选 A。** 实施以本文件＋[P3 落地 ADR](2026-11-08-personal-sync-2.0-p3-adr.md) 为准；ADR 里新增的 DEC-A..E 是 P3 实施前要再拍的 5 项，不改变本次 6 项拍板。

### DEC-1｜默认局域网传输先走哪条？

- **A（推荐）**：保留现有 HTTP，先加 mDNS/手动地址/并发/诊断；P3 再上 QUIC 直连。
  - 好处：2–3 周见效、兼容旧版、风险低；
  - 代价：暂时没有“一台设备一个 QUIC 端点”的最终形态。
- **B**：直接上 QUIC 直连（LAN 无 relay），旧 HTTP fallback。
  - 好处：一步到位、延迟更低；
  - 代价：发现/兼容/测试量更大，P1 可能延后。
- **沉默 ⇒ A**。

### DEC-2｜后台形态先做哪一档？

- **A（推荐）**：先做“App 托盘常驻”（关窗继续，退出停）。
  - 好处：1–2 周、风险低、MCP/前端桥零迁移；
  - 代价：真正退出 UI 后不同步。
- **B**：直接做独立 Sync Core daemon（退出 UI 也同步，CLI/多端复用）。
  - 好处：最终形态；
  - 代价：3–4 周+，打包/签名/托盘/更新复杂。
- **沉默 ⇒ A，P3 再升 B**。

### DEC-3｜是否把个人版普通笔记页迁到块级 CRDT？

- **A（推荐）**：P3 做，双写/影子/灰度，普通笔记页先迁；数据库页/属性/附件元数据后续。
  - 好处：冲突大幅减少、只传改动、实时基础；
  - 代价：4–6 周、数据迁移风险，需要版本历史/回滚。
- **B**：暂不迁，只优化页级冲突提示。
  - 好处：便宜；
  - 代价：冲突/整页覆盖问题仍在。
- **沉默 ⇒ B（维持现状，不冒数据迁移风险）**。

### DEC-4｜私有中继的交付边界？

- **A（推荐）**：官方安装包 + 许可证，用户自己部署；我们不运营公共中继。
- **B**：我们运营公共中继（需要资质/成本，当前不建议）。
- **C**：不做跨网，只做局域网。
- **沉默 ⇒ A**。

### DEC-5｜MCP 的后台策略？

- **A（推荐）**：V1 MCP 留在 App；关窗不可用（与今天一致）；若只要关窗可用，DEC-2 选 A 托盘常驻。
- **B**：托盘常驻，关窗 MCP 可用。
- **C**：P3 迁入 daemon，退出 UI 也可用（需无 UI 危险写拒绝策略）。
- **沉默 ⇒ A**。

### DEC-6｜私有中继是否默认勾选/自动启用？

- **A（推荐）**：默认不启用；用户配置后才启用；LAN 永远优先。
- **B**：订阅用户默认启用（跨网更“无感”）。
- **沉默 ⇒ A**。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| CRDT 迁移丢数据 | 双写、影子比对、逐页 sha、版本历史、灰度、回滚 |
| 中继故障拖垮 LAN | P0 不变量 + 测试：relay 关闭时 LAN 必成功 |
| 后台常驻耗电/安全 | 空闲退避、Wi-Fi/电池策略、托盘可见、MCP 默认关 |
| 打包/签名/更新 | daemon 稳定路径、随 App 更新、公证/登录项/防火墙一次做 |
| 私有部署合规 | 用户协议+合规提醒；不运营公共中继；法务确认 |
| 旧客户端不兼容 | 版本协商、旧 HTTP fallback、对端旧版本提示 |

### 12.2 后续优化（按优先级；全部**未开工**，开工时把状态改成“已做”并补判据）

#### P0（影响验收正确性，建议先做）

```text
1) 影子看门“每天至少扫一次”＋差异来源分类
   问题：只在页面/空间变化时扫描 ⇒ 空闲日不写历史 ⇒ 7 天观察凑不齐；
         differ 分不清“正常差异（MCP/裁决写投影、不动 CRDT）”与“异常差异”。
   目标：跨天必落一条；差异按来源（编辑器/MCP/裁决/导入）分类，只有前者计入 0 差异考核。
   判据：连续 7 天每天都有记录（含空闲日）；分类字段齐；差异趋势可查；坏 JSON 不假装无记录。

2) 「同名不同 uid 确认」做成双向握手
   问题：现在确认只在本机生效 ⇒ 本机吸收对端，对端仍拒收 ⇒ 单向半通，用户要两头手点、容易漏。
   目标：确认后随同步/公告把“身份对齐”带到对端（或对端自动记确认），一次确认双向放行。
   判据：只在一台点确认 ⇒ 双向融合各一次；UI 明确提示“另一台会自动生效”；对端未升级时不假装成功。

3) 附件按需下载走 QUIC 的**大文件/续传**
   问题：QUIC 路径整包缓冲（≤64MB），大附件内存峰值高；Range 续传只有 HTTP 路径有。
   目标：QUIC 也分块流式（边收边写 .part），与 HTTP 共用同一份续传/暂停/取消状态机。
   判据：≥64MB 文件 QUIC 下载成功且内存峰值有上限；暂停→续传、取消→保留 .part；落盘 sha256 一致。
```
