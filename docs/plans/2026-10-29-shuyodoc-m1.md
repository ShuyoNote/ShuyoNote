## 范围（M1 只做这些）

- **导出**：一篇笔记 → 一个 `.shuyodoc`（zip）。包内：
  ```text
  document.shuyodoc
    manifest.json      # format/version/id/title/created/updated/assets 清单
    content.json       # Lexical 块 JSON（保留块 id）
    assets/<sha256>.<ext>
  ```
  ⛔ 不带 `comments.json` / `versions.json`（格式里留着可选字段，v1 不写）。
- **导入**：选一个 `.shuyodoc` → **新建一篇笔记**（新 id），附件按 sha256 落库去重。
  ⛔ 不覆盖、不合并（同名也新建，标题可加「(导入)」后缀）。
- **不做**：空间包、评论/历史、签名（`signature.json`）、覆盖导入。

## 导入侧必须挡住的（整个包拒绝，不部分导入）

1. zip-slip：条目名含 `../`、绝对路径、盘符；
2. `manifest.json` 缺失 / JSON 坏 / `format` 不等于 `shuyonote.document` / 版本未知（⛔ 不猜）；
3. `content.json` 缺失或不是合法块 JSON；
4. 资产 sha256 与文件名不符（内容寻址自证）；
5. 同名资产不同内容（同 sha 不同字节 ⇒ 拒绝并报哪个文件）；
6. Windows 大小写冲突 / 非法字符 / 超长路径；
7. 单文件或总大小超限（上限待定，先按 200 MB 总、50 MB 单文件）。

失败一律**如实报**「哪个条目、为什么」，⛔ 不静默跳过、⛔ 不"导一半"。

3. **判据**：往返——导出→导入→再导出，`content.json` 语义等价、资产 sha 全对、标题与块数不丢；恶意包 5 类全部拒绝且错误信息点名条目。
4. **接线**：页面右键「导出为 .shuyodoc」＋ 文件区「导入文档包」（新页面）；走 Rust 侧既有附件写入路径（⛔ 不新造第二套写库）。
5. 每步跑 `pnpm verify`（默认组）＋ 新增判据，合 `dev` 前给读数。
