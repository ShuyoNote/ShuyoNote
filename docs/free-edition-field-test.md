# 免费版上门实测清单（**两台真机**）

> 面向**执行实测的人**。目标只有一个：验「**免费版 ＝ 本地全功能 ＋ 局域网设备直连（零账号、不经我们任何服务器）**」。
> ⚠️ **这一页是"人手验收"** —— 机器跑不出来（要两台真机、真网络 ✓）；⛔ **不许把本页当成"已通过"** ✗，

## 0. 准备（10 分钟）

| 项 | 要求 |
|---|---|
| 设备 | **两台**（最好一台 macOS／一台 Windows —— 跨平台才是真场景） |
| 网络 | **同一个 Wi-Fi**（⛔ 不要用访客网络／酒店网络 —— 它们常开 AP 隔离 ✓） |
| 安装包 | 走 CI 产物（GitHub Actions 的 `release`／`macOS (build)`／`Android (build)`） |
| 版本 | 记下两台的**版本号**（面板或「关于」里） |
| 备份 | ⚠️ 在一台**空的或可弃的**空间上做第一轮（下面的步骤会改数据） |

> ⭐ **最快的"网络行不行"预检**：两台都 `ping <对方 IP>` —— 通了再往下做，不通先看排障指引 §1 ✓。

## 1. 逐条步骤（每条都有"通过的样子"）

| # | 做什么 | 通过的样子 | 失败 ⇒ 取什么证据 |
|---|---|---|---|
| **1** | 两台各建（或导入）**同一个空间** | 两边都能打开、内容一致 | 空间名、导入方式（配对码／导出包） |
| **2** | 两台都开**设备直连**：监听地址填 **`0.0.0.0:8788`** | 面板不显示「尚未绑定」 | 面板那一行原文 |
| **3** | ⭐ 两台各设一个**窗口口令**（≥8 字符、非纯数字） | **保存成功** | 面板「口令：已设」 |
| **4** | ⚠️ **反向验一次**：把口令改成 `123456` | **被拒**，且理由里说清"未加密时它是唯一防线"＋给出路 | 报错原文（**这一条验的是本轮新加的口令强度** ✓） |
| **5** | 等**一轮广播**（30 秒级；真机读数可能≈45 秒） | 面板出现「**附近发现 1 台**」 | 面板原文（含"还见过 N 台"那句） |
| **6** | 在 A 上改一页 → 在 B 上切换页面／等一轮 | **B 看到 A 的改动** | 时间戳、两边那一行 |
| **7** | ⭐⭐ **拔掉外网**（路由器 WAN 断掉／关掉 A 的默认网关），只留局域网 | **同步仍然工作** | ⭐ 这是"**不经服务器**"的**硬证据** —— 记下两台的同步时间 |
| **8** | （可选，最强）在两台上抓包（Wireshark／`tcpdump`），只做第 6 步 | **没有对外（公网）连接** | 抓包文件 |
| **9** | ⚠️ **反向验网络**：把 B 连到**另一个** Wi-Fi（不同网段） | **发现不到**，且**排障指引能定位**（ping 不通 ⇒ §1① 或 §1②） | 两台 IP、ping 结果 |
| **10** | （可选）在**访客网络／企业 Wi-Fi** 上重复第 5 步 | 大概率**发现不到**（AP 隔离／禁广播） | 网络类型 ＋ 面板原文 |

## 3. ⚠️ 已知会失败的四种（**不是缺陷**，别记成 bug）

```text
① **跨网段／跨地点**（不同子网、两个人各自在家）⇒ ⛔ 我们**不做**跨网段／NAT 穿透／中继 ✗
   ⇒ 要跨地点只有两条路：**自架虚拟局域网**（Tailscale 等）或**自架同步服务器** ✓
② **访客 Wi-Fi／酒店／企业 Wi-Fi**（AP 隔离 或 禁广播）⇒ 发现不到
   ⭐ 这是**网络策略**，不是产品坏了 —— 最快的验证是**换手机热点**再试 ✓
③ **防火墙拦入站**（"看得见、拉不动"）⇒ 见排障指引 §2① ✓
④ **虚拟网段**要用 `100.64-127.x` 那个地址（Tailscale 默认段已放行 ✓）或直接填 `0.0.0.0` ✓
```

## 6. ⭐ 逐台解除（U11）—— 2026-10-02 新增，**两台真机**才能看到

```text
为什么必须真机：那一块**只在"这台机器真的认了设备"时才出现** ✓ —— 一台机器上永远看不到它 ✗。
前置：两台你自己的设备（甲／乙），**同一个空间**，都装这一版 ✓。
```

| # | 做什么 | **通过的样子** |
|---|---|---|
| 1 | 甲：同步面板 ⇒「把这台设备接进来」⇒ **生成投放码** | 出一段码 ✓ |
| 2 | 把那段码交给**乙**（自己那台 ✓）⇒ 乙里粘贴 ⇒ **先看比对码** | **两端逐位相同** ✓（不同 ⇒ 停在"停"态 ✓，那是**对的** ✓） |
| 3 | 乙：点「我核对过了，采纳」 | 乙说「已配对」✓ |
| 4 | ⭐ 甲／乙再看同步面板 | 出现「【要点】这台机器认了 **1** 台设备…」✓ ＋ 一行 `设备 XXXXXX · 配于 2026-10-02 14:03` ＋ 一颗「解除」✓ |
| 5 | ⭐ **盯这四处**（都是 2026-10-02 特意改的 ✓） | ① 那一串是 **6 位大写短码**（如 `EF8DB8`）✓ —— ⛔ **不是**设备号／IP ✗<br>② 时间是 `YYYY-MM-DD HH:mm` ✓ —— ⛔ **不是** `9/28/2026, 2:03:00 PM` ✗<br>③ 提示里**没有** `**` 星号 ✓ —— 出星号就是老版，记 bug ✓<br>④ 那一行**只有一颗**按钮（解除）✓ |
| 6 | 点「解除」 | 那一行**消失** ✓ ＋ 底下多一句「还认 0 台。已解除这一台：它现在拉不动你了…」✓ |
| 7 | ⭐⭐ **真正的验收**：乙**再同步一次** | ⛔ **拉不动** ✓（如实报错，⛔ 不静默成功 ✗） |
| 8 | ⭐ 若你还有**第三台**（丙，也配过） | **丙照常能拉** ✓ —— 这一条才是"**逐台**"的意思 ✓（⛔ 若丙也拉不动了 ⇒ 那是"换口令"那个旧办法 ✗，记 bug ✓） |

⚠️ **两条如实写的限制**（⛔ 别当成 bug ✗）：

```text
① **短码不能跨端比对** ✗ —— 它是从"**本机看到的对方设备号**"派生的 ✓
   ⇒ 甲上看到的是"乙的码"、乙上看到的是"甲的码" ⇒ **两端不一样** ✓（这不是哈希、也不是校验码 ✓）
   ⇒ **认台只能靠时间**（＋台数）✓ —— 想要"两端对得上"，那是配对流程里**比对码**的活 ✓
② 短码**不是安全凭据** ✗ —— 它只用来"认得出是哪一台" ✓（决定权仍在"谁能碰到这台机器" ✓）
```
