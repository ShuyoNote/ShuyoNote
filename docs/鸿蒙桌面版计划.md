# 鸿蒙桌面版开发计划（方案 1：ArkWeb 壳 + 原生同步客户端 + 可替换数据层）

目标：用 HarmonyOS NEXT（ArkTS/ArkUI）做一个**能浏览/编辑/同步**的鸿蒙桌面版，复用现有 Web 版（编辑器/Lexical/sql.js 数据），同步用 ArkTS 原生客户端对齐全桌面同步协议。

> 关键事实（调研确定）：
> - Web 版**不实现同步**（`web.ts` 的 `sync_now`/`sync_workspace` 是"不支持"的 stub）——同步只在桌面 Rust（`src-tauri/src/sync.rs`）。
> - 因此鸿蒙版同步必须**原生实现**（ArkTS 调 sync-server），与桌面/Rust 同一协议。

---

## 阶段 0：环境 + 可行性验证（POC）
**目标**：确认 ArkWeb 能跑通 Web 版核心能力，扫清风险。
- 环境：DevEco Studio + HarmonyOS NEXT SDK（API 12+）
- 最小 ArkWeb 壳：窗口 + `Web`/`ArkWeb` 组件加载一个 URL
- 关键验证点：
  - ArkWeb 对 **WASM（sql.js）** 的支持
  - ArkWeb 的 **IndexedDB / localStorage**（Web 版数据存储）
  - **长文本输入 / 编辑器焦点**（Lexical contenteditable）
  - **桌面窗口**（PC 窗口/卡片 + 缩放）
- **交付**：一个能打开、能输入、能落库的 ArkWeb 壳 POC
- **工作量**：小；**风险**：WASM/IndexedDB/输入法兼容（需先验证，若 ArkWeb 限制大，则转向部分原生）

## 阶段 1：ArkWeb 壳 MVP
**目标**：可用的鸿蒙桌面 GUI（浏览/编辑页面、数据库、看板、关系图）。
- Stage 模型应用 + 桌面窗口
- ArkWeb 加载**本地打包的 dist-web**（离线，避免网络依赖；`base:"./"` 已就绪）
- 基础导航：侧栏（页面树/空间切换）+ 工具栏
- 复用 Web 版全部视图（编辑器/数据库/看板/关系图/搜索）
- **交付**：鸿蒙桌面上可正常打开、编辑、保存（数据在 ArkWeb IndexedDB）
- **工作量**：中（壳 + 导航 + 资源打包）；**风险**：低（复用 Web）

## 阶段 2：ArkTS 原生同步客户端（关键）
**目标**：鸿蒙与其他设备（桌面/Web/其他鸿蒙）互通同步。
- 按桌面 `src-tauri/src/sync.rs` 的协议在 ArkTS 实现 **SyncClient**：
  - **认证**：`POST {server}/auth/register`、`POST {server}/auth/login`（body `{email,password,...}`）→ `token`；`GET /auth/me`、`POST /auth/logout`、`DELETE /auth/account`
  - **空间**：`GET {server}/spaces`、`POST {server}/spaces`；空间/成员/组织（团队版可后续）
  - **推送**：`POST {server}/push`（Bearer token；body `{device_id, last_pushed_seq, changes:[{device_seq,entity,entity_id,op,payload}]}`）
  - **拉取**：`GET {server}/pull?since={seq}&limit=500&space_id=..&exclude_device=..`
  - **增量**：本地 `changes` 表（device_id/device_seq/entity/entity_id/op/payload），推进 `last_pushed_seq`/`last_pulled_seq`
  - **绑定空间**：`sync_profiles`（ws_id/server_url/token/space_id/seq），空间必须绑定
- 登录态存 `auth_sessions`（server_url/email/token）
- **交付**：鸿蒙登录 → 加入空间 → push/pull 跨端一致
- **工作量**：大（客户端 + 协议对齐 + 冲突）；**风险**：中（协议字段/冲突/加密）

## 阶段 3（可选）：数据层替换原生 SQLite + 性能
**目标**：大规模数据下接近桌面性能。
- 数据层抽象：把依赖 sql.js 的部分换成鸿蒙原生 **`@ohos.data.relationalStore`**（SQLite）
- 编辑器/UI 仍可保留 ArkWeb（后端数据走鸿蒙原生）
- **交付**：大库流畅、启动更快、内存更低
- **工作量**：大；**风险**：高（需桥接 ArkWeb 与原生数据）

---

## 建议
1. **先做阶段 0**（POC）——验证 ArkWeb 对 WASM/IndexedDB 的支持，这是**成败关键**（若 ArkWeb 不能跑 sql.js WASM，则方案 1 数据层要改用原生 SQLite，提前知道好调整架构）。
2. 阶段 0 通过 → 阶段 1（壳 MVP）→ 阶段 2（同步）。
3. 阶段 3 按需。
