# 排障：**附近的设备**连不上 / 拉不动

> 面向用户。**适用**：你没绑服务器，只靠「**设备直连**」（同一网络里两台设备互相同步）时。
> ⚠️ 这一页**不是**服务端排障（那见 [`SYNC.md`](SYNC.md) 与自部署仓的 `docs/deploy.md`）。
> ⚠️ 依据：底层是**自研的 UDP 广播发现**（广播到 `255.255.255.255:47821`，每 **30 秒**一轮）
> ＋ 每一台上的 **HTTP 窗口**（默认 `:8788`）。**这两样都只在"同一网络、且网络允许广播"时成立** ✓。

---

## 0. 先看界面上的那一行（它已经告诉了你一半）

「同步」面板底部那一行是**读数**，不是装饰：

```text
同步地址：直连（同一网络）http://192.168.1.5:8788  ｜ 附近发现 3 台
（还见过 1 台，现在不发声了）
```

| 你看到的 | 意思 |
|---|---|
| **`尚未绑定`** | 这一档**还没开** ⇒ 先去填监听地址（或直接写 `0.0.0.0:8788` ✓） |
| **`附近发现 0 台`** | ⚠️ **本页 §1 那三种**最常见（广播出不去／回不来） |
| **`附近发现 N 台`** 但拉不动 | ⇒ 看 **§2**（不是发现的问题，是**能不能连上**） |
| **`还见过 M 台，现在不发声了`** | 那几台**曾经在**、现在收不到了（关机？换网？）—— 只是**事实**，不是诊断结论 ✓ |

## 1. `附近发现 0 台` —— 三件事按顺序排

### ① 你们其实不在同一个网络 ⚠️ 最常见

- **怎么确认**：两台设备的 IP 前三段是不是一样（`192.168.1.x` vs `192.168.1.y` ✓）。
  一台连 Wi-Fi、一台插网线，**很可能**在路由器的不同网段上（甚至不同的 VLAN）。
- **怎么办**：把两台放到**同一个** Wi-Fi（或同一个交换机下）。

### ② 路由器开了「AP 隔离 / 客户端隔离」⚠️ 第二常见

- **是什么**：很多路由器（尤其是**访客网络**、酒店、公共 Wi-Fi、企业 Wi-Fi）会**禁止客户端之间互相通信** ——
  你可能上得了网，但**两台设备彼此看不到**。
- **怎么确认**（在 A 上 ping B 的 IP）：
  - Windows：`ping 192.168.1.5`
  - macOS / Linux：`ping 192.168.1.5`
  ⇒ **ping 不通** ＝ 基本就是它 ✓（或防火墙，见 §2①）。
- **怎么办**：
  · 换到**不开隔离**的网络（自己的手机热点**通常可以** —— 这是个很快的验证 ✓）；
  · 或者登录路由器，把「AP 隔离 / 客户端隔离 / 无线隔离」**关掉**；
  · 或者改用 **§3 的虚拟网段**（Tailscale 等）✓ —— 那条路**绕过**广播 ✅。

### ③ 这个网络**不让广播**（企业网 / 部分 Wi-Fi）⚠️

- **是什么**：公司网络常把 `255.255.255.255` 这类**广播**挡掉（或只允许定向单播）。
- **怎么确认**：同一网络里**别的设备直连工具**（如局域网传输 App）也找不到对方 ⇒ 更像这个 ✓。
- **怎么办**：
  · 用**手机热点**验证一次（能把问题定位到"网络策略"而不是"产品坏了" ✓）；
  · 长期用 ⇒ 走 **§3 虚拟网段** ✓。

## 2. `附近发现 N 台`，但**拉不动**

### ① 防火墙挡了**入站**

发现走的是**广播（出站）**，拉取走的是**对方来连你的 `:8788`（入站）** ——
所以"看得见、拉不动"**非常典型** ✓。

- **怎么办**：
  · **Windows**：首次运行会弹「允许访问网络」⇒ 要选**专用网络 ＋ 允许**；漏了点过的话，去
    「Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙」里把本应用勾上**专用网络**。
  · **macOS**：系统设置 → 网络 → 防火墙 ⇒ 允许本应用接受传入连接。
  · **Linux**：`sudo ufw allow 8788/tcp`（或你改过的那个端口）。
- **怎么确认**：在 B 上访问 A 的地址（浏览器打开 `http://192.168.1.5:8788/`）——
  **通** ⇒ 防火墙没问题 ✓；**不通** ⇒ 基本就是它 ✓。

### ② 口令对不上

界面上那一行写「口令：已设／未设」：

- ⚠️ **未加密的空间里，口令是唯一的防线** —— 所以它**必须**两家**一模一样**，
  而且**新口令有强度要求**（至少 8 个字符、不能纯数字、不能整串同一个字符）✓。
- **怎么办**：两边填**同一个**口令；**改了口令要两边都改** ✓。

### ③ 对端**服务的不是这个空间**

直连是**按空间**建立关系的：A 上开着「空间甲」的窗口，B 上必须也有**同一个空间** ✓。
- **怎么办**：确认两边开的是**同一个空间**（不是"同一个名字"，而是**同一份**空间 —— 换设备时先用
  **配对码**把空间搬过去，见「空间隐私」里的「换设备」✓）。

## 3. 虚拟网段（VPN / Tailscale 等）—— **跨地点**怎么用

虚拟网卡上的地址**不是** `192.168.x`，而是各家的段（**Tailscale 默认 `100.x.y.z`** ✓）。

- ✅ **我们已经放行 `100.64.0.0/10`**（2026-09-30 起 ✓）⇒ Tailscale 默认段**可用** ✓。
- ⚠️ **要填对地址**：填**虚拟网卡上那个地址**（`100.x.y.z:8788`），
  或者干脆填 **`0.0.0.0:8788`**（＝**听所有网卡**，地址由系统报出去 ✓ —— **换网、多张网卡都不用改** ✓）。
- ⛔ 公网地址**一律不收**（安全边界：直连只在自己网段里 ✓）。

---

## 4. ⛔ 我们**不做**什么（免得你白试）

```text
⛔ **不做跨网段 / NAT 穿透 / 中继** —— 你所在的两张网之间如果没有三层可达的路，
   我们**不会**替你打洞、也**不会**替你转发 ✗（这是**架构选择**：数据不经我们的服务器 ✓）。
⇒ 跨地点要同步，只有两条路：
   ✅ **自架虚拟局域网**（Tailscale / WireGuard / ZeroTier …… 见 §3 ✓）
   ✅ **自架同步服务器**（服务端由你自己部署；见 [`SYNC.md`](SYNC.md) ✓）
```

## 5. 一分钟自查清单

| # | 查什么 | 怎么查 | 通过的样子 |
|---|---|---|---|
| 1 | 同一网络？ | 两台 IP 前三段一样？ | `192.168.1.x` ↔ `192.168.1.y` ✓ |
| 2 | 能互相 ping？ | `ping <对方 IP>` | 有回应 ✓（不通 ⇒ §1②／§2①） |
| 3 | 地址填了？ | 面板那一行 | 不是「尚未绑定」✓ |
| 4 | 端口通？ | 浏览器开 `http://<对方IP>:8788/` | 有响应 ✓ |
| 5 | 口令一致？ | 两边都看那一行 | 都「已设」且**同一串** ✓ |
| 6 | 同一空间？ | 两边空间名与内容 | 是**同一份**空间 ✓（换设备用配对码 ✓） |
| 7 | 试过热点？ | 手机热点下再试一次 | ⭐ **能通 ⇒ 是原网络策略（隔离/广播）的问题** ✓ |

## 6. 要贴给支持时，请给这三样

1. **面板那一行的原文**（`同步地址：… ｜ 附近发现 N 台`）；
2. 两台的 **IP**（`192.168.x.x` —— ⚠️ **公网 IP 请隐去最后一段** ✓）、系统与版本；
