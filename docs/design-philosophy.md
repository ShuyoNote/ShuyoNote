# ShuyoNote 设计哲学

> 本文把 ShuyoNote 的核心设计信条沉淀成一份**可执行的指南**，用于指导后续功能走向与取舍。它回答「我们如何思考数据、文件夹、数据库与扩展」；具体方案见 `plans/`，现状见 `roadmap.md`。

## 1. 一句话哲学

**页面是本源，属性是语义，数据库是透镜，文件夹是容器。**

- 页面永远是「能被当作普通笔记编辑的一等公民」；
- 属性是叠加在页面上的**可类型化语义**，但保持松散；
- 数据库是**同一份数据的投影**（视图 + 成员规则），不是新的 schema；
- 文件夹同时是**页面层级容器**与**文件库（网盘）**。

## 2. 根本心智模型

| 概念 | 类比 | 说明 |
|------|------|------|
| 页面 = 行 | 一条记录 | 标题/正文是本体；属性是「元」 |
| 属性 = 列 | 字段 | 带类型（text/number/date/select/multi/checkbox/tag/ref），值按类型解释 |
| 数据库 = 透镜 | 查询/投影 | 视图（表格/画廊/看板/列表/日历/时间轴/目录）+ 成员规则 |
| 文件夹 = 容器 | 项目空间 | 组织页面 + 承载文件（本地/去重/可加密的网盘） |
| 标签 / 引用 | 语义连接 | 催生关系图与反链；数据一次，处处呈现 |

**关键洞察**：视图是**呈现**，不是数据。数据只存在于「页面 + 属性」；改一处，所有视图 / 关系图 / 反链同步。这是「透镜」模型最值钱的地方。

## 3. 核心设计信条

### 3.1 数据库是透镜，不是 schema
- 笔记应用里，「数据库」不应该是把页面降级为行、让页面必须归顺它的实体。
- 正确心态：**数据库叠加在页面之上**，用户把一行「展开」成页面、把页面「折叠」成一行，应无缝。
- **容器 vs 查询**：数据库有「手动集合」（基础）与「动态纳入规则」（如 `状态=进行中 且 标签=工作`）两种成员；走向混合（查询型 / 保存视图）是下一步的威力所在。
- **视图 = 声明式配置**：每视图一套 `{列, 排序, 过滤, 分组}`，存于数据库页；一个库可多个视图。`kind='database'` 页面 + 行内联编辑已朝此方向。

### 3.2 灵活页面 + 共享 schema
- **页面属性**是松散的（`page_props`，按类型解释的 TEXT）——保持笔记自由，可给任意页面加任意属性。
- **数据库列**引用**共享属性定义**（`attr_defs`）——保证同名属性跨页/跨库语义一致（`状态` 列在所有库都是同一套选项/颜色）。
- 分层：`attr_defs`（共享 schema）→ `page_props`（页面值）→ `database_columns`（库列）→ 视图（前端渲染）。

### 3.3 文件夹是容器，不只是层级
- 文件夹既是**页面树层级**，也是**文件库（网盘）**——一个项目文件夹 = 文档 + 相关素材（PDF/图片/表格/压缩包）在一个地方（对齐 FlowUs/Wolai/有道/Quark 的成熟模型）。
- ShuyoNote 的差异化：**本地优先 + 内容寻址去重 + 可选自建同步 +（规划中）端到端加密**。你的文件在你设备的本地存储；去重省空间；无云容量/限速/配额；加密后自建服务器不可读——是**「私有、去重、无限速、可加密的网盘」**，而非公网网盘的替代。
- **文件是一等公民**：文件本身存在于文件夹（可搜索/预览/下载），页面可引用（建立关联）。页面附件（笔记内引用）与文件夹文件库（网盘视角）**并存**。

### 3.4 本地优先与隐私优先
- 数据与附件在本机；附件按**内容哈希**存储、跨页/夹去重；可选自建 sync-server（outbox + LWW + 内容寻址增量）；M2 端到端加密后服务端不可读。
- **不**做成公网网盘生态（不做分享链接、配额、转存、云盘会员）——那是另一个产品。

### 3.5 扩展性：能力分层
- **L0 命令** → **L1 磁盘命令插件**（受限 boa 运行时 + 白名单 API）→ **L2 UI 插件** → **L3 市场**。
- 扩展点最小稳定面是「命令注册表 + 启停持久化」；UI/市场在沙盒与信任体系成熟后再上，避免过早铺开复杂度。

### 3.6 克制与反 AI 味
- 标签/图标/配色遵循「设计系统」的语义 token；**别用 emoji 当功能图标**（用 1.6–1.8px 描边 monoline SVG）。
- 遵循「**~80% 成熟模式 + ~20% 独特选择**」的灵魂法则：一个大胆视觉、有性格微文案、一个记忆点微交互、一个只有用过的人才会放的细节。

## 4. 设计取向与取舍

| 取向 | 取舍 |
|------|------|
| 页面优先 | 页面永远是页面（可随时当普通笔记编辑），结构化是叠加视角 |
| 类型小而完备 | 8 种类型够用，别乱加；select/multi 选项 = 枚举（着色/分列/计数） |
| 属性值按类型解释的 TEXT | 牺牲少量查询性能换「无 schema 迁移成本」；需要时才加真实类型列（慢即是快） |
| 视图前端渲染 | 本地优先、离线快、无服务器依赖；聚合在前端算 |
| 文件夹 = 页面+文件 | 聚焦核心网盘 UX（上传/预览/搜索/下载/去重/流式/统计），不做分享/配额等生态 |
| 收紧里程碑 | 价值/工程量排序；M9 模板、M10 多空间、M11 插件先行；市场/移动端延后 |

## 5. 边界（它不是什么）

- **不是关系型数据库**：不强 schema、无复杂外键/事务约束；页面属性灵活。
- **不是公网网盘**：无分享/配额/转存生态；聚焦私有、本地、去重、可加密。
- **不是协作平台**：共享/权限是另一个能力，早期不混入。

## 6. 可记忆的口诀

- **数据一次，处处呈现。**
- **数据库是透镜，不是 schema。**
- **文件夹是容器，不只是层级。**
- **你的文件，你的设备，你的私密。**
- **视图是配置，不是页面。**
